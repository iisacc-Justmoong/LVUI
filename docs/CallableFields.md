# 네이티브 callable 필드

공개 C++ 멤버가 메서드인지 호출 가능한 필드인지는 생성된 C++의 타입 검사로 결정한다.
`.lvui`에서 헤더를 반사하거나 필드 이름을 등록하지 않는다. 메서드 참조와 필드 선택은
그 연산을 실행하지 않으며, 이벤트나 명시적인 함수 호출에서만 실행한다.

```cpp
struct Model {
    ii::core::Observable<std::function<std::string(std::int64_t)>> format{
        [](std::int64_t value) { return std::to_string(value); }
    };
    ii::core::Observable<std::shared_ptr<MoveOnlyHandler>> run{
        std::make_shared<MoveOnlyHandler>()
    };
};
```

```lvui
import vm Model
let render: (Int) -> String = vm.format
@Static let original: (Int) -> String = render
let Actions(run: () -> Void = vm.run): View = PushButton(run)
Window { VStack {
    Label(text: render(4))
    Actions()
} }
```

## 선택과 소유권

- `Observable<T>` 등 관측 가능한 값 원본은 네이티브 `ReadContext`에 등록한다. 게시된
  복사 가능한 함수 값은 선택 시 소유 버전으로 복사하고, 같은 함수 입력의 소비자들은
  그 버전을 공유한다. 원본의 가변 저장 셀 주소를 실행 중인 함수로 사용하지 않는다.
- `shared_ptr<Handler>`는 핸들의 선택 버전을 보유하고 실제 함수 객체를 복사하지 않는다.
  이동·복사 불가능한 함수 객체도 공유 버전으로 사용할 수 있다. 빈 핸들은 선택 실패이다.
- 일반 C++ 함수 객체 필드는 좌측값·우측값과 constness를 유지하여 차용한다. 원본 객체의
  정체성과 가변 상태를 보존하며 임의의 복사 정책을 만들어 넣지 않는다. 명시적인
  `reference_wrapper`, 원시 객체 포인터와 좌측값 `unique_ptr` 역시 C++ 차용 수명을 따른다.
- 함수 포인터 필드는 선택한 포인터 값을 보존한다. 이후 슬롯에 다른 주소를 써도 기존
  선택의 대상이 바뀌지 않는다. null 함수 포인터는 선택 실패이다.
- 임시 부모·공유 부모·중간 객체의 소유권은 기존 [객체 메서드 참조](ObjectMethodReferences.md)의
  경계를 따른다. 임시 부모의 함수 필드도 부모보다 오래 살아 있는 참조가 되지 않는다.
  공개 C++ 접근자 선택기가 함수 객체를 값으로 계산하면 그 결과를 먼저 소유한다.
  이동·복사 불가능한 결과도 직접 생성하며 원래 우측값 호출 한정자를 유지한다.

일반 차용 필드의 외부 교체·파괴는 원래 C++ API의 책임이다. 실행 중 교체와 버전 고정이
필요한 함수는 `Observable<copyable callable>` 또는 `Observable<shared_ptr<Handler>>`로
게시한다. `@Static`은 선택된 버전·핸들 또는 차용 정체성을 고정하며 차용 대상 내부를 깊게
복사하는 기능은 아니다. 관측 가능한 함수 필드에는 별도의 합성 백엔드 리비전 의존을
추가하지 않는다. 일반 필드는 생성 스코프의 명시적 변경 발행 계약을 사용한다.
`get()`·`revision()`만 제공하고 `observe()`가 없는 원본도 백엔드의 명시적 변경 발행을
사용한다. 값을 읽을 수 있다는 사실을 변경 통지를 제공한다는 뜻으로 해석하지 않는다.

## 함수 값과 실패

타입 지정 `let`, `@Static let`, `var`, 구성 매개변수·기본값·전달과 이벤트에 같은 선택을
적용한다. 선언한 인자·반환 타입, 접근 권한·const 접근은 실제 생성 C++로 검사한다.
읽기 전용 호출은 파일 리비전을 발행하지 않는다.

빈 함수나 null 공유 핸들의 최초 선택은 활성화에 실패하며 부분 바인딩을 남기지 않는다.
이후 게시가 실패하면 이전 유효 버전을 보존하고 바인딩 오류로 기록한다. 복구 게시에는
같은 함수 입력·위젯으로 회복한다. 실행 중 교체·재진입·자기 제거는 접수한 버전을 반환까지
보존한다. 뷰 종료와 다른 실행 영역의 새 호출은 기존 접수 경계에서 거부한다.

## 검증 범위

`tests/native_callable_fields.cpp`는 버전 공유·고정, 빈 값 복구, 부분 활성화 정리, 이동 불가
함수의 공유 핸들, 실행 중 교체와 재진입, 차용 정체성·const 접근, 함수 포인터 선택,
자기 제거와 실행 영역, 임시 접근자 결과의 소유권과 비관측 원본의 발행 경계를 검사한다. 실제 생성 C++의 허용·거부 타입 계약은
`tests/native_callable_field_validation.py`로 별도 확인한다. 일반 타입 추론·중첩 함수 타입과 전체 LVRS·플랫폼
완료는 이 필드 연결만으로 입증하지 않는다.

수정 전 유효해야 하는 필드 연결 7개가 C++ 컴파일에서 거부되는 것을 확인했다. 임시
접근자 결과의 조기 파괴는 파괴된 함수를 호출하지 않고 수명 카운터로 재현했다.
`get()`·`revision()`만 있는 원본의 발행 누락도 네이티브와 실제 생성 위젯에서 각각
재현한 뒤 자체 관측 원본과 구분하여 수정했다. 일반 메서드 연결의 생성 형태 변경에 맞춰
기존 문자열 검사와 내부 함수 슬롯에 의존한 검사 대상을 갱신하고 전체 회귀를 다시 수행했다.

iiGUI 메모리 검사는 생성 C++와 WidgetState를 계측한다. 이 구성에서 차용한 일반
Native 아카이브의 구현은 LVUI의 별도 메모리 검사로 검증했다. 실제 LVRS 앱·OS 창·GPU·
다른 플랫폼의 실행과 제품의 UI 지연 개선률은 이 결과에 포함하지 않는다.
