# LVUI 언어와 iiGUI 프레임워크의 책임 경계

LVUI는 QML과 같은 역할의 선언형 UI 언어이다. 뷰와 자식 구성, 스타일 입력,
`import`, 바인딩과 임시 UI 상태의 의미를 정의하고 AOT로 C++ 연결 코드를
생성한다. 이는 QML 구문·엔진과의 호환이나 Qt 의존성을 요구하지 않는다.

iiGUI는 QtQuick과 같은 역할의 그래픽 인터페이스 프레임워크이다. 시각
컴포넌트와 그 상태·동작·배치·입력·접근성, 장면 및 GPU 렌더링을 소유한다.
LVUI가 생성한 코드는 이 프레임워크의 공개 API를 사용한다. 애플리케이션은
iiGUI를 LVUI 없이 C++로 사용할 수도 있다. 앱 데이터와 명령은 C++ 객체가
소유하며 iiSDKCore 쿼리로 접근한다. 뷰의 `@State`·`@Bindable`, 소유 수명,
변경 이벤트 기반의 선택 갱신은 기존 계약을 따른다.

LVUI 디자인 시스템의 토큰과 디자인 자산은 공통 시각 계약으로 유지하되
iiGUI가 특정 앱·LVUI 컴파일러·Figma에 종속되지 않도록 값 또는 명시적
자산 입력으로 전달한다. OS는 창·입력·텍스트·접근성 서비스를 제공하며
컴포넌트 렌더링을 브라우저나 OS 기본 컨트롤에 위임하지 않는다.

## 현재 소스의 차이

현재 `src/Controls`, `src/Editing`, `src/Collections`, `src/Overlays` 등에
컴포넌트 구현이 존재하고, `Compiler.cpp`도 일부 시각 동작을 생성한다. 이는
이전된 완료 상태가 아니라 변경할 대상이다. 진행 표시기의 상태·기하·접근성·
그리기·모션, 메뉴 구분선, 이미지·아바타·시트와 기본 버튼·모달·목록 행·AppCard·AppHeader의 네이티브 호스트는
iiGUI로 이전했으며,
언어 생성기는 디자인 자산·토큰과 반응형 값의 전달을 담당한다. 다른 컴포넌트는
여전히 이전해야 한다. `LVUI::Localization`은 앱이 저장·직렬화 콜백을 주입하는
계약으로 분리했다. `LVUI::ImageIO`와 `LVUI::Color`도 Core 외 SDK를 자동으로
찾거나 링크하지 않는 계약이다. 구체적인 이미지·색상 서비스는 앱 예제에서
필요한 SDK들을 명시적으로 조합한다. 아직 LVUI의 다른 시각 컴포넌트가 iiGUI
헤더를 직접 사용하므로 전체 SDK 간 소스 의존성 제거는 완료되지 않았다.

이전 과정에서는 `.lvui` 사용법, 기존 사용자 데이터와 병행 작업을 보존한다.
iiGUI를 LVUI에 의존시키지 않고, iiSDKCore를 제외한 SDK 모듈 간 직접 의존성을
추가하지 않는다. 기존 코드가 남은 동안 이를 이미 이전된 것으로 보고하지 않는다.

이전은 컴포넌트별로 상태·입력·레이아웃·모션·그리기와 디자인 값을 먼저
분류한 뒤, 범용 C++ 구현을 iiGUI에 두고 LVUI 생성기가 해당 공개 인터페이스를
호출하도록 진행한다. 각 컴포넌트에서 기존 선언·접근성·수명·변경 알림과
디자인 결과를 검사하고, 소비자 이식이 확인된 뒤 중복 구현을 제거한다.
디자인 토큰과 자산은 입력으로 분리하며 앱의 도메인 객체를 iiGUI로 옮기지 않는다.

2026-11-07 macOS arm64에서 진행 표시기와 구분선의 생성·헤드리스 호스트,
메뉴 섹션·중첩 메뉴 및 복합 목록 연동 검사 17건이 통과했다. 동적·모션 선언도 C++로
컴파일했다. 이 결과는 실제 창이나 GPU, 다른 운영체제의 실행을 확인한 것은 아니다.

2026-11-07 이미지와 아바타의 모델·배치·접근성·그리기는 iiGUI로 이전했다.
디자인 자산과 토큰은 생성기가 전달한다. 시트 닫기 버튼도 생성된 앱이 기존
토큰과 모션을 전달해 iiGUI 버튼으로 조합한다. 파일·네트워크·코덱 로더 및 색상 계산은
앱의 교체 가능한 조합 예제로 분리했으며, 실제 창이나 GPU는 실행하지 않았다.

앱 빌드 함수는 iiGUI를 자동 탐색하지 않으며 애플리케이션이 호스트 타깃을
명시적으로 제공한다. 생성되는 C++과 아직 이전하지 않은 시각 구현은 여전히 iiGUI
공개 API를 직접 사용한다. 팝업 열림 바인딩, 취소 이벤트 판정과 일시적 톤
포트와 메뉴·탭의 섹션 조합 계약은 구체적인 그래픽 SDK 없이 iiSDKCore와
주입된 타입 및 계약만 사용한다. 텍스트 경계 어댑터도 주입된 인덱스 타입을
사용하므로 그래픽 SDK 헤더를 직접 포함하지 않는다. 스택 배치 변환은 앱이
전달한 호스트 타입을 사용하고 정렬의 숫자 순서가 아닌 이름을 기준으로 연결한다.

정적·반응형 스택의 배경과 테두리 도형은 iiGUI가 계산하고 캐시한다. LVUI는
디자인 값과 변경 바인딩을 전달하며 해당 바인딩 헤더는 iiGUI를 직접 포함하지 않는다.

기본 버튼과 드롭다운의 상태·기하·입력·그리기 호스트는 iiGUI로 이전했고
중복 계산 모델을 제거했다. 기본 버튼과 드롭다운 바인딩은 Core 외 SDK를 참조하지 않는다.
경고 버튼도 모델 계산과 호스트를 iiGUI로 옮겼다. LVUI 정책 어댑터는 기존
디자인 토큰과 이벤트를 전달한다. `LVUI/AlertButton.h`의 중복 모델은 제거했고
버튼 바인딩은 Core 외 SDK를 참조하지 않는다.
경고창의 액션·배치·아이콘 및 텍스트 표현과 위젯 트리·입력 호스트도 iiGUI에 있다.
LVUI는 토큰과 자산·콜백을 제공하며 바인딩은 Core 외 SDK를 참조하지 않는다.
토글과 스테퍼의 상태·기하·입력과 그리기는 iiGUI가 소유한다. 두 LVUI
바인딩은 iiGUI를 직접 참조하지 않는다. 다른 컴포넌트의 이전은 남아 있다.
도구 버튼의 상태·배치·그리기·호스트도 iiGUI로 옮겼으며, 목록과 도구 모음이
이를 재사용한다. 구형 `LVUI/ToolbarButton.h` 계산 모델은 제거했으며 계층 도구
모음의 선택·기하·입력·그리기 및 수명도 iiGUI가 소유한다. 두 바인딩은 Core 외
SDK를 참조하지 않는다.
목록 하단의 슬롯 배치·명령·아이콘과 호스트 수명도 iiGUI로 옮겼다. 구형
푸터 배치 모델은 제거했고 두 목록 패널의 검증도 iiGUI 모델을 사용한다. 푸터
바인딩은 Core 외 SDK를 참조하지 않는다.
목록 상단의 세 슬롯 도구 모음도 iiGUI가 배치·입력·그리기와 수명을 소유한다.
단독 선언은 생성된 앱이 iiGUI를 직접 조합한다. 구형 목록 도구 모음 기하 모델은
제거했고 목록 패널의 사전 검증도 iiGUI에서 수행한다. 목록 패널 바인딩은
Core 외 SDK를 직접 참조하지 않는다.
모달은 iiGUI가 상태·기하·액션·제목과 설명 표현·팝업 트리·본문 수명을 담당한다.
LVUI 바인딩은 Core 외 SDK를 직접 참조하지 않고 앱에서 디자인 입력과 iiGUI를
조합한다. 구형 `LVUI/Modal.h` 계산 모델은 제거했으며 다른 시각 구현은 남아 있다.
목록의 기본 행은 iiGUI가 상태·배치·접근성·그리기와 호스트 수명을 소유한다.
구형 행 계산 모델은 제거했고 복합 행도 같은 iiGUI 모델로 검증·배치한다. 목록
데이터 및 가상화와 복합 행의 내부 컨트롤은 아직 LVUI에 있다.
`AppCard`는 LVUI의 구형 위젯과 값 모델을 제거하고 생성된 앱 코드가 iiGUI를
직접 사용한다. LVUI에는 기존 뷰모델을 위한 모양 열거형만 유지한다.
`AppHeader`의 위젯과 모델도 LVUI에서 제거했으며, 생성된 앱이 iiGUI에 스타일과
윈도우 악센트를 전달한다. 다른 시각 컴포넌트의 직접 참조는 여전히 남아 있다.
`EventListener` 입력 표면과 크기 모델도 iiGUI가 소유하며 LVUI는 선언과 콜백·
크기 바인딩을 생성한다. 기존 LVUI 리스너 구현과 해당 설치 헤더는 제거했다.
독립 아이콘의 이미지 위젯과 갱신·퇴역은 iiGUI가 소유하며 LVUI 생성 코드가 앱에서
디자인 자산을 연결한다. 구형 LVUI 아이콘 위젯과 설치 헤더는 제거했고 SVG 자산
계약의 iiGUI 직접 참조도 제거했다. 디코딩과 공유 캐시는 앱이 선택한 iiGUI
디코더가 소유하며 다른 시각 어댑터의 직접 참조는 아직 남아 있다.

아이콘 자산의 소유 스레드 캐시도 디코더 주입 방식으로 분리했다. LVUI는 자산
조회와 버전 검사를 제공하고 iiGUI 디코더는 SVG 처리와 공유 래스터 캐시를 담당한다.
기존 버튼·목록 등 어댑터는 앱이 선택한 디코더를 명시하며, 이 어댑터 자체의
iiGUI 직접 참조와 다른 시각 구현은 아직 남아 있다. macOS arm64에서 설치 헤더의
Core 단독 컴파일과 해당 컴포넌트 36개 헤드리스 검사를 통과했다.

아바타의 디자인 마스크 자산과 화면 크기·배율 계산도 분리했다. LVUI 자산 헤더는
Core만 포함하며 생성된 앱이 iiGUI의 이미지 공급자와 SVG 디코더를 조합한다.

체크박스의 선택·기하·마스크 곡선·모션·그리기·입력과 수명은 iiGUI로 옮겼다.
LVUI에는 디자인 입력과 자산 선택 바인딩이 남으며 앱이 iiGUI와 디코더를 조합한다.

컴파일된 뷰를 호스트에 공급하는 팩터리와 원천은 iiGUI로 이전했다. LVUI의
해당 네이티브 호스트 헤더는 제거했고 앱이 두 모듈을 직접 조합한다.

렌더링용 sRGB 선형 변환은 iiGUI가 공통으로 제공하며 목록·카드·표와 입력 필드가
이를 사용한다. LVUI 텍스트 길이 경계는 그래픽 SDK 없이 UTF-8 문자를 보존한다.

일반·검색 입력의 지우기 표시는 iiGUI가 그리며 LVUI의 중복 그리기 헤더는 제거했다.

텍스트 문단의 줄바꿈·암호 마스킹·선택 기하와 커서 배치는 iiGUI로 이전했다.
LVUI의 해당 텍스트 배치 구현과 설치 헤더는 제거했다.

일반·검색 입력의 표면 재질 생성과 캐시는 iiGUI로 이전했다. LVUI는 디자인 값과
독립 바인딩만 소유한다. 복합 목록의 텍스트 배치 경로도 iiGUI 헤더를 직접 사용한다.

라디오 버튼의 선택·그룹·원형 기하·색상·점 전환과 그리기·입력 호스트는
iiGUI로 옮겼다. LVUI 바인딩은 Core 외 SDK를 직접 참조하지 않는다.

목록 행의 모델·그리기·호스트 바인딩은 iiGUI 직접 참조 없이 앱이 공급한 모델과
색 변환기·이미지·그리기 포트를 조합한다. 복합 목록은 아직 직접 참조를 가진다.

표의 사용자 View 부착·키별 수명과 가시 범위 갱신은 iiGUI가 소유한다. LVUI는
관찰 가능한 표 컨텍스트와 Core 단독 바인딩을 제공한다. 나머지 표 시각 구현은 남아 있다.

표 머리글의 열 모델·아이콘 준비·클리핑·텍스트·입력·접근성과 위젯 수명은
iiGUI가 소유한다. LVUI는 Core 외 SDK에 의존하지 않는 디자인 정책과 바인딩을
제공하며 전체 표 호스트는 아직 분리 중이다.

세그먼트 컨트롤의 모델·기하·표면·자식 스타일 연결과 수명은 iiGUI가 소유한다.
LVUI 세그먼트 값과 바인딩은 iiSDKCore 외 SDK를 직접 참조하지 않는다.

목록 툴바의 디자인 값과 모델·호스트 바인딩은 iiSDKCore 외 SDK를 직접 참조하지
않는다. 복합 목록이 iiGUI 모델·호스트·이미지 디코더를 명시적으로 조합한다.

도구 버튼과 목록 푸터는 독립 디자인 바인딩을 제공하며 앱이 iiGUI 모델·호스트와
이미지 디코더를 조합한다. 두 패널은 생성된 앱이 조합하며 복합 행은 아직 이를 직접 조합한다.

공통 버튼 메서드 이벤트·등록은 위젯 타입을 주입받아 iiGUI 직접 참조 없이 동작한다.
기본 버튼 호스트도 앱이 주입하며 나머지 시각 어댑터의 직접 참조는 아직 남아 있다.
