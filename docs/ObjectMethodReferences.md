# 일반 객체의 네이티브 메서드 참조

`객체.method`는 수신 객체를 선택하여 보관하고 실제 호출은 이벤트나 명시적 함수 호출까지
연기한다. 가져온 백엔드의 직접 메서드 외에 중첩 객체·선택된 공유 객체·구성 입력·별칭·
괄호·인덱스·C++ 반환 객체를 사용할 수 있다. `.lvui`는 C++23으로 생성하며 문자열 검색,
소스 인터프리터와 별도 VM을 사용하지 않는다.

```lvui
import class Domain.Item
import vm Model
let current = vm.selected
let render: () -> String = vm.selected.describe
let Action(item: Item, run: () -> Void = item.act): View = PushButton(run)
Window { VStack {
    Label(text: render())
    PushButton(current.act)
    PushButton((vm.selected).act)
    PushButton(vm.items[0].act)
    PushButton(vm.current().act)
    Action(item: vm.selected)
} }
```

## 평가와 호출

참조를 계산할 때 수신 객체만 선택하며 해당 메서드를 실행하지 않는다. `vm.current().act`
에서는 `current()`로 수신자를 얻지만 `act()`는 호출하지 않는다. 일반 반응형 참조는
선택의 의존값이 바뀌면 현재 버전을 교체한다. 마운트·레이아웃·의존값 갱신 자체를
메서드 호출로 바꾸지 않는다.

명시적인 함수 선언·입력은 기존 `(인자 타입) -> 결과 타입` 계약을 따른다. `let` 함수 값은
의존값에 따라 갱신하고, `@Static let`은 해당 활성화의 처음 선택을 고정한다. `var` 함수
값은 초기 버전을 선택한 뒤 기존 C++ setter로 교체한다. 참조가 선택하는 객체를 깊은
복사로 고정하는 계약은 아니다.

일반 C++ callable 팩터리인 `vm.selected.makeHandler()`도 기존 반환 콜백 경로를 사용한다.
팩터리에서 반환한 callable의 소유권은 해당 C++ API의 계약을 따른다. 참조를 만들거나
반환 callable을 받는 것만으로 최종 동작을 호출하지 않는다.

## 객체 정체성과 수명

`Methods::reference`는 원래 수신 객체의 주소와 const·lvalue·rvalue 범주를 보존한다.
일반 lvalue와 표준 참조는 복제하지 않는다. 공유 핸들은 선택 당시의 소유자를 보존하고,
중첩 하위 객체를 차용하면 그 객체에 도달하는 동안 읽은 공유 부모도 해당 함수 버전에서
보존한다. 실행 중 선택이 교체되어도 이전 수신자와 부모는 호출이 반환할 때까지 유효하다.

C++ prvalue는 함수 버전이 소유하며 직접 생성하므로 이동·복사 불가능한 임시 객체도
사용할 수 있다. 순수 임시 객체의 `&&` 한정 메서드와 lvalue 객체의 `&` 한정 메서드를
C++ 규칙에 따라 선택한다. 포인터·공유 핸들·표준 참조를 역참조한 객체는 lvalue이다.

`vm.makeParent().child.act`와 `vm.makeParent().selected().act`는 임시 부모를 먼저 소유한
뒤 하위 필드·getter 결과를 선택한다. 선택 결과가 참조여도 부모는 해당 함수 버전이
보유한다. 값 컨테이너의 `vm.items[index].act`는 요소를 복사하지 않고 C++ 인덱스 결과의
const·참조 범주를 유지하며 범위를 검사한다. 임시 컨테이너도 먼저 소유하고 요소를
선택한다. 조건식은 선택된 분기의 객체 정체성을 유지한다.

생성 C++는 `receiver_member`·`receiver_index`·`receiver_value`를 조합한다. C++에서 직접
수신자 팩터리를 작성할 때에도 임시 부모의 하위 참조를 반환한다면 같은 선택 헬퍼를
사용해야 한다. 이미 파괴된 객체의 참조를 반환하는 임의 C++ API를 사후에 복구하지는 않는다.

raw 포인터·표준 참조와 lvalue 독점 핸들의 대상은 외부 소유자를 차용한다. 해당 소유자는
참조를 사용하는 활성화와 호출보다 오래 살아야 한다. 임의 핸들의 복제·언로드·소유권
프로토콜을 자동으로 추정하지 않는다.
비소유 C++ 뷰 값도 원래 API가 정한 저장소 수명을 따른다. 뷰 객체를 소유하는 것이
그 뷰가 가리키는 문자열·버퍼까지 소유하거나 고정한다는 뜻은 아니다.

호출 접수는 기존 콜백·함수 값의 활성화 경계를 따른다. 소유 뷰가 닫히거나 다른 실행
스레드에서 호출하면 퇴역한 수신자에 접근하지 않는다. 실행 중 자기 뷰를 제거하면
접수한 호출의 수신자와 버전을 반환까지 보존하고 그 뒤 해제한다.

## 읽기 수집과 실패

수신자를 선택하는 명시적 읽기와 C++ getter 내부의 Core Observable 읽기를 별도
`ReadContext`로 수집한다. 기존 바인딩에 의존값을 전달하고 선택한 버전에는 필요한
소유자만 보관한다. 별도 폴링·객체 등록소·작업자 런타임을 추가하지 않는다.

최초 널 수신자나 잘못된 선택은 활성화를 실패시킨다. 이후 실패는 마지막 정상 callable을
보존하며 실패한 선택을 복구할 수 있는 원본의 구독도 유지한다. 정상 선택이 돌아오면
기존 위젯·입력·포커스를 유지하며 복구한다. 파일 revision이나 파일 저장은 참조 계산에서
발행하지 않는다. 기존 import 백엔드의 이벤트 후 합성 publication은 일반 public 필드의
표시 갱신을 위해 유지하며 문서 revision과 구분한다. 구성 입력이나 외부 차용 객체의 일반
필드 변경은 기존 명시적 publication·Observable 계약을 따른다.

메서드 존재·접근성·const·인자·결과와 오버로드는 생성 C++가 검사한다. 잘못된 LVUI
수신자와 예약된 이름은 소스 위치를 포함하여 거부한다. [callable 필드](CallableFields.md)의
관측 값·공유 핸들·차용 계약도 같은 선택 경계로 연결한다. 나머지 일반 타입·불투명 핸들의
소유권 프로토콜, 깊은 Static과 가변 View는 별도의 전체 완료 조건이다.

## 엄격한 소비자 경고 설정

AOT가 만드는 읽기 문맥 인자는 `[[maybe_unused]]`로 표시한다. 수신자가 스코프의
일반 C++ 객체이면 문맥을 읽지 않을 수 있지만, 반응형 수신자는 같은 인자를 사용한다.
의존 추적·호출·수명 동작은 유지하며 소비자의 `-Werror=unused-parameter`에서도
직접 백엔드 메서드와 중첩 객체 메서드를 컴파일한다. 소비자 경고 설정을 완화하지 않는다.

메서드 타입을 판별하는 내부 포인터 인자도 값 호출 대신 타입 증명에만 쓰는 경우를
명시한다. 인자의 구성·전달이나 원래 메서드의 호출 시점은 바꾸지 않는다.

같은 어댑터가 순수 조회 콜백과 상태 변경 콜백에 공통으로 쓰이므로 스코프·버튼 이벤트
인자도 선택 경로에서 사용하지 않을 수 있음을 표시한다. 필요할 때의 참조·이벤트 전달은 유지한다.

자동으로 대화상자를 여는 페이지의 embedded build 거부 경로에서는 생성자 팩토리 인자도
명시적으로 소비한다. 이 경로는 오류를 반환하는 기존 정책을 유지하며 엄격한 예제 빌드로 검사한다.
