# 네이티브 값 바인딩

`LVUI::Native`는 Qt·iiGUI·LVRS에 의존하지 않는 C++23 모듈이다.
실행 중 LVUI 소스나 AST를 읽지 않는다. AOT가 생성한 C++ getter가
`ReadContext::read()`로 읽은 Core Observable만 추적한다.

## 갱신 계약

- 활성화마다 `Bindings` 하나를 소유 UI 스레드에서 생성·사용·파괴한다.
- 원본별 관찰 연결 하나를 공유한다. 조건식의 실제 실행 분기에 따라 의존성을 교체한다.
- `derive()`의 읽기 전용 파생값이 먼저 계산된 뒤 `bind()`의 표시 갱신을 실행한다.
- `begin_batch()`와 `end_batch()`를 중첩할 수 있다. 가장 바깥 배치 종료 시 갱신한다.
- 같은 결과는 setter를 다시 호출하지 않는다. String view는 소유 문자열로 복사한다.
- 계산·setter 실패는 `failures()`에 남기며 마지막 성공 값을 유지한다. 다른 바인딩은
  계속 갱신하고, 유효한 원본 변경이 오면 실패한 바인딩도 재시도한다.
- 의존 구독 교체에 실패하면 이전 연결을 보존한다. 무한 갱신은 유한한 처리 한도로 차단한다.
- 원본 C++ 객체는 연결보다 오래 살아야 한다. 이동·재배치는 활성 구독 중 수행하지 않는다.

`remove()`는 해당 연결을 해제한다. `close()`는 새 작업을 막고 모든 연결과 파생 출력을
닫는다. 한 번 닫힌 활성화는 다시 열지 않으며 새로운 활성화는 새 객체를 만든다.
다른 스레드에서 직접 호출하면 `wrong_executor`를 반환한다. 이 모듈이 UI 스레드로
작업을 자동 전송하거나 백엔드 작업을 취소하는 것은 아니다.

`NativeValues.h`는 생성된 C++의 유한 Number, 엄격한 Bool, 문자열 연결, 범위 검사,
단락 평가를 지원한다. getter는 일반 C++ 함수이며 소스 표현식 해석기가 아니다.
임의의 C++ 멤버 쓰기를 관찰 가능하게 바꾸지는 않는다. Core Observable은 자체 변경을
발행하며, 일반 공개 멤버는 생성된 스코프의 변경 발행 경로를 사용해야 한다.

## LVUI와 C++ 연결

```lvui
import vm Backend
var note: String = "Ready"
let heading: String = vm.ready ? vm.title + "!" : "Waiting"
@Static let initialCount: Int = vm.count
Window {
    VStack {
        Label(text: heading)
        Label(text: note)
        PushButton(vm.run, text: "Run", enabled: vm.ready)
    }
}
```

스칼라 `var`는 생성 스코프의 Core Observable이며 생성 뷰의 `set_note()` 같은 타입 setter로
갱신한다. `let` 파생값에는 쓰기 setter를 생성하지 않는다. 스코프별 C++ 객체의 공개 멤버는
별도 export 등록 없이 컴파일된 접근으로 사용한다. 타입·접근성은 C++ 컴파일에서도 검사한다.
`var local = vm.count + 3`처럼 외부 수식으로 초기화한 변수도 활성화 때 자체 값을 소유한다.
이후 원본의 변경이 해당 변수를 덮어쓰지 않으며, 변수에 대한 쓰기가 그 변수를 읽는 파생값을
갱신한다. 원본을 계속 따라야 하는 파생 선언에는 `let`을 사용한다.

공개 멤버가 Core Observable이면 해당 속성의 알림을 구독한다. 일반 멤버이면 생성 스코프의
`revision_0` 같은 객체 변경 값을 구독하며, 연결된 버튼·컨트롤 메서드 호출 후 이를 발행한다.
메서드가 예외를 던져도 이미 변경한 공개 상태를 발행하고 원래 예외는 유지한다. 외부 작업은
Core 큐로 소유 UI 스레드에 결과를 넘기고 그 스코프의 변경 경로를 발행해야 한다.

백엔드 구성 콜백은 스코프 소유권을 확보한 직후, 값·위젯 생성 전에 실행한다. 따라서 공유
목록·문서 모델도 한 인스턴스를 주입할 수 있다. 모달의 콘텐츠 활성화마다 별도 바인딩을
보관하고 닫을 때 해제하며, 부모 백엔드는 기존 인스턴스를 재사용한다. 창이 닫힌 뒤 생성 뷰의
변수 setter는 `closed`를 반환한다. 입력 해제와 백엔드 작업의 최종 퇴역은 별도 경계이다.

연결된 동기 메서드는 `native::callback()`으로 스코프와 활성화를 약하게 참조한다. 참조를
만들 때 실행하지 않으며, 닫힌 활성화·제거된 객체·소유 스레드가 아닌 호출은 접수하지 않는다.
이미 접수한 호출은 반환할 때까지 객체를 유지한다. 메서드 내부에서 자신의 뷰를 닫아도
실행 중인 객체를 먼저 파괴하지 않고, 외부에 보관한 콜백은 종료된 백엔드를 캐시에 남기지 않는다.

iiGUI의 `WidgetBuilder::on_retire()`는 상호작용 종료 알림과 소유 객체 해제 전에 활성화의
바인딩을 닫는다. 모달 구성 함수도 부모 활성화가 닫힌 뒤에는 새 콘텐츠를 생성하지 않는다.
이 경로는 비동기 작업을 자동으로 발견·취소하는 계약과 구분한다. C++ 백엔드가 생성한
대기 작업의 소유·취소·완료와 다른 실행 영역의 최종 자원 해제는 계속 별도로 연결해야 한다.

`LVUI::LVUI`의 기존 소비자는 `LVUI::Native`를 전이 의존성으로 받는다. 컴파일러가 필요 없는
네이티브 값 소비자는 `LVUI::Native`만 연결할 수 있다. Core는 이 모듈을 역으로 참조하지 않는다.

## 확인된 범위

`tests/native_bindings.cpp`는 선택적 갱신·조건 분기·파생값 우선순위·배치·2,048개
연결의 원본 공유·실패 복구·재진입·종료·스레드 경계를 검사한다. 이는 UI 독립 실행부의
검사이다. 전체 컴포넌트 AOT, 비동기 작업의 종료, GPU 표시, 플랫폼별 동작의 완료를
뜻하지 않는다. `tests/native_generated.cpp`는 생성된 C++ 상태 경로를 UI 호스트 없이 실행한다.
콜백 검사는 직접 종료·재진입·지연 호출 거부와 실행 중 수신 객체 보존도 실행한다.
전체 완료 기준은 [Completion.md](Completion.md)를 따른다.

[네이티브 배치](NativeLayout.md)는 같은 그래프에서 스택의 전체 배치 값을 계산하여
iiGUI의 원자적 setter에 전달한다. 순수 값 계약은 GUI 의존성 없이 사용하며 실제 위젯
어댑터는 사용하는 생성 C++에서만 iiGUI를 요구한다. 상수 배치는 컴파일할 때 확정한다.

[네이티브 Window 입력](NativeWindow.md)은 같은 그래프의 한 효과에서 루트 창 설정을
계산하고, 변경된 선언 필드만 약한 소유 접점에 전달한다. 내부 패널은 창 설정 권한을
상속하지 않으며 갱신은 파일 revision을 발행하지 않는다.

[읽기 전용 멤버](ReadonlyMembers.md)는 const Observable의 구독과 멤버 선택을 연결한다.
ReadContext는 계산 중 만난 공유 소유자를 평가·의존성 검사·적용이 끝날 때까지 보존하며,
재진입 선택 교체로 이전 멤버가 먼저 파괴되는 경로를 차단한다.

[C++ 구성 입력](ObjectInputs.md)은 호출자 식의 구조체나 객체 핸들을 같은 파생값
저장소에 보관한다. 소비자·기본값·중간 전달은 입력을 다시 호출하지 않고 이미 계산한
값을 읽는다. 타입과 const·공유 소유권은 생성 C++에서 보존하며 널 입력은 정상값을
덮어쓰기 전에 거부한다.

[객체 메서드 조회](MethodQueries.md)는 Core의 동기 읽기 범위를 기존 그래프에 연결한다.
Core Observable은 객체가 이동해도 유지되는 상태 식별자를 사용하여 명시적 읽기와 메서드
내부 읽기의 구독을 공유한다. 사용자 정의 원본의 get·observe 계약은 유지하며 내부 Core
상태를 계산 중 보존한다. 독립 바인딩의 재진입 prepare·구독·setter는 바깥 읽기 수집을
가리고, 각 메서드는 자신의 읽기 범위를 사용한다. 원본 수 한도는 수집 시에도 적용한다.
별도의 소유 핸들을 제공하지 않는 사용자 정의 원본은 해당 바인딩의 활성화보다 오래
유지해야 하며, 이 경우 읽기 기록의 소유자 필드는 비어 있다.
