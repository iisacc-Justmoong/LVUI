# 네이티브 Window 입력과 창 수명

Window의 일반 입력도 기본적으로 반응형이다. C++ Observable, 파생식, 재사용 View 입력과
`@Static` 스냅샷을 AOT 생성 코드에서 읽으며 실행 중 LVUI 소스를 해석하지 않는다.
Dreamscapes는 이 요구를 확인하는 읽기 전용 관측 대상이며 제품을 변환하지 않는다.

```text
import state WorkspaceState
Window(title: state.title, width: state.width, minimumWidth: state.minimumWidth,
       backgroundColor: state.background, fontFamily: state.fontFamily) {
    VStack {
        InputField(text: "Draft")
        Label(text: state.status)
    }
}
```

## 입력과 초기 창

| 입력 | 네이티브 계약 |
|---|---|
| title | String, 유효한 UTF-8, NUL 없음, 최대 64 KiB |
| width, height, minimumWidth, minimumHeight | Bool을 제외한 숫자, 유한한 1–32767 논리 단위 |
| backgroundColor | 기존 Color 값·iiColorManager 공유 값과 동일한 색상 계약 |
| fontFamily | 비어 있지 않은 UTF-8 String, NUL 없음, 최대 4096바이트 |
| accent | `blue`, `purple`, `rose`, `red`, `orange`, `yellow`, `green`, `gray`, `brown`, `cyan`, `teal`, `white` |

네이티브 C++ 속성의 최종 타입도 생성 팩터리를 컴파일할 때 검사한다. title·fontFamily에
숫자를 문자열로 바꾸어 넣지 않는다. `accent`는 정적 선언에서 `.purple` 또는
`"purple"`처럼 지정한다. C++ 백엔드의 반응형 입력은 `lvui::WindowAccent` 또는
같은 이름의 문자열을 받는다. 알 수 없는 이름, 범위를 벗어난 enum과 다른 숫자·enum
타입은 거부한다. C++의 공개 타입은 `<LVUI/WindowAccent.h>`에 있다.

```lvui
import vm EditorBackend
Window(accent: vm.accent) {
    PushButton(text: "Save", width: 120, onClick: vm.save)
}
```

창 소유 접점이 활성화되면 강조색이 기본 호스트 팔레트와 LVUI의 `AbstractButton`,
`PushButton`, `LabelButton`, `IconButton` 기본 팔레트에 반영된다. 재사용 View 안의
버튼도 같은 값을 사용한다. 버튼에서 명시한 `primaryColor`, `hoverColor`,
`pressedColor` 또는 `normalPressedColor`는 창 기본값보다 우선한다.
나머지 독립 위젯에 강조색을 일괄 상속하는 기능은 아직 지원하지 않는다.
`backgroundColor`는 별도 입력이며 강조색 변경으로 덮지 않는다. 카탈로그가 보유한
색상과 스타일 프로필 재정의를 사용하고, gray·white는 LVUI에 보관한 기본값을 사용한다.

생성 타입의 정적 `options()`와 `appearance()`는 Host를 만들기 위한 초기값이다. 아직
활성화하지 않은 백엔드를 이 메서드에서 생성하거나 호출하지 않는다. 반응형 입력은
스코프의 생성 정책·초기 설정과 값 초기화가 끝난 뒤 평가한다. 정적 초기 크기와 최소 크기는
항상 유효한 관계를 유지하며, 동적 실제 크기·최소 크기는 활성화 시 다시 검증한다.
입력이 전부 상수이면 기존 리터럴 생성과 LVUI 런타임 헤더 없는 출력을 유지한다.

## 유지된 창에 적용

동적 입력은 각각 별도의 네이티브 파생값으로 계산한다. 크기나 색상만 바뀔 때 제목을
계산하는 백엔드 메서드를 다시 실행하지 않는다. 동적 Window는 이 값들을 한 효과로
`ii::gui::WindowProperties`로 계산한다.
기존 `WidgetAppearance`를 복제한 뒤 명시한 동적 색상·폰트·강조색을 적용한다.
창 적용이 성공한 후에만 버튼의 강조색을 발행하므로 거절된 창 설정이 버튼 팔레트만
앞서 바꾸지 않는다. 이 값은 소스·AST·호스트 포인터를 보유하지 않는다.

iiGUI의 `WindowPropertiesTarget`은 루트 위젯 상태를 가리키는 약한 실행 영역 전용
접점이다. 갱신은 기존 위젯·입력 내용·포커스·백엔드를 교체하지 않는다. 기본 테마는
유지된 자식과 팝업의 테마에도 반영하며, 명시적인 위젯별 스타일은 해당 입력이 계속
소유한다. 폰트·기본 버튼 크기 변경은 자연 크기 캐시를 무효화한다.

모든 선언값을 매번 창에 덮어쓰지 않는다. 마지막 정상 선언과 비교하여 바뀐 필드만
Host에 전달한다. 사용자가 720×500 선언 창을 1200×900으로 직접 늘린 뒤 제목을 바꾸면
1200×900을 유지한다. 이후 width만 800으로 바꾸면 실제 높이 900을 유지한다.
접점의 snapshot은 마지막 정상 선언의 기록이며 실제 현재 크기는 Host의 snapshot으로 읽는다.
최소 크기만 커지면 필요한 축만 늘리며, 새로 명시한 크기가 최소 크기보다 작으면 전체
갱신을 거부한다. 관련 입력을 동시에 변경할 때는 기존 네이티브 batch 계약을 사용할 수 있다.

이 갱신은 파일 revision·저장·편집 이력을 발행하지 않는다. 관련이 없는 뷰 상태의 변경은
창의 의존식이나 백엔드 메서드를 다시 실행하지 않는다.

## 구성·실패·종료

후보를 만드는 동안 창 설정은 후보 상태에만 저장한다. 후보의 입력·자식 구성과 네이티브
표면 연결이 성공한 뒤 Host가 설정을 승인하며 그 이후 기존 화면을 교체한다. 최초 평가나
후보 구성이 실패하면 기존 창에 설정을 보내지 않고 후보의 구독·소유자를 종료한다.

갱신 전 전체 입력을 검증한다. getter 실패·유효하지 않은 값·네이티브 접점의 적용 실패는
마지막 정상 선언과 화면을 보존한다. 실패는 기존 `Bindings::failures()` 경로로 보고하며
다음 유효한 의존 변경에서 다시 적용한다. 기본 테마와 창 크기 중 한쪽만 먼저 적용한
부분 상태를 검증 실패로 남기지 않는다.

내부 콘텐츠와 팝업의 빌더는 창의 소유 접점을 물려받지 않는다. 이 빌더에서 `build()`한
Window는 시각 콘텐츠만 구성하며 상위 창의 제목·크기·테마를 변경하지 않는다. 내부 뷰의
Window 입력은 창 설정으로 평가하지 않는다. 창 소유 접점이 있는 루트 mount에서만
해당 효과를 연결한다.

종료된 접점은 닫힘 오류를, 다른 스레드의 접근은 실행 영역 오류를 반환한다. 접점은 Host나
백엔드의 수명을 늘리지 않는다. `@Static` 입력은 해당 활성화의 값으로 고정하고 새
활성화에서 다시 선택한다.

## 플랫폼과 검증 경계

macOS는 내용 최소 크기와 내용 크기, Windows는 최소 크기와 클라이언트 크기,
Linux/X11은 WM 최소 크기 힌트와 크기 요청을 갱신한다. X11의 실제 크기와 resize 통지는
ConfigureNotify가 소유한다. iPadOS의 기본 scene 크기는 OS가 소유하므로 동적 크기·
최소 크기 요청을 명시적으로 거부한다. 이 거부 전에 제목을 부분 변경하지 않는다.
보조 UIKit 창은 해당 크기 변경 경로를 사용한다.

검사 항목은 다음과 같다. 실행 통과 여부는 현재 빌드 로그와 검증 기록을 기준으로 한다.

- `LVUI.Window.*`: 동적 입력·강조색·상수 출력·소스 진단이다.
- `LVUI.Window.AccentGenerated`: 생성 C++의 창·버튼 색상, 중첩 View, 명시 스타일 우선,
  잘못된 입력과 창 적용 거부 후 복구를 창 없는 위젯 트리에서 검사한다.
- `LVUI.NativeWindowValidation`: 실제 생성 C++에서 유효 타입과 부적합 타입을 검사한다.
- `iiGUI.native_window.*`: 창 없는 실제 위젯 상태와 동일한 루트 구성 경로로 준비·승인,
  변경 필드, 편집 보존, 잘못된 값·네이티브 거부 후 복구, 실행 영역, 종료, 내부 뷰 차단,
  Static 스냅샷·루트 인자 전달을 검사한다.
- `iiGUI.layout_package`: 설치 후 경로를 바꾸어 Window 공개 헤더·API와 AOT 팩터리를
  컴파일·링크하며, 열리지 않은 Host와 종료된 접점의 호출 거부를 실행한다.

창 없는 값·위젯·패키지 검사를 실제 OS 창 조작·GPU 그리기·모든 LVUI 컴포넌트의
스타일 상속·모든 플랫폼의 실행 완료로 확대하지 않는다. 일반 값·인터페이스, 가변 View와
깊은 Static 수명, 상속·모션·앵커·입력·IME·접근성과 전체 원본 등가도 계속 완료 조건이다.

## 2026-10-26 검증 기록

당시 macOS arm64 작업 트리에서 다음 결과를 확인했다. 아래 LVRS 팩터리 항목은
현재 삭제된 레거시 경로의 과거 결과이며 LVUI 독립 경로의 기능 증거가 아니다.
일반 구성의 최종 전체 검사와
메모리 검사 구성은 독립 실행이며, 두 구성의 건수를 서로 다른 기능 수로 합산하지 않는다.

| 검사 | 확인 결과 |
|---|---|
| LVUI Release 전체 | 204/204 통과 |
| LVUI 관련 ASan·UBSan | 133/133 통과 |
| iiGUI 일반 창 없는 검사·패키지 | 최소 폭 보완 후 최종 141/141 통과 |
| iiGUI ASan·UBSan | 141/141 통과, 같은 최소 폭 보완 포함 |
| 새 Window 위젯 검사 | 각 구성 12건, 입력 보존·갱신·범위·거부·복구·종료 포함 |
| 외부 C++ Window 타입 | 각 구성 유효 3개 컴파일, 부적합 6개 거부 |
| LVUI 재배치 소비자 | Native 값·AOT 컴파일러·선택적 Runtime 3건 통과 |
| iiGUI 재배치 소비자 | 일반·메모리 검사 구성 각각 컴파일·링크·제한된 실행 통과 |
| 생성 위젯 헤더 | 두 구성의 39개 내용 일치 |
| LVRS | 기존 34개와 Window 5개, 39개 팩터리를 두 구성에서 컴파일, 실행 미실시 |
| Dreamscapes | QML 81개 해시 유지, 변환·재설치 없음 |

최초 소스 검사에서는 동적 Window 입력의 미지원 상태를 재현했다. 일반 전체 검사의
첫 실행에는 과거의 동적 Window Color 거부 기대값과 지역 스코프의 생성 주석 기대값이
남아 있었다. 새 Color 허용·실제 부적합 값 검사를 갱신하고 기존 지역 스코프 주석을 보존한
뒤 전체 204건을 다시 실행했다. 최소 폭만 변경하는 추가 경계는 실제 현재 크기에 적용하며,
보완 후 일반 141건을 다시 실행한 결과도 보존한다. 최초 로그를 최종 통과 로그로 덮지 않는다.

이는 생성 C++·기본 위젯 상태·설치 소비자의 증거이다. OS 창과 GPU 표면을 만들지
않았으며, macOS Host 어댑터의 컴파일·링크를 다른 플랫폼의 실제 실행으로 간주하지 않는다.
메모리 검사 iiGUI 실행에서 NativeBindings 구현은 일반 아카이브를 차용하며, 그 구현의
ASan·UBSan 실행은 별도의 LVUI 검사 133건에 포함한다. LVUI 언어·LVRS 전체의 완료를
뜻하지 않으며 [완료 감사](Completion.md)의 나머지 항목을 유지한다.
