# 활성화가 소유하는 단일 콜백 값

타입 지정 콜백 매개변수에 C++ 팩터리 결과를 전달하면 컴포넌트 활성화가 하나의
`CallbackValue<Signature>`를 소유한다. 같은 입력을 여러 컨트롤이나 자식 뷰로 전달해도
각 컨트롤이 팩터리를 다시 만들지 않는다. 소스 해석기·문자열 메서드 탐색·별도 스레드는 없다.

```lvui
import vm Model
let Leaf(run: () -> Void): View = PushButton(run)
let Pair(run: () -> Void, again: () -> Void = run): View = VStack {
    Leaf(run: run)
    Leaf(run: again)
}
Window { Pair(run: vm.makeHandler(vm.amount)) }
```

## 값과 함수 버전

위 입력은 활성화 시 한 번 바인딩하고 두 소비자가 같은 값과 현재 함수 객체를 사용한다.
함수가 가진 이동 전용 캡처와 가변 내부 상태도 현재 버전 안에서 공유한다. 인자를 단순히
다시 전달하거나 앞선 콜백을 기본값으로 지정하면 새 값을 생성하지 않는다. 별도의
컴포넌트 활성화나 별도로 작성한 팩터리 인자는 각각 독립된 값을 만든다.

C++ 값·우측값 반환은 소유하고, 좌측값 참조 반환은 수신 스코프에 연결하여 차용한다.
참조를 복사본으로 바꾸거나 `const`를 제거하지 않는다. 값 반환은 C++의 보장된 복사
생략을 사용하므로 이동·복사를 모두 금지한 함수 객체도 받을 수 있다. C++ 함수 참조도
차용할 수 있다. 여러 활성화가 같은 C++ 객체의 참조를 명시적으로 받으면 그 대상 객체의
상태는 공유한다. 외부 참조의 유효성과 컨테이너 변경에 따른 참조 무효화는 원래 C++
API의 수명 계약을 따른다.

입력은 기본적으로 반응형이다. 팩터리가 읽은 의존 리비전이 바뀌면 컴포넌트의 팩터리
바인딩을 한 번 평가하고 현재 함수 버전을 교체한다. 값의 정체성과 소비 위젯은 유지한다.
일반 C++ 메서드의 반환 식은 기존 계약대로 백엔드의 합성 리비전도 읽는다. 따라서 해당
리비전을 발행하는 네이티브 호출 이후 새 함수 버전이 계산될 수 있다. 함수 내부 상태가
의존값 변경을 넘어 영구 보존된다는 계약은 아니다.

실행 접수 시 현재 함수 버전을 보존한다. 그 함수가 의존값을 변경하여 새 버전이 생겨도
진행 중 호출의 캡처는 반환까지 유지한다. 이후 호출은 새 버전을 사용한다. 팩터리 평가가
실패하면 모든 소비자가 마지막 유효 버전을 계속 사용하고 네이티브 바인딩 오류를 보존한다.
초기 평가 실패는 후보 활성화를 실패시키며 이전 화면을 유지한다.

## 소유권과 종료

컴파일러는 팩터리 입력을 내부 스코프 필드와 초기화 코드로 생성한다. 사용자 소스에 내부
메서드나 보조 전역 객체를 추가하지 않는다. 일반·전달·조건·반복 뷰와 창 루트의 스코프를
사용하며, C++ 타입과 직접 멤버 접근은 빌드 시 검사한다.

소비자 하나를 제거해도 살아 있는 소유 컴포넌트의 콜백 값은 유지한다. 소유 활성화를
제거하면 팩터리 구독과 함수 자원을 퇴역시킨다. 외부에 저장한 값 핸들은 닫힌 수신자를
되살리거나 캡처를 계속 보유하지 않는다. 실행 중 자기 컴포넌트나 루트를 제거하는 경우는
진행 중 호출과 함수 버전이 돌아온 뒤 자원을 해제한다.

콜백은 생성한 UI 실행 영역에서만 접수한다. 다른 스레드에서는 약한 수신자·바인딩 참조를
잠그기 전에 거부한다. 이 사전 검사는 제거 중인 수신자의 마지막 참조가 잘못된 실행
영역에서 잠시 생기는 것도 방지한다. 작업 스레드의 결과는 [명시적 UI 전달](ActivationWork.md)을
사용한다. 콜백 값은 임의 백엔드 멤버의 동시 접근을 허용하는 잠금이 아니다.

## C++ API

`make_callback_value<Signature>(scope, bindings, factory, invoke)`는
`std::shared_ptr<CallbackValue<Signature>>`를 반환한다. 함수 버전의 저장·의존 추적은
기존 `Bindings`가 소유한다. 값은 함수를 복사하지 않고 동일한 버전을 참조한다.

```cpp
auto value = lvui::native::make_callback_value<void(std::int64_t)>(
    owner, bindings,
    [owner](lvui::native::ReadContext& context) {
        return [state = std::make_unique<int>(context.read(owner->amount))](std::int64_t n) {
            *state += int(n);
        };
    },
    [](const auto&, auto& handler, std::int64_t n) { handler(n); });
auto second = value;
(*value)(1);
(*second)(1);
```

이벤트 결과는 `Void`이며 실제 타입·payload 적응은 [콜백 입력 계약](CallableInputs.md)을
따른다. 네이티브 C++ 이벤트 객체는 차용 참조를 보존한다. 값 객체가 자기 호출 안에서
제거되더라도 이미 접수한 액션은 반환까지 유지한다.
생성된 팩터리 람다는 `decltype(auto)`로 원래 반환 종류를 보존한다. 직접 C++ API를
사용할 때에도 참조를 반환하려면 해당 팩터리의 C++ 반환 타입을 참조로 선언해야 한다.

## 검증과 전체 완료 조건

[네이티브 값 검사](../tests/native_callback_values.cpp)는 공유 정체성·상태·반응형 교체·
실패 복구·실행 중 교체와 자기 제거·잘못된 스레드 호출을 검사한다.
[위젯 검사](../../iiGUI/tests/native_shared_callable.cpp)는 실제 생성 C++에서 다중 소비자·
별도 활성화·소비자와 소유자의 다른 수명·초기 후보 실패·갱신 실패·자기 제거를 확인한다.
창 루트의 전달·조건부 콘텐츠와 이동 불가능한 차용 함수 객체도 검사한다.
원래의 구문·서명·설치·기존 구성 회귀 검사도 유지한다.

실제 LVRS 앱·테스트 실행은 전체 목표의 최종 일괄 검증으로 유지한다. 함수 값의 나머지
일반 타입·프로토콜, LVRS API·시각 상태·플랫폼 실행은
[전체 완료 감사](Completion.md)의 별도 항목이다.
반환값이 있는 함수 호출과 읽기 전용 선언은 [함수 값](FunctionValues.md)을 따른다.
