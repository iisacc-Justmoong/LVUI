# LVUI 코드 문서 모델

`CodeDocument.h`는 Qt, QML, LVRS와 화면 위젯에 의존하지 않는 코드 텍스트의
읽기·편집 경계다. `CodeDocumentSource`는 불변 `CodeDocumentView`를 제공하고
`CodeDocumentEditor`는 관찰한 리비전과 변경 범위를 받아 원자적으로 게시한다.
앱은 파일이나 협업 저장소에 맞는 다른 소스·편집기를 구현할 수 있다.

위치와 범위는 UTF-16 코드 단위이며 입력과 출력은 NUL 없는 UTF-8이다. 유니코드
스칼라 중간을 가르는 범위는 거절한다. `read()`는 호출자가 지정한 바이트 예산 안에서
부분 문자열을 읽고 `line_start()`는 0부터 시작하는 줄의 위치를 반환한다. LF를 줄
경계로 취급하므로 CRLF에서는 다음 줄이 LF 뒤에서 시작한다. 빈 문서도 첫 줄 하나를
가진다. 소스가 반환한 뷰는 이후 편집과 별도로 보관·읽을 수 있다.

선택적 `CodeMemoryDocument`는 텍스트를 불변 UTF-8 조각으로 저장한다. 편집할 때
변경 범위 주변의 조각만 다시 만들고 나머지는 이전 뷰와 공유한다. 줄 수와 UTF-16·
바이트 누적 위치를 조각 단위로 색인한다. 최신 리비전의 한 편집만 게시하며 동일한
문자열을 다시 적용하면 리비전을 증가시키지 않는다. 오래된 요청은 기존 내용을 보존한다.

기본 문서 한도는 64 MiB, 한 번의 입력은 4 MiB, 한 번의 읽기는 최대 4 MiB다.
문서와 편집 한도, 조각 크기는 `CodeDocumentLimits`로 줄이거나 정해진 범위 안에서
변경할 수 있다. 조각은 최대 65,536개이며 너무 많은 조각이 필요한 입력은 거절한다.
`range_byte_size()`는 지정 범위의 UTF-8 바이트 수를 반환한다. 메모리 구현은 조각
색인을 사용하고, 다른 소스의 기본 구현은 제한된 크기로 나누어 읽는다.
`CodeEditorController`는 선택과 커서를 문서와 별도의 뷰 상태로 관리하며, 주입한
편집기에 선택 영역이나 명시적인 범위의 대체를 요청한다. 스칼라 단위 삭제와 이동,
줄 처음·끝 이동, 문서 처음·끝 이동을 제공한다. 위아래 이동은 짧은 줄을 지날 때
UTF-16 논리 열을 기억하며, 글꼴에 따른 화면 좌표 이동은 아직 제공하지 않는다.
외부 변경으로 요청이 오래되면 덮어쓰지 않고 오류를 반환한다.
앱이 `refresh()`를 호출하면 위치를 새 문서 길이와 스칼라 경계에 맞춰 제한한다. 외부
삽입에 따른 의미상 커서 추적은 앱이나 향후 변경 매핑 계층의 책임이다. 컨트롤러는
생성한 스레드에서 사용하며 확정 중 재진입을 거절한다.

iiGUI의 `CodeViewport.h`는 불변 문서에서 보이는 줄과 열 구간만 가져온다. LVUI는
문서와 요청·결과 값 및 교체 가능한 바인딩을 제공한다. 한 요청은 최대
512줄, 줄당 65,536 UTF-16 단위와 총 4 MiB로 제한되며 각 경계는 유니코드 스칼라를
나누지 않도록 조정한다. LF와 CRLF 줄바꿈은 표시 텍스트에서 제외한다. 수평 위치는
픽셀이 아니라 논리 열이며 실제 글자 배치와 스크롤은 이후 화면 구현에서 맡는다.

`CodeComposition`은 최대 64 KiB의 한글 등 조합 문자열을 원본 스냅샷 위에 임시로
투영한다. 표시·읽기·줄 위치는 투영된 결과를 따르지만 실제 문서는 그대로 보존한다.
취소 시 투영을 버리고, 확정 시 원본 범위와 후보 문자열을 컨트롤러의 리비전 확인
교체 연산에 전달한다. 교체할 원본 범위가 커도 그 전체를 임시 문자열로 복사하지 않는다. 후보 선택
범위도 UTF-16 단위이며 스칼라 중간을 가를 수 없다. 운영체제의 입력 이벤트와 이
모델은 [독립 화면 위젯](NativeCodeEditor.md)에도 연결되어 있다.

`CodeEditorSession`은 문서 컨트롤러와 입력 조합의 수명 주기를 묶는다. 조합을 갱신할
때마다 같은 원본 범위에 새 후보를 투영하고, 확정이나 최종 텍스트 입력에서만 문서를
편집한다. 일반 선택 이동과 새로고침은 조합을 확정 또는 취소한 뒤 처리한다. 별도의
텍스트 서비스 선택은 조합과 독립적으로 표시 문서의 양방향 anchor·caret을 바꾸며,
조합 안팎의 유효한 UTF-16 스칼라 경계만 허용한다. 후보를 확정할 때 이 선택 방향과
위치를 보존한다. 잘못된 선택은 원본·후보·기존 선택을 변경하지 않으며 오래된 원본에
대한 확정은 후보와 선택을 유지한다. 일반 `insert`의 명시적 교체 범위는 현재 표시된
조합 범위 전체와 일치해야 한다.
텍스트 입력기의 `insert_input_text`와 `insert_input_text_selection`은 표시 문서의
임의 범위를 받아 조합 후보와 함께 하나의 원본 편집으로 확정한다. 두 변경 사이에서
보존해야 할 내용과 새 문자를 합친 임시 문자열은 64 KiB로 제한하며, 한도를 넘거나
범위·결과 선택이 유효하지 않으면 원본과 후보를 변경하지 않는다.
원본 변경 알림의 범위는 하나의 원본 편집에 포함된 조합과 요청 범위를 모두 덮는다.
`erase_input_surrounding`은 선택 양쪽의 삭제를 계산하고 조합 후보와 원본의 변경을
분리한다. 원본에 대한 삭제가 있으면 리비전을 검사한 하나의 편집으로 게시하고,
후보 내부의 삭제는 확정 전 투영에만 반영한다. 선택·조합 방향과 보관된 뷰를
보존하며 후보를 취소해도 확정된 주변 삭제는 유지된다. 양쪽 원본 삭제 사이에
보존할 텍스트는 65,536 UTF-8 바이트로 제한한다. 한 구간의 원본 삭제에는 이
중간 텍스트 복사가 필요하지 않다. 후보만 바뀌는 경우에도 원본 리비전을 검사하고,
충돌이나 잘못된 범위·부분 읽기는 기존 후보와 선택을 보존한다.
텍스트 서비스의 교체 후 방향성 선택은 문서 변경 전에 투영된 결과에서 검증하고
변경이 성공할 때 함께 적용한다. 실패 시 기존 문서와 선택을 보존한다.
`set_input_composition_region`은 기존 표시 문자를 바꾸지 않고 조합 영역을 지정하며
방향성 선택을 유지한다. 진행 중인 후보가 있으면 새 영역과 선택을 미리 검증한 후 기존
후보를 확정한다. 빈 영역은 기존 조합을 종료한다. 오래된 리비전, 부분 읽기, 한도를
넘는 후보나 준비 실패는 기존 후보와 선택을 보존한다. 기존에 보관한 투영 뷰도 이후
확정의 영향을 받지 않는다. 결과는 영역 갱신 여부와 확정된 문서 변경을 구분한다.
`set_input_composition`과 `insert_input_text`는 입력기가 지정한 교체 후 커서를
텍스트 교체와 함께 검증한다. 1은 삽입 끝, 0은 삽입 시작이며 그 밖의 값은 해당
끝점을 기준으로 계산한 뒤 문서 범위에 맞춘다. 서로게이트를 나누는 커서와 오래된
원본은 전체 요청을 거절한다. 빈 후보도 독립적인 조합 상태이므로 선택된 원문을
삭제할 수 있고, 종전의 빈 조합 취소와 구분한다.
외부 편집 때문에 확정이 실패하면 후보를 유지하므로 호출자는 취소 후 새로고침할 수
있다. 편집기 콜백이 같은 세션을 재진입하여 수정하지 못하도록 보호한다.

확장 자소 단위 이동, 문법 강조와 실행 취소 이력은 아직 연결되지 않았다. 입력
어댑터의 실제 플랫폼 검증과 더 풍부한 편집 동작은 남아 있다.

`LVUI.OwnedCodeDocument.Model`은 UTF-16 경계와 줄 위치, 여러 조각에 걸친 무작위
한국어·이모지 편집, 보관된 스냅샷, 한도, 오래된 요청과 동시 편집을 검사한다.
`LVUI.OwnedCodeDocument.Controller`는 선택, 이동, 편집 충돌, 재진입 및 스레드
경계, 논리 줄 이동과 삭제를 검사한다. `LVUI.OwnedCodeDocument.Viewport`는 긴 줄과
많은 줄의 부분 조회, CRLF, 이모지 경계와 요청 한도를 검사한다.
`LVUI.OwnedCodeDocument.Composition`은 확정 전 원본 보존, 큰 선택 범위, 무작위
부분 읽기와 줄 색인, 다국어 조합 경계를 검사한다.
`LVUI.OwnedCodeDocument.Session`은 조합 갱신·취소·확정, 기존 문자 영역 표시,
부분 읽기·충돌·보관된 뷰 보존, 읽기 전용 및 재진입 경계를 검사한다.
