# 기본 반응형 값

상태: 2026-10-20에 채택한 LVUI 언어 설계이다.
값은 기본적으로 상태 변경 추적과 바인딩을 사용한다.
`@Static`은 해당 수명 동안 고정되는 값을 명시적으로 설정한다.
현재 LVUI 0.1 파서는 이 모델을 구현하지 않는다.

<a id="default-value-semantics"></a>

## 기본 값 의미

뷰에서 사용하는 비정적 값은 변경 추적과 바인딩에 자동으로 참여한다.
레이블에서 `vm.value`를 읽으면 실시간 의존성이 생긴다.
원본이 바뀌면 레이블은 현재 값을 받으며, 한 번 복사하고 끝나는 입력이 아니다.

이는 일반 LVUI 변수를 포함한 언어의 공통 값 모델이며 가져온 ViewModel에만 한정되지 않는다.
기본 동작을 활성화하기 위한 관찰 어노테이션이나 바인딩 래퍼는 필요하지 않다.
구현별 상태 저장소, 선언 스코프, 의존성 추적은 추가 설계가 필요하다.

반응형 동작과 쓰기 권한은 별개이다.

- `var`는 선언한 타입에 따라 재대입을 허용하며 기본 반응형 모델에 참여한다.
- `let`은 상수 선언을 유지하며 재대입할 수 없다.
  원본을 추적하더라도 덮어쓰기나 const 멤버 변경 권한이 생기지 않는다.
- `@Static`은 이후 원본 변경을 따라가지 않고 해당 수명 동안 설정한 값을 고정한다.

이 규칙은 지역 변수를 새 ViewModel로 만들거나 가져온 객체의 소유자를 변경하지 않는다.
정확한 참조 의미와 파생 선언 의미는 타입·선언 설계에 남아 있다.

<a id="counter-with-increment-and-reset"></a>

## 증가·초기화 카운터

제공된 예제를 [examples/ReactiveCounter.lvui](examples/ReactiveCounter.lvui)에 저장하였다.

```text
import vm CounterViewModel

Column {
    Label(text: vm.value)

    PushButton(vm.increment) {
        text: "+"
    }

    PushButton(vm.reset) {
        text: "Reset"
    }
}
```

이 설계 예제에서는 C++ VM이 `0`으로 초기화한 읽기 가능한 정수 `value`와
인자·반환값이 없는 메서드 `increment()`, `reset()`을 제공한다고 가정한다.
증가는 값을 1 늘리고 초기화는 0으로 설정한다.
예제 버튼 인터페이스는 첫 번째 입력으로 콜백을 받아 허용된 클릭에 대해 호출한다.

예상 상호작용은 다음과 같다.

```text
초기 표시: 0
"+" 클릭      -> vm.increment() -> 값이 1이 됨 -> 레이블에 1 표시
"+" 클릭      -> vm.increment() -> 값이 2가 됨 -> 레이블에 2 표시
"Reset" 클릭  -> vm.reset()     -> 값이 0이 됨 -> 레이블에 0 표시
```

이 과정 내내 `vm.value`는 어노테이션 없이 현재 상태를 따른다.
메서드 참조는 구분한다. `vm.increment`와 `vm.reset`은 호출 가능한 값으로 전달되며
버튼이 호출할 때 실행된다. 반응형 의존성 갱신은 이 참조를 암묵적으로 호출하지 않는다.
[MethodReferences.md](MethodReferences.md)를 참조한다.

`Column { ... }`은 제공된 컴포넌트 표기를 기록한 것이다.
전체 컴포넌트 어휘와 빈 괄호 생략 규칙은 미정이다.
현재 0.1 파서로 실행할 수 있는 예제가 아닌 설계 예제이다.

<a id="static-values"></a>

## 정적 값

정적으로 명시한 스칼라는 초기화 시 설정한 원본 값을 보존할 수 있다.

```text
@Static let initialValue: Int = vm.value
```

해당 정적 수명 동안 `vm.value`가 이후 바뀌더라도 `initialValue`는 고정된다.
원래 VM 상태는 계속 자체 계약을 따른다.
정적 수명의 소유권과 참조·깊은 불변성 의미는
[DeclarationAnnotations.md](DeclarationAnnotations.md#open-questions)의 미정 사항으로 남아 있다.

`@Observable`은 관찰을 명시하는 표기로 계속 사용할 수 있다.
비정적 값이 변경을 따라가기 위한 필수 조건은 아니며, 기본 동작 이상의 추가 동작은 정하지 않았다.

<a id="aot-and-core-integration"></a>

## AOT와 Core 연동

[AOT 컴파일러](CompilationModel.md)는 비정적 뷰 값에 대한 네이티브 의존성 추적과
갱신 경로를 제공해야 한다. VM 어댑터는 [Core 읽기·쓰기·변경 쿼리](ViewModelQueries.md)를 사용해
상태를 읽고 변경을 알리며, 소유 UI 실행 영역에서 최신 값을 전달한다.

소스 접근성과 네이티브 변경 알림은 구현의 책임이다.
기존 Core 쿼리 포트만으로 임의의 C++ 쓰기를 감지하지 않는다.
생성된 접근 경로와 백엔드 연동은 언어의 기본 동작 구현에 필요한 변경 정보를 제공해야 한다.
애플리케이션에서 값마다 기능을 선택적으로 활성화해야 한다는 뜻은 아니다.

바인딩은 같은 원본 객체를 유지하며 해당 스코프의 종료 경계를 따른다.
의존성 갱신 과정에서 VM을 재생성하거나 매 프레임 모든 속성을 폴링하거나,
제거된 수신 객체를 갱신해서는 안 된다.

<a id="future-implementation-validation"></a>

## 향후 구현 검증

- 제공된 카운터는 관찰 어노테이션 없이 증가·초기화를 통해 `0 -> 1 -> 2 -> 0`을 표시한다.
- 뷰에서 사용하는 일반 LVUI 변수의 상태 변경이 기본적으로 반영된다.
- 정적 스칼라는 같은 정적 수명 동안 초기값을 유지한다.
- `let`과 읽기 전용 멤버의 재대입 제한을 유지한다.
- 의존성 재평가는 메서드 참조를 호출하지 않는다.
- 마운트 해제는 의존성을 분리하고 늦은 갱신을 거부한다.

이는 향후 컴파일러·런타임의 수용 기준이며, 테스트 통과 결과가 아니다.
