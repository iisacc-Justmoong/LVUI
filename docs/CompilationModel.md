# AOT 컴파일과 네이티브 마운트

현재 구조와 남은 전환 범위는 [LVUI 독립성](LVUIIndependence.md)에 정리한다.
LVUI는 자체 컴포넌트, 외형과 디자인 파라미터를 소유한다. `View`는 네이티브 C++
위젯으로 생성하며, iiSDKCore는 앱 런타임·진입점·최종 바이너리 부착을 담당한다.
iiGUI는 범용 C++ 위젯·레이아웃·입력·그리기와 OS 호스트 어댑터를 제공한다.
LVRS는 계승한 시각 언어의 레거시 출처이며 LVUI의 구현 경계가 아니다.

상태: 2026-10-20에 채택하고 2026-10-22에 네이티브 위젯·가속 경로를 명확히 한 LVUI 아키텍처이다.
LVUI는 AOT로 컴파일되는 네이티브 언어이다.
2026-10-22에 일부 컴포넌트의 C++23 AOT 생성과 iiGUI Cocoa 마운트를 구현했다.
현재 지원 입력·빌드 API와 남은 범위는 [LVUI 독립성](LVUIIndependence.md)에 구분한다.
기존 `FRAMEWORK LVRS` 생성 경로는 아직 제거되지 않은 레거시 호환 경로이다.
이 문서의 전체 언어·반응형·다른 OS·가속 생성 요구사항을 모두 구현한 것은 아니다.

<a id="selected-execution-model"></a>

## 채택한 실행 모델

LVUI는 컴파일 타임에 iiGUI의 자체 네이티브 C++ 위젯을 생성하는 코드로 빌드한다.
Cocoa/AppKit·Win32 같은 OS 계층은 창·단일 표면·입력·접근성 연결을 제공한다.
Metal, DirectX/Direct3D, Vulkan 가속 경로도 대상 플랫폼에 맞는 네이티브 코드로 컴파일·링크한다.
이렇게 생성한 네이티브 UI와 가속 코드의 산출물을 iiGUI에 전달하고,
iiSDK 런타임 안에서 네이티브 GUI 대상으로 마운트한다.

```text
.lvui 소스 + 참조하는 C++ 선언
    -> iiGUI C++ 위젯 생성 코드와 대상별 Metal/DirectX/Vulkan 가속 코드 연결
    -> AOT 컴파일과 대상 플랫폼 네이티브 링크
    -> 네이티브 애플리케이션 또는 UI 라이브러리
    -> 컴파일된 네이티브 UI·가속 산출물을 iiGUI에 전달하고 마운트
    -> iiGUI 호스팅 아래 네이티브 위젯·이벤트·레이아웃·GPU 표시 실행
```

LVUI 인터프리터, 소스 표현식 평가기, 바이트코드 가상 머신, JIT 실행 경로는 없다.
JVM과 .NET/CLR도 언어의 실행 모델에 포함되지 않는다.
배포된 UI는 `.lvui` 소스나 컴파일러 도구 체인 없이 실행할 수 있다.

iiSDK 런타임은 실행을 호스팅하고 작업을 스케줄링하며 소유권·수명 관리에 참여하는
네이티브 애플리케이션 기반이다. iiGUI는 네이티브 GUI·그리기 기능을 제공한다.
이러한 책임은 관리형 언어 가상 머신을 도입하지 않는다.

<a id="native-widgets-and-acceleration"></a>

## 자체 네이티브 위젯과 그래픽 가속

LVUI 컴포넌트는 iiGUI C++ 위젯을 생성·연결·갱신·파괴하는 코드로 변환한다.
위젯은 상태·레이아웃·히트 테스트·입력 처리·그리기 목록을 소유한다.
그리기 목록은 해당 그래픽 API로 컴파일된 iiGUI 렌더러가 표시한다.

| 대상 | 네이티브 위젯 코드의 대상 | 그래픽 가속 코드의 대상 |
|---|---|---|
| macOS | 공통 iiGUI 위젯과 Cocoa 창·입력·접근성 어댑터. 컴포넌트별 OS 컨트롤은 생성하지 않는다. | Metal과 Vulkan. |
| Windows | 같은 iiGUI 위젯을 Win32 창·입력·접근성 어댑터에 연결해야 한다. 위젯 마운트 어댑터는 아직 미완성이다. | Direct3D 11과 Vulkan. |
| Linux | 같은 iiGUI 위젯을 X11/Wayland 표면·입력에 연결해야 한다. 현재 X11 호스트가 위젯 마운트를 제공한다는 뜻은 아니다. | Vulkan. |

빌드 구성은 위젯 백엔드와 포함할 가속 백엔드를 정하고,
생성한 코드·필요한 셰이더 자산·리소스 연결 정보를 대상 플랫폼용 산출물에 포함한다.
iiGUI는 전달받은 코드를 네이티브 호스트·UI 실행 영역·입력 전달·표시·자원 수명에 연결한다.
버튼·레이블·레이아웃에 OS 컨트롤이나 OS 레이아웃을 사용하지 않는다.
OS 글꼴 조형·래스터화와 IME·가상 접근성 서비스는 플랫폼 경계에 격리한다.

컴파일 타임에 생성하는 것은 위젯과 가속 경로의 실행 코드이다.
실제 창·C++ 위젯·GPU 장치·스왑체인 등의 객체는 애플리케이션 실행 시 해당 코드가 생성한다.
실행 시 장치 기능을 확인하거나 빌드에 포함된 가속 백엔드 중 사용 가능한 경로를 선택할 수 있다.
이는 LVUI 소스의 재해석이나 실행 중 새로운 플랫폼 백엔드의 컴파일을 요구하지 않는다.

<a id="build-time-responsibilities"></a>

## 빌드 시 책임

AOT 도구 체인은 배포 전에 채택한 언어 규칙을 처리해야 한다.

- 선언·컴포넌트 구조·import·표현식을 파싱한다.
- 시각적 요소의 공통 타입 `View`와 `{}`로 전달하는 자식 `View` 인자를 검사한다.
- 이름·타입·C++ 공개 멤버·constness·호출 호환성을 확인한다.
- 일반적인 멤버 접근·호출 표현식·인자 타입 규칙으로 컴포넌트 입력과 callable 시그니처를 검사한다.
- `let`/`var` 선언과 지원하는 어노테이션 조합을 검증한다.
- 네이티브 스코프 활성화, 백엔드 생성·파괴, 동작 호출, 바인딩 접근, 관찰 지원 코드를 생성한다.
- 관찰 어노테이션 없이 비정적 값의 의존성 추적과 변경 전파를 제공한다.
- 컴포넌트를 iiGUI 자체 C++ 위젯 생성 코드로 변환하고 속성·이벤트·레이아웃 연결 코드를 생성한다.
- Metal·DirectX/Direct3D·Vulkan 중 빌드에 포함할 네이티브 가속 코드와 필요한 셰이더 자산을 준비한다.
- 대상 플랫폼에 필요한 C++ 백엔드·iiSDK/iiGUI 계약과 네이티브 UI 코드를 링크한다.

소스 검증은 런타임 백엔드 인스턴스를 생성하지 않는다.
가져온 객체는 계속 소유 스코프 활성화 시점에 생성한다.

컴파일러는 [메서드 참조와 명시적 호출의 구분](MethodReferences.md)을 유지한다.
컴포넌트 인터페이스가 콜백 매개변수 타입을 제공하고, 컴파일된 구현이 이벤트 계기를 제공한다.
언어 프런트엔드에는 `PushButton`이나 첫 번째 인자를 클릭 이벤트로 만드는 특별 규칙이 필요하지 않다.

C++23을 생성한 뒤 네이티브 컴파일러를 사용하거나,
다른 AOT 백엔드에서 네이티브 코드를 생성하는 방식을 구현 선택으로 고려할 수 있다.
컴파일러 백엔드·중간 언어·드라이버 이름·생성 파일 형식은 여기서 정하지 않는다.
요구되는 결과는 실행 전에 생성한 네이티브 코드이다.

컴파일된 데이터 테이블이나 디스크립터가 네이티브 콜백에 동반될 수 있다.
그 존재가 LVUI 소스·바이트코드의 런타임 평가기를 허용한다는 뜻은 아니다.

<a id="mounting-responsibilities"></a>

## 마운트의 책임

마운트는 iiSDK 런타임에서 컴파일된 네이티브 위젯 코드와 가속 경로를 iiGUI의 GUI·그리기 대상에 연결한다.
계약은 다음 책임을 다뤄야 한다. 이는 제안된 API 이름이 아닌 요구사항이다.

| 책임 | 필요한 동작 |
|---|---|
| 스코프 활성화 | 마운트된 뷰의 정체성을 설정하고 소유 import와 바인딩을 활성화한다. |
| 호스트 문맥 | 대상의 뷰포트·배율·소유 UI 실행 영역을 제공한다. |
| 네이티브 위젯 | 컴파일된 코드로 iiGUI 위젯을 생성하고 부모·자식 구조·속성·이벤트·수명에 연결한다. |
| 입력과 동작 | 지원 입력을 컴파일된 네이티브 콜백과 기존 백엔드·쿼리 계약으로 전달한다. |
| 상태 갱신 | 관찰된 변경을 의존 네이티브 뷰 상태에 적용하고 필요한 레이아웃·그리기 작업을 요청한다. |
| 그리기와 가속 | 위젯이 내보낸 패널·글자·이미지·오버레이를 컴파일된 Metal·DirectX·Vulkan 렌더러로 표시한다. |
| 마운트 해제 | 접수를 닫고 연결을 분리하며 활성 사용을 종료한 뒤 소유 객체·그리기 자원을 해제한다. |

마운트 시 `.lvui` 소스를 파싱하거나 컴포넌트 선언을 해석하거나 버튼 클릭마다 백엔드를 생성하지 않는다.
[스코프 기반 import](TypeImports.md)와 [종료](InvocationLifecycle.md) 계약은
컴파일된 UI에도 계속 적용된다.

<a id="values-and-interactions-after-compilation"></a>

## 컴파일 이후의 값과 상호작용

AOT 컴파일은 실행 동작을 미리 확정한다.
뷰포트 크기·카운터 값·사용자 입력·쿼리 결과는 실행 중에도 달라질 수 있다.
필요한 속성 평가·레이아웃·상태 갱신은 컴파일된 네이티브 코드가 수행한다.

[기본 반응형 값 모델](ReactiveState.md)과 `@Static` 값 안정성은 컴파일되는 언어 의미이다.
`@Observable`은 선택적인 명시적 표기이며 활성화 요구사항이 아니다.
구현에는 네이티브 저장소·콜백·[Core 쿼리 계약](ViewModelQueries.md)을 사용할 수 있다.
런타임 어노테이션 해석은 필요하지 않다. 정확한 `@Static` 수명 소유자는
독립적인 [선언 설계 미정 사항](DeclarationAnnotations.md#open-questions)으로 남아 있다.

VM과 C++ 서비스는 기존 책임을 유지한다.
컴파일된 뷰의 마운트는 새 관리형 힙을 생성하거나 인스턴스 소유권을 변경하지 않는다.

<a id="dependency-boundaries"></a>

## 의존성 경계

애플리케이션과 생성된 UI 코드는 네이티브 런타임·그리기 계약을 사용한다.
Core는 LVUI 소스 구문과 애플리케이션 ViewModel로부터 독립성을 유지한다.
마운트 계약이 Core에 LVUI 컴파일러 import를 요구하거나 순환 의존성을 도입해서는 안 된다.

현재 `LVUI/Compiler.h`와 `lvui-compile`이 C++ 생성 도구를, iiGUI의
`NativeWidgets.h`가 실행 중 마운트 인터페이스를 소유한다.
런타임 그리기 대상은 이미 컴파일된 UI를 실행하기 위해 컴파일러 프런트엔드를 필요로 하지 않는다.

<a id="current-implementation-boundary"></a>

## 현재 구현 범위

패키지는 [HTML 형태의 LVUI 0.1 계약](Language.md)을 위한 기존 C++23 파서와
[컴포넌트 언어 프런트엔드](ComponentLanguage.md)를 함께 제공한다.
`Parser.cpp`는 기존 문서 파싱을, `Language.cpp`는 예약어·토큰·`View` 트리 파싱을 구현한다.
`lvui-check`는 실제 컴포넌트 소스의 구문을 검사하는 네이티브 도구이다.
구문 검사와 별도로 `lvui-compile`·`compile_native`가 일부 컴포넌트의 C++23 코드를 생성한다.
`lvui_generate`가 CMake 빌드 의존성을 연결하고 네이티브 C++ 컴파일러가 실제 타입 검사·링크를 수행한다.

기존 iiGUI 캔버스 연동은 이미 파싱한 `lvui::Document`를 받는다.

- `LVUI/NativeDocument.h`는 문서의 레이아웃과 앱 측 호스트 연결을 소유한다.
- `iiGUI/Host.h`는 특정 상위 타입에 의존하지 않는 `set_view` 확장점과 `set_canvas`를 제공한다.
- 앱이 LVUI 어댑터와 iiGUI를 함께 사용하면 LVUI가 계산한 프레임을 호스트에 제출한다.

실제 AOT 경로는 이와 별개이다. 생성한 C++가 `Host::mount_widgets`에서
`WidgetBuilder`의 직접 생성 함수를 호출한다. iiGUI가 C++ 위젯의 배치·입력·그리기를 담당하며
AppKit 컨트롤과 Auto Layout을 사용하지 않는다. [지원 목록](LVUIIndependence.md)에 창·레이아웃·버튼·
입력·범위 컨트롤·아이콘·탭과 타입을 가진 콜백을 명시한다. 앱에는 LVUI 소스·AST·컴파일러 호출이 필요 없다.
반응형 필드 접근·나머지 예약 컴포넌트·다른 OS 입력 어댑터·추가 GPU 코드 생성은 미완성이다.

<a id="future-implementation-validation"></a>

## 향후 구현 검증

- `.lvui` 뷰를 iiGUI의 네이티브 C++ 위젯으로 빌드하고 OS 컨트롤 없이 생성·갱신·표시되는지 확인한다.
- Metal·DirectX/Direct3D·Vulkan의 대상별 가속 코드가 빌드 산출물에 포함되고 iiGUI를 통해 실행되는지 확인한다.
- 애플리케이션 실행 중 소스를 읽거나 언어 컴파일러·인터프리터·관리형 VM을 호출하지 않고 해당 UI를 실행·마운트한다.
- 같은 소유 스코프 인스턴스를 유지하면서 컴파일된 네이티브 코드로 백엔드 동작·관찰·쿼리 전달을 수행한다.
- iiGUI를 통해 마운트된 대상의 크기를 바꾸고 갱신·그리기를 수행한다.
- 마운트를 해제하고 접수 종료·오래된 결과 거부·소유 백엔드와 그리기 자원의 사용 종료를 검증한다.

위 목록은 전체 설계를 위한 수용 기준이다. macOS의 실제 위젯·스코프·직접 동작·크기 변경·종료와
설치 소비자 검증은 [NativeAOTVerification.md](NativeAOTVerification.md)에 별도로 기록한다.
일반 관찰·쿼리 바인딩과 GPU 코드 생성은 여전히 향후 기준이다.
