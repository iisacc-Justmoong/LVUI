# Society·Dreamscapes의 LVUI 이전 계획

작성일: 2026-11-07. 이 문서는 현재 작업 공간의 소스와 명세를 읽어 작성한 계획이다.
앱 실행, 성능 측정, 설치 또는 제품 변경 결과가 아니다. 앱을 이전하기 전에 LVUI와
iiGUI의 부족한 계약을 먼저 완성하고, 제품의 기능과 데이터 의미를 유지한다.

## 목표와 범위

- `.lvui`를 빌드 시 C++23으로 생성하고, LVUI가 소유하는 사용자 정의 위젯을
  iiGUI의 운영체제 창·입력·그리기 표면에 마운트한다. 소스 해석기나 가상머신을
  제품 UI 실행 경로에 추가하지 않는다.
- 두 제품의 동작과 현행 Figma의 LVUI 디자인을 기준으로 상태·레이아웃·키보드·
  접근성을 이전한다. 화면 변경은 각 제품의 Figma에서 먼저 검토한다. 제품별
  스타일 토큰이나 LVUI 위젯 오버라이드를 새로 도입하지 않는다.
- LVUI와 iiGUI를 포함한 SDK에서 iiSDKCore 런타임과 그 공개 의존 계약은 사용할 수
  있다. 현행 Runtime 패키지는 Contracts와 Observation을 공개 의존성으로 포함한다.
  그 밖의 SDK 기능 모듈끼리는 직접 의존하지 않으며, 앱 조합 계층에서 인터페이스와
  플랫폼 서비스를 연결한다. 실제 남아 있는 직접 의존성은 선행 작업으로 관리한다.
- Qt가 없는 **UI 경로**, Qt가 없는 **앱 전체**, 각 플랫폼의 **실제 실행**을
  별도 완료 조건으로 둔다. GUI 전환만으로 백엔드의 Qt 의존성이 제거되지는 않는다.

## 현재 소스에서 확인한 출발점

| 구분 | 관측 | 의미 |
|---|---|---|
| Society | `App/Society`의 QML 54개, 약 1.18만 행. 51개가 LVRS를 import한다. | Dashboard·저장소·사진·모델·계정·기기·캘린더·프로젝트·도구를 포함한다. |
| Dreamscapes | `src/App`의 QML 82개, 약 1.83만 행. 77개가 LVRS를 import한다. | 홈·생성·결과·편집기·타임라인·출판·설정을 포함한다. |
| 공통 | 두 앱 모두 Qt Quick, Qt Layouts, Controls, 동적 Loader·반복 모델·신호 연결, 파일 선택과 접근성 속성을 사용한다. | 구문과 위젯 이름만 치환해서는 입력·모델·수명·OS 통합이 보존되지 않는다. |
| LVUI | AOT 컴파일러, 뷰 세션, 반응형 바인딩, 버튼·입력·목록·계층·표·카드·팝업·가상 컬렉션의 독립 구현이 존재한다. | 각 앱에 필요한 속성·이벤트·플랫폼 및 성능 동등성은 별도 검사해야 한다. |

파일 수와 import 수는 위 두 앱 소스 디렉터리의 정적 텍스트 집계이다. 테스트와
다른 SDK가 공급하는 외부 QML은 제외되며, 인스턴스 수나 기능 완성도를 의미하지
않는다. 예를 들어 Society는 계정 화면과 에이전트 질문 화면을, Dreamscapes는
라이선스 화면과 에이전트 질문 화면을 SDK의 QML 리소스로도 불러온다.

Dreamscapes의 `Dreamscapes.Style`은 이름만으로 별도 토큰 체계라고 판정하지
않는다. 현재 [LvuiStyleTokens.cpp](../../../Product/Dreamscapes/src/App/ViewModels/LvuiStyleTokens.cpp)는
LVUI 토큰을 QML에 노출하는 연결부이며, 화면에는 이 연결부와 기존 `LV.Theme`이
함께 사용된다. 실제 Figma·LVUI 카탈로그·화면별 적용 값은 이전 전에 대조한다.

Dreamscapes에는 [순수 네이티브 뷰모델](../../../Product/Dreamscapes/cmake/NativeViewModels.cmake)과
별도의 결과 검토 세션이 이미 있다. 그러나 제품에서 사용 중인 뷰는 여전히 QML이고,
[결과 그리드 빌드](../../../Product/Dreamscapes/cmake/NativeReviewNavigation.cmake)는
`FRAMEWORK LVRS`와 `LVRS::LVRS`를 요구한다. 현재 [LVUI AOT CMake](../cmake/LVUIAot.cmake)는
`iiGUI` 이외의 프레임워크를 거부한다. 따라서 이 소스 조합의 네이티브 기반 구성은
현재 LVUI로 전환하기 전 정리가 필요하다. 이 문서 작성 시 빌드로 재현하지는 않았다.

현재 LVUI의 [CMake 구성](../CMakeLists.txt)은 Core를 직접 찾고, 선택 기능은
ColorManager·iiGUI·FileProvider·Network·VisualCodec 등을 직접 연결한다.
Core 런타임 및 그 공개 의존 계약의 사용은 허용된다. 기본 색상 값은 LVUI가
소유하므로 Native를 쓰기 위해 ColorManager를 찾지 않는다. Core를 제외한 기능
모듈 사이의 직접 의존성은 제품의 조합 계층으로 옮겨야 한다.

2026-11-07 기준 iiGUI Wayland에는 단일 접점 touch 전달과 장치 제거·다중 접점
취소가 추가되었다. 다중 접점 제스처와 tablet은 아직 없다. 클립보드 송신은 pipe
준비 신호와 전송 만료에 따라 대기한다. 현재 LVUI `QueryConnections`의 미완료 구독
퇴역은 1ms 재검사를 사용하므로 이벤트 기반 완료 통지와 독립적인 구독 포트로
교체해야 한다. 위 변경만으로 P0·P1 또는 제품 이전 진입 조건이 충족된 것은 아니다.

## LVUI와 iiGUI 선행 작업

### P0. 실제 계약과 빌드 경계 고정

1. 각 화면의 필수 상태, 명령, 서비스, 오류, 접근성, 키보드, 모바일 크기와
   파일·계정 권한을 표로 고정한다. 위젯별로 `구현`, `부분 구현`, `미구현`,
   `소스만`, `대상 OS 실행 확인`을 구분하고 기존 QML 검사와 대응시킨다.
2. Dreamscapes 결과 검토의 `FRAMEWORK LVRS`와 LVRS 전용 타입을 현재 LVUI
   모델·가상 컬렉션으로 대체할 수 있도록 SDK 컴포넌트와 테스트 계약을 먼저
   정리한다. 기존의 순수 뷰모델은 별도로 빌드 가능하게 유지한다.
3. LVUI 공개 헤더·CMake·생성 C++·선택 기능의 직접 SDK 의존성을 목록화하고,
   허용된 Core 런타임을 제외한 iiGUI·이미지·색상·저장소 연결을 앱이 주입하는
   포트로 분리한다. 큐 포화 시 완료 이벤트가 유실되지 않는 예약·재개·취소 장벽도 포함한다.
4. 기존 Society 세션 전체 검사의 300초 시간 초과는
   [반응형 감사](../../docs/ReactiveRuntimeAudit.md)에 기록된 미완료 사항이다.
   Core API 사용 자체와 별개로 이벤트 누락 복구·수명·취소·폴링 금지 위반은
   유지보수해야 한다. 과거 검사 실패를 현재 통과한 것으로 간주하지 않는다.
   현재 작업 공간의 iiSocietyHelper 0.12는 상태 API와 ABI가 바뀌었으므로 두 앱,
   컴파일러와 설치 소비자가 실제로 사용하는 SDK 버전·라이브러리를 함께 고정하고
   구버전 설치본과 새 헤더를 섞어 회귀를 판정하지 않는다.

### P1. 언어·상태·수명

- QML의 `required property`, alias, 바인딩, 이벤트 인자, `Connections`, 동적
  `Loader`·반복 항목, 조건부 View와 C++ 모델 경계를 제품 사례로 대조한다.
  현재 뷰 세션은 상태·타입 지정 쿼리를 지원하지만 임의 컨트롤 이벤트 인자를
  이름으로 읽는 일반 구문은 제한된다. 누락 표현은 컴파일 오류로 드러낸다.
- 객체·구독은 앱/창/뷰 세션에 명확히 소유시키고, 중복 활성화·늦은 응답·뷰
  파괴 중 콜백·비동기 취소와 `revision`/`gap` 뒤 재조회 경로를 검증한다.
  UI 실행기 밖의 작업은 비동기로 완료를 전달한다.
- 반복 모델은 안정된 ID와 범위별 삽입·삭제·변경을 사용하고, 일상적인 선택·진행
  변경이 전체 컬렉션을 다시 그리거나 저장소를 다시 훑지 않도록 한다. 프레임은
  재생·모션·활성 편집 중에만 호스트 프레임 시계로 구동한다.

### P2. 공통 위젯과 플랫폼 서비스

- 두 앱의 빈도와 실제 화면 계약을 기준으로 Label·버튼·아이콘·InputField·
  ComboBox·Slider·탭·메뉴·Sheet·모달·카드·목록·그리드·계층·표를 먼저
  완성한다. 컴포넌트 이름이 카탈로그에 있다는 사실은 해당 입력과 동작의 완성을
  뜻하지 않는다. [컴파일 범위](NativeCompilerCoverage.md)의 `TextEditor`, 모바일
  탭과 입력기 가드 등 미완료 항목을 제품 요구에 맞춰 해결한다.
- 긴 프롬프트와 편집에는 다중행·선택·복사·실행 취소·Unicode/IME·접근성을
  검증한다. 현재 InputField는 크기와 플랫폼별 입력기 제한이 있으므로 모든
  `TextEditor`를 동일한 필드 하나로 대체하지 않는다.
- 파일 열기/저장 대화상자, 드래그 앤 드롭, 클립보드, 카메라·사진 권한, 외부
  링크, QR, 공유와 앱 메뉴는 교체 가능한 OS 포트로 연결한다. 파일의 실제 생성과
  제공은 iiFileProvider가 담당한다. 비동기 취소와 권한 거부를 정상 상태로 다룬다.
- Wayland는 기본 Linux 호스트이다. 현재 호스트 문서는 다중 접점 제스처·태블릿·DnD·
  fractional scale·activation token 공백을 명시한다. 웹은 AOT WASM이지만
  현재 파일 핸들·IME·접근성·보조 창에 제한이 있으므로 제품 지원을 별도 결정한다.

### P3. 대량 미디어·캔버스·재생

- 가상 그리드와 계층의 정체성, 부분 갱신, 미리보기 캐시·취소·메모리 예산,
  비동기 디코딩과 색상 관리를 실제 Society/Dreamscapes 데이터 크기로 확인한다.
- iiSharedCanvas 문서·편집 로직과 렌더 표면을 분리하고, iiGUI/플랫폼 포트를
  앱 조합 계층에서 주입한다. 포인터·펜·터치·줌·회전·고DPI, 레이어·마스크,
  색상, GPU device loss 및 저장 중 종료를 다룬다.
- 비디오·오디오·카메라는 OS별 교체 가능한 미디어 포트로 취급한다. 파일이나
  모델을 UI에서 직접 복사해 관리하지 않는다. 하드웨어 가속은 실제 선택된 백엔드와
  대상 장치에서 확인하며, 프레임 타이밍과 비활성 시 자원 해제를 검사한다.

**제품 이전 진입 조건:** 해당 화면이 쓰는 LVUI 계약·호스트 능력·Qt 없는
컴파일/링크·자동 테스트·설치 소비자 검증이 먼저 통과하고, 남은 플랫폼 제약이
명시되어 있어야 한다. 아직 존재하지 않는 기능을 빈 위젯이나 폴링 대체로 숨기지 않는다.

## 제품별 이전 순서

1. **대표 경계 검증:** Society의 캘린더 소형 뷰와 Dreamscapes의 결과 그리드를
   별도 테스트 구성에서 작성한다. 동등한 입력·데이터로 현행 뷰모델과 결과를
   비교하고, 실제 제품 화면이라고 주장하지 않는다.
2. **Society 기본 경로:** 앱 창·온보딩·계정·설정과 Dashboard를 연결한다.
   이어 파일/모델/사진 그리드, 검색·필터·미리보기, 작업 이력·재시도, 캘린더와
   프로젝트를 순서대로 옮긴다. 자원 ID, 내용/메타데이터 판본, 위치·복제본,
   권한과 Job의 의미를 유지한다.
3. **Society 서비스 경로:** 로컬 데몬, 라이선스·인증, 기기 발견·연결·권한 철회,
   오프라인·재접속·이벤트 누락 복구를 연결한다. 오래된 캐시와 진행 중 작업을
   파괴하거나 다른 컨테이너로 연결하지 않는다.
4. **Dreamscapes 생성 경로:** 홈·프롬프트·모델/옵션·첨부와 작업 큐, 결과
   그리드·미디어 재생·비교·내보내기를 연결한다. 기존 Native 뷰모델과 결과
   세션을 우선 재사용하고 Qt 변환 래퍼만 제거 가능한 경계에서 제거한다.
5. **Dreamscapes 편집 경로:** 캔버스·도구·레이어·문서·타임라인·사진/카메라,
   출판과 에이전트/MCP 연결을 기능 단위로 이전한다. 저장 형식, 작업 세션,
   Undo/Redo와 미완료 생성 작업이 이전 전후에 동일해야 한다.
6. **제품 전환:** 두 구현을 비교하는 기간에는 별도 테스트/빌드 구성으로 분리하고
   실제 저장소에 두 쓰기 주체를 동시에 붙이지 않는다. 기능별 회귀와 데이터 복구
   조건이 충족된 뒤 제품 진입점을 전환한다. 최종 산출물에는 QML 엔진, LVRS,
   Qt GUI 및 과도기 어댑터를 남기지 않는다.

## 2026-11-07 비용 재산정: Core 런타임 허용

다음은 현재 소스의 정적 조사와 작업 분해에 따른 초기 계획값이다. 실제 이 프로젝트의
유사 작업 속도, 인건비, 인력 구성, 플랫폼별 수용 기준을 아직 반영하지 못했으므로
견적이나 신뢰수준이 확인된 통계 예측이 아니다. 낮음·계획·높음은 각각 작업 항목의
판단 범위를 더한 시나리오이며 P50·P90이나 확정 상한을 뜻하지 않는다. 항목 사이
위험이 함께 커질 수도 있다. 전제와 불확실성을 명시하고 실적에 따라 갱신하는 방식은
[미국 GAO 비용 추정 지침](https://www.gao.gov/assets/gao-20-195g.pdf)과
[NASA 소프트웨어 비용 추정 지침](https://swehb.nasa.gov/pages/viewpage.action?navigatingVersions=true&pageId=16777319)의 원칙을 참고했다.

### 산정 경계와 현재 크기

- 한 인일은 관련 개발·코드 검토·해당 항목의 단위 검사를 수행하는 사람 한 명의
  8시간 작업량이다. 휴가, 다른 프로젝트 배정과 대기 시간은 달력 일정에서 따로 다룬다.
- 기본 목표는 현재 기능과 디자인의 유지, LVUI의 C++23 AOT 출력, iiGUI 네이티브
  호스트, 그리고 macOS·Windows·Linux/Wayland의 데스크톱 빌드와 기능 검증이다.
  Figma 현행 디자인 대조는 포함하되 새 화면 디자인이나 제품 기능 확대는 포함하지 않는다.
- UI 이전 단계는 QML·Qt Quick·LVRS에 의존하는 UI 경로를 제거하는 범위이다.
  백엔드에 QtCore·QtNetwork 또는 다른 Qt 라이브러리가 남아 바이너리에 링크될 수 있다.
  앱과 필수 SDK 의존성 폐쇄에서 Qt를 완전히 제거하는 비용은 별도 행으로 더한다.
- iiSDKCore `Runtime`과 현재 그 공개 의존성인 `Contracts`·`Observation`은 허용한다.
  다른 SDK 간 직접 의존성은 여전히 금지하며 앱 조합 계층에서 연결한다. 기존 Core
  호출을 다른 구현으로 갈아엎는 비용은 포함하지 않는다. 구독 취소·수명, 이벤트
  누락 복구 및 불필요한 폴링 제거는 별도로 수행해야 한다.
- 2026-11-07 작업 트리에서 `App/Society`의 QML은 54개·11,767행이며, 51개가
  LVRS를 import한다. `src/App`의 Dreamscapes QML은 82개·18,237행이며 77개가
  LVRS를 import한다. 이 집계는 SDK가 공급하는 외부 QML을 제외한다.
- 같은 경로의 `.cpp`·`.h`·`.mm` 중 `tst_` 파일명을 제외한 정적 검색에서
  `Q_OBJECT`가 포함된 파일은 Society 26개, Dreamscapes 57개였다. `QQuick` 또는
  `QQml` 이름이 포함된 파일은 각각 6개와 19개였다. 주석과 다중 선언을 구분하지
  않는 텍스트 지표이므로 클래스 수, 화면 수 또는 선형적인 작업량으로 취급하지 않는다.
- 파일·그리드·대용량 목록, 생성·결과·캔버스·타임라인과 계정·공유 경로를 포함한다.
  현재 서비스·데이터 형식·권한·파일 제공자·Job 의미는 보존한다. 앱에서 실제로
  사용하는 외부 SDK QML 화면도 범위에 두되, SDK 전체를 일괄 재작성하지 않는다.

경로로 설계할 수 있다는 가정이다. 모바일에서 데스크톱과 동일한 시스템 권한이나
상주 동작을 약속하지 않는다. Web/WASM은 포함하지 않으며 브라우저 파일 권한·모델
실행·메모리·접근성의 별도 타당성 평가가 필요하다.

### Core 허용의 영향

기존 이전 계획에는 인일 기준 비용이 기재되지 않았으므로 과거 견적 대비 실제
절감액이나 확정된 절감률은 계산할 수 없다. 비교를 위해 Core 런타임까지 분리한다고
가정하면 iiGUI 호스트·실행기 경계 10~20인일, LVUI 바인딩·쿼리와 생성 코드 경계
15~30인일, 패키지·소비자 전환 5~10인일, 합계 약 **30~60인일**이 추가되는
초기 판단이다. 이 수치는 비교를 위해 새로 설정한 저신뢰 반사실적 추정이며 실측이
아니다. 위 표에서는 이 추가분을 계상하지 않는다. 기존 코드의 1ms 재검사, 이벤트
유실·취소·수명과 Core 이외 모듈 간 직접 결합은 여전히 표에 포함한다.

### 일정과 금액 산정 방법

숙련된 C++/플랫폼·LVUI·Society·Dreamscapes 담당 네 명이 각각 근무일의 75%를
이 작업에 투입하고 한 달을 20근무일로 보면, 계획값 402인일은 단순 나눗셈으로
약 6.7개월, 다섯 OS 계획값 482인일은 약 8.0개월이다. 플랫폼 선행 조건과 통합
직렬 구간을 감안한 초기 일정 가정은 각각 약 8~11개월, 10~14개월이다. 이는 팀
구성·숙련도·병렬성·결함과 대기 시간을 실측한 일정이 아니다.

실질 투입 인일당 비용을 `R`로 정하면 세 데스크톱의 전체 Qt 제거 개발비 계획값은
`402 × R`, 다섯 OS는 `482 × R`이다. `R`에는 급여·복리후생·간접비와 비가동률을
어떻게 반영했는지 명시해야 한다. 순전히 계산 예시로 `R = USD 500`이면 계획값은
각각 USD 201,000과 USD 241,000이다. 이는 실제 단가나 시장 가격이 아니다. 기기·CI·
외부 서비스·라이선스·앱스토어 비용·세금·지원 및 제품 지연에 따른 기회비용은 별도이다.
자동화 에이전트의 처리량과 검토 비용도 측정되지 않았으므로 사람 인일을 모델 호출
시간이나 비용으로 환산하지 않는다.

먼저 Society 캘린더 및 Dreamscapes 결과 그리드의 수직 경로에서 같은 입력·기능·
테스트로 작업량과 결함을 측정하고, 그 실적과 앱별 SDK 의존성 폐쇄를 반영해 위 표를
갱신한다. 대표 경로 비용은 이미 각 공통·제품 구간에 포함되어 별도 가산하지 않는다.
