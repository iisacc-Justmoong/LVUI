# 백엔드 소유권·사용과 종료

상태: 2026-10-20에 채택한 설계이다.
백엔드 수명은 소유 import 스코프와 남아 있는 사용을 따른다.
구체적인 스케줄링·취소 API는 추가 명세가 필요하다.

후속 [활성화 소유 작업 구현](ActivationWork.md)은 Core Runtime·TaskScope의 등록 작업에
대해 접수 차단·취소·실행 중 소유자 보존·UI 결과·비차단 퇴역을 제공한다. 아래 명세의
전체 네이티브 작업·플랫폼 계약과 실행 검증 범위를 구분한다.

<a id="owner-and-instance-lifetime"></a>

## 소유자와 인스턴스 수명

[import](TypeImports.md)를 활성화한 스코프가 생성된 인스턴스를 소유한다.
자식 뷰, 동작 연결, 속성 구독은 해당 인스턴스를 빌려 사용한다.

```text
소유 뷰 스코프 활성화
    백엔드 인스턴스 A 생성
    자식 차용자·속성 구독·동작 연결 부착
    첫 번째 클릭 -> A.save 실행 -> A 유지
    두 번째 클릭 -> A.save 실행 -> A 유지
소유 뷰 스코프 닫기
    새 사용 차단 및 연결 제거
    대기 중인 소유 작업 취소 및 활성 사용 종료
    A를 정확히 한 번 파괴
    A가 소유한 자원 반환
```

메서드가 정상 반환하면 해당 호출의 사용이 끝난다.
살아 있는 동작 연결을 통한 이후 클릭 등 다른 사용으로 인해 가져온 인스턴스가 계속 필요할 수 있다.
정상적인 메서드 완료는 스코프 소유 백엔드를 파괴하지 않는다.

<a id="bound-callback-values"></a>

## 연결된 콜백 값

[연결된 메서드 참조](MethodReferences.md)는 호출이나 새 백엔드 생성 없이 기존 수신 객체를 사용한다.
콜백 입력 계약에 따라 이 callable을 보관하는 컴포넌트는 미래 사용 경로를 만든다.
호출 계기는 컴포넌트가 정하며, 소유권 규칙은 내장 컴포넌트와 사용자 정의 컴포넌트에 동일하게 적용된다.

스코프를 닫을 때는 수신 객체를 파괴하기 전에 콜백 접수와 연결을 종료한다.
활성 호출과 캡처는 정상적으로 종료되어야 한다.
callable을 저장하더라도 수신 객체를 더 오래 사는 소유자에게 암묵적으로 이전하지 않는다.

<a id="compiled-ui-mounting-and-unmounting"></a>

## 컴파일된 UI의 마운트와 해제

[AOT로 컴파일된 UI](CompilationModel.md)는 마운트 시점과 컴파일된 컴포넌트 구조의 요구에 따라
소유 스코프를 활성화한다. iiSDK 런타임은 해당 UI를 iiGUI의 그리기 대상으로 마운트한다.
네이티브 활성화 코드가 스코프 소유 백엔드를 생성하며, 마운트 시 소스 문서를 해석하지 않는다.

마운트 해제는 마운트된 소유 스코프를 제거하고 종료 절차를 시작한다.
새 입력·쿼리 전달을 차단하고 연결·활성 사용을 종료한 다음,
안전해지면 소유 백엔드와 그리기 자원을 해제한다.
공유 런타임 서비스는 자체 소유자를 유지한다. 정확한 마운트·해제 API는 미정이다.

<a id="what-counts-as-use"></a>

## 사용으로 계산하는 항목

| 사용 | 해당 사용의 종료 시점 |
|---|---|
| 독립 값으로 복사하는 일회성 읽기 | 읽기와 복사가 완료될 때이다. |
| 동기 메서드 호출 | 호출이 반환되고 그로부터 발생한 차용 사용도 끝날 때이다. |
| 속성 구독 | 구독이 분리될 때이다. |
| 이벤트·메서드 연결 | 연결이 제거되고 활성 호출이 종료될 때이다. |
| 인스턴스를 사용하는 비동기 작업 | 작업이 완료·취소되고 모든 인스턴스 접근과 캡처가 종료될 때이다. |
| 사용 가능한 import 바인딩 또는 다른 미래 사용 경로 | 해당 바인딩·경로가 종료되어 더 이상 접근을 허용할 수 없을 때이다. |

자체 데이터를 소유한 복사 결과는 백엔드보다 오래 유지될 수 있다.
백엔드 저장소를 빌리는 결과는 계속 사용으로 계산하며 수명 계약이 필요하다.

뷰를 숨기는 것은 스코프 제거와 같지 않다.
숨겨진 뷰에도 구독, 동작 연결, 미래 소비자가 남아 있을 수 있다.

<a id="destruction-condition"></a>

## 파괴 조건

다음 조건을 만족하면 인스턴스를 즉시 파괴할 수 있다.

1. import 바인딩·연결·구독·다른 미래 경로 중 어느 것도 새 사용을 시작할 수 없다.
2. 동기 호출·비동기 작업·콜백 캡처·네이티브 작업 중 어느 것도
   인스턴스나 그 소유 자원을 더 이상 사용하지 않는다.

이 경로들의 종료는 소유자가 통제한다.
활성 차용은 파괴 책임을 자식에게 이전하거나 스코프를 암묵적으로 무한 연장하는 임의의 공유 소유권을 만들지 않는다.

조건을 만족하면 대응하는 파괴 계약을 정확히 한 번 실행하고 인스턴스 소유 자원을 반환한다.
사용하지 않는 살아 있는 백엔드를 암묵적인 캐시에 보관하지 않는다.

<a id="closing-sequence"></a>

## 종료 순서

1. 종료 상태로 들어가 새 호출과 전달을 거부한다.
2. 이벤트 연결·속성 구독·자식 차용자를 분리한다.
3. 백엔드가 소유한 대기 작업을 취소하고, 작업 계약이 지원하면 활성 작업의 취소도 요청한다.
4. 활성 사용·콜백·캡처가 종료되도록 한다.
5. 필요한 실행 영역에서 인스턴스를 파괴하고 소유 자원을 반환한다.

종료는 미래 접근 권한을 즉시 회수한다.
남아 있는 실제 사용이 끝나는 즉시 물리적 파괴가 뒤따른다.
대기 작업은 사용이 종료된 인스턴스에 대한 사용을 시작해서는 안 된다.

<a id="closing-from-inside-a-callback"></a>

## 콜백 내부에서 종료하기

메서드가 자신의 창을 닫거나 자신의 컴포넌트를 제거할 수 있다.
현재 호출 스택은 여전히 백엔드를 사용 중이다.

즉시 접수를 닫고 미래 사용을 분리한 뒤 해당 호출 스택이 해제되도록 한다.
최종 파괴는 활성 사용이 끝난 뒤에 수행한다.
자신의 메서드 실행 중에 수신 객체를 동기적으로 파괴하거나,
그 콜백 안에서 자기 자신이 끝나기를 기다려서는 안 된다.

런타임은 종료를 비동기로 완료해야 할 수 있다.
정확한 종료 핸들·실행기·스케줄링 프로토콜은 미정이다.
파괴 전에 모든 사용이 끝나야 한다.

<a id="asynchronous-work-and-longer-lived-jobs"></a>

## 비동기 작업과 더 오래 유지되는 작업

작업 핸들을 반환했다는 사실만으로 백엔드를 더 이상 사용하지 않는다고 판단할 수 없다.
백엔드 소유 비동기 작업은 접근과 캡처가 종료될 때까지 같은 종료 경계에 속한다.
협력적 취소는 요청이며, 활성 작업이 이미 중단되었다는 증거가 아니다.

뷰 제거 후에도 계속할 작업은 필요한 데이터와 소유권을 더 오래 사는 애플리케이션 작업이나 서비스에 명시적으로 이전해야 한다.
이전 이후 종료 중인 뷰 백엔드에 추적되지 않는 접근이 남아서는 안 된다.
뷰 소유 백엔드를 무기한 보관하는 것은 암묵적인 작업 수명 정책이 아니다.

UI 결과 전달은 수신 스코프의 종료 경계를 확인해야 한다.
늦은 결과가 제거된 뷰나 나중의 활성화에서 생성된 다른 인스턴스를 갱신해서는 안 된다.

<a id="queries-during-teardown"></a>

## 종료 중 쿼리

[VM 객체 쿼리](ViewModelQueries.md)도 같은 종료 경계를 따른다.
새 요청을 거부하고 대기 중인 소유 전달을 취소하며,
수신 객체를 파괴하기 전에 활성 처리기와 캡처를 종료한다.
큐에 들어간 완료 콜백은 취소로 억제될 수 있으므로 UI 전달을 보장한다고 취급해서는 안 된다.

빌린 포트 참조는 소유 VM이나 어댑터보다 오래 유지되어서는 안 된다.
살아 있는 수신 스코프를 통해 결과를 전달하고,
제거된 스코프나 다른 활성화를 대상으로 하는 늦은 결과는 거부한다.

<a id="validation-criteria-for-an-implementation"></a>

## 구현 검증 기준

- 같은 가져온 타입을 별도로 활성화하면 독립 인스턴스를 생성한다.
- 하나의 import를 여러 자식이 빌려도 추가 생성을 일으키지 않는다.
- 반복 클릭과 속성 갱신에서 같은 활성 인스턴스를 유지한다.
- 차용자 하나를 제거해도 다른 유효한 사용이 남아 있으면 인스턴스를 유지한다.
- 소유자를 제거하면 새 접근을 차단하고 모든 사용이 종료된 뒤 인스턴스를 정확히 한 번 파괴한다.
- 백엔드 콜백 내부 종료는 콜백 반환 전에 백엔드를 파괴하거나 자기 자신을 기다리는 교착 상태를 만들지 않는다.
- 대기 작업과 늦은 결과는 사용이 종료된 백엔드나 새 활성화에 접근할 수 없다.
- 종료 후 인스턴스 소유 자원 예약량은 기준 상태로 돌아온다.

이는 향후 런타임 수용 기준이며, 런타임 테스트 통과 보고가 아니다.

<a id="open-questions"></a>

## 미정 사항

- 정확한 실행 영역 귀속과 비동기 종료 조정.
- 작업별 취소·완료·실패 보고.
- 호출 직렬화, 메서드 중첩 실행, 재진입 정책.
- 메서드 인자, 오버로드, 반환값의 소유·차용 구분.
- 부분 활성화와 정리 실패의 오류 처리.
- 애플리케이션 소유 작업으로의 명시적 이전 API.
