# LVUI 0.1 언어와 렌더링 계약

이 문서는 현재 구현된 HTML 형태의 구문을 규정한다.
[문서 목차](README.md)는 2026-10-20에 채택한 컴포넌트 형태의 언어,
스코프 기반 백엔드 import, 소유권, 런타임 계약 설계 기록으로 연결된다.
해당 설계 기록은 이 문서에서 지원하는 문법을 변경하지 않는다.

채택한 언어는 [AOT 네이티브 컴파일과 iiSDK/iiGUI 마운트](CompilationModel.md)를 사용한다.
아래의 파서와 문서 레이아웃 경로는 기존 0.1 구현이며, 해당 컴파일러나
컴파일된 대상의 마운트 계약을 구현한 것은 아니다.

UTF-8 `.lvui` 소스에는 루트 요소가 정확히 하나 있어야 한다. 태그와 속성 이름은
대소문자를 구분한다. 요소는 명시적으로 닫거나 `/>`를 사용해야 한다.
루트 주변과 자식 사이에는 공백과 `<!-- comments -->`를 사용할 수 있다.
doctype, 암묵적인 태그 복구, HTML 파서 의존성은 없다.

| 요소 | 의미 |
|---|---|
| `view`, `main`, `div`, `section` | 자식 요소를 담는 컨테이너이며 기본 배치는 열 방향이다. |
| `text`, `p`, `span` | 타이포그래피를 상속하는 일반 텍스트 말단 요소이다. |
| `h1` | 기본 글자 크기가 28 논리 픽셀이며 굵게 표시되는 일반 텍스트 말단 요소이다. |

모든 요소는 박스이다. `span`은 인라인 흐름이 아닌 텍스트 박스이다.
컨테이너의 텍스트는 텍스트 요소 안에 배치해야 한다. 텍스트 말단 요소는 다른 요소를
포함할 수 없다. 텍스트의 연속된 ASCII 공백은 하나로 합쳐지며 앞뒤 ASCII 공백은 제거된다.
`&amp;`, `&lt;`, `&gt;`, `&quot;`, `&apos;`, `&nbsp;`, 10진수 `&#...;`,
16진수 `&#x...;` 유니코드 스칼라 참조를 디코딩한다. NUL, 서로게이트,
범위를 벗어나는 스칼라 참조는 오류가 된다. 일반 텍스트는 네이티브 글자 조형에 전달되며,
마크업을 네이티브 HTML 가져오기 기능에 전달하지 않는다.
줄바꿈과 정확한 글리프 치수는 설치된 글꼴에 따라 달라진다.

속성은 `id`와 `style`만 존재한다. 속성값은 작은따옴표 또는 큰따옴표로 감싸야 하며,
그 안의 엔티티도 디코딩한다. ID는 고유한 ASCII 식별자이며, 문자 또는 밑줄로 시작하고
이후에는 문자, 숫자, `_`, `-`를 사용할 수 있다.
중복 속성은 오류가 된다. 알 수 없는 태그·속성·속성 항목과 지원하지 않는 값도 오류가 된다.
스크립트, 이벤트 속성, 선택자, 외부 리소스, URL, JavaScript, `<style>`,
임의의 웹 콘텐츠를 실행하는 경로는 없다.

<a id="inline-styles"></a>

## 인라인 스타일

스타일은 세미콜론으로 구분하는 `property:value` 선언이며, 같은 속성을 여러 번 선언하면
마지막 선언이 적용된다. 마지막 세미콜론은 생략할 수 있다.
익숙한 표기를 사용하는 소규모 LVUI 어휘이며 CSS 엔진은 아니다.

| 속성 | 값과 기본값 |
|---|---|
| `width`, `height` | `auto`, 음수가 아닌 수, `px`, `0%`..`100%`; 기본값은 `auto`이다. |
| `display` | `flex`만 지원하며, 모든 컨테이너는 이미 흐름 레이아웃을 사용한다. |
| `flex-direction` | `column`이 기본값이며 `row`도 지원한다. |
| `padding` | CSS의 위·오른쪽·아래·왼쪽 순서로 음수가 아닌 픽셀 길이 1~4개를 지정한다. 기본값은 0이다. |
| `gap` | 자식 박스 사이의 음수가 아닌 픽셀 길이이며 기본값은 0이다. |
| `background`, `background-color` | 단일 단색이며 기본값은 투명이다. |
| `border-radius` | 음수가 아닌 픽셀 길이이며 짧은 박스 변의 절반 이하로 제한한다. 기본값은 0이다. |
| `color` | 텍스트 색상을 상속하며 루트 기본값은 검정이다. |
| `font-size` | 8..256 논리 픽셀 범위에서 상속하며 루트 기본값은 14이다. |
| `font-weight` | `normal` / `400` 또는 `bold` / `700`을 상속하며 루트 기본값은 400이다. |
| `text-align` | `left`, `center`, `right`를 상속하며 루트 기본값은 왼쪽이다. |

단위가 없는 수는 논리 픽셀이다. 픽셀 길이는 유한해야 하며 최대 8192이다.
음수, NaN, 무한대, 알 수 없는 단위는 오류가 된다. 색상은 sRGB로 인코딩된
`#RGB`, `#RGBA`, `#RRGGBB`, `#RRGGBBAA`, `black`, `white`, `transparent`를 지원한다.
iiGUI는 GPU 합성을 위해 이를 선형광 값으로 변환한다.

<a id="iigui-layout"></a>

## iiGUI 레이아웃

루트의 자동 크기는 논리 뷰포트를 채운다. 모든 크기는 패딩을 포함하는 border-box 방식이다.
열 방향에서 너비가 자동인 자식은 부모 콘텐츠의 너비를 채운다.
행 방향에서 너비가 자동인 자식은 고정 너비·백분율 너비·간격을 제외한 남은 너비를 균등 분배한다.
행 방향 자식은 위쪽에 정렬한다. flex 축소, 콘텐츠 기반 최소 너비, 절대 위치,
마진, 스크롤, 일반적인 CSS flex 알고리즘은 지원하지 않는다.

백분율은 부모 콘텐츠의 사용 가능한 크기를 기준으로 계산한다.
높이가 자동인 컨테이너는 부모로부터 받은 사용 가능 높이를 자손에게 전달한다.
높이가 자동인 열은 자식 높이·간격·패딩을 합산한다.
높이가 자동인 행은 가장 높은 자식의 높이에 패딩을 더한다.
높이가 자동인 텍스트는 네이티브 줄바꿈 측정값을 사용한다.
텍스트 높이를 명시하면 콘텐츠 사각형에 맞춰 잘라내며 글꼴 크기는 바꾸지 않는다.

자식이 고정된 컨테이너의 너비나 높이를 초과하면 Core의 `out_of_range` 오류로
레이아웃에 실패한다. 크기가 0인 빈 컨테이너는 허용하며 패널을 생성하지 않는다.
텍스트 박스의 콘텐츠 너비는 양수여야 한다. 둥근 배경은 자손에 대한 둥근 클리핑을 제공하지 않는다.
텍스트는 자신의 콘텐츠 사각형에서 잘리고, 전체 장면은 뷰포트에서 잘린다.
컨테이너를 자식보다 먼저 그린 다음, 겹치지 않는 텍스트 레이어를 그린다.

`ii::gui::layout_view(document, size)`는 CanvasFrame과 ID가 있는 요소의 논리 경계를 반환한다.
`Host::set_view(document)`는 현재 창 크기를 사용하여 기존의 갱신 병합 캔버스 API로
프레임을 접수한다. 값 스냅샷 방식이므로 Document를 유지하고 크기 변경 콜백에서 다시 호출해야 한다.
유효하지 않은 레이아웃은 이전에 접수한 장면을 보존한다.
숨겨진 폴링이나 애플리케이션 인터프리터를 도입하지 않는다.

<a id="limits-and-diagnostics"></a>

## 제한과 진단

파서는 UTF-8 입력 최대 1 MiB, 요소 4096개, 루트를 포함한 중첩 깊이 64단계까지 허용한다.
NUL은 거부한다. 진단에는 0부터 시작하는 바이트 오프셋과 1부터 시작하는 행·유니코드 스칼라 열이 포함된다.
유효하지 않은 UTF-8은 오프셋 0으로 진단한다. 엔티티를 디코딩한 스타일 문자열 내부의 오류는
원본 속성의 위치를 가리킨다. 소유된 불변 트리는 입력 버퍼보다 오래 유지될 수 있다.

렌더러는 iiGUI 캔버스 기하, 물리 텍스처, 텍스트 예산도 적용한다.
각 차원의 최대 크기는 8192 논리/장치 픽셀이며, 패널과 텍스트 실행 단위는 4096개,
텍스트 실행 단위당 64 KiB, 전체 텍스트는 1 MiB와 사용 가능한 장치 메모리로 제한한다.
따라서 파싱에 성공한 문서도 레이아웃이나 장치 접수 단계에서 실패할 수 있다.
이 구분을 통해 언어는 특정 그래픽 호스트로부터 독립성을 유지한다.
