# LVUI 언어·모듈 완성 기준

이 작업의 목표는 LVUI 언어와 네이티브 모듈을 독립적으로 완성하고 Qt/QML 및 LVRS
구현 의존성을 제거하는 것이다. LVRS의 시각 언어와 디자인 값만 계승한다.
Dreamscapes QML은 실제 사용 요구를 관측하는 입력이며, Dreamscapes를 변환하거나
제품 소스를 수정하는 작업은 포함하지 않는다. 일부 문법이나 예제의 성공을 전체 목표의
완료로 간주하지 않는다.

> 2026-10-28 사용자는 LVUI의 완전한 독립 구현을 요청했다. 아래 2026-10-27의
> 제품 작성 준비 기준은 중간 관문이며, 레거시 의존성을 남긴 채 종료할 근거가 아니다.
> 현재 구현과 남은 전환은 [독립 구현 현황](LVUIIndependence.md)을 따른다.

## 2026-10-27 사용자가 지정한 종료·설치 기준

이번 작업은 LVUI·iiGUI로 Dreamscapes의 뷰를 Qt/QML 없이 새로 작성할 수 있는 정도가
되면 종료하고 시스템 SDK에 설치한다. 이에 따라 관측된 제품의 화면·입력·상태 연결·
캔버스·타임라인·미디어·목록·창 수명을 실제 네이티브 구성으로 증명하는 것을 종료 관문으로
둔다. 사용하지 않는 LVRS 원본 API 전부와 모든 OS 실행 동등성을 먼저 달성해야만
종료할 수 있다는 의미로 이 기준을 확장하지 않는다. 원본 대응표의 partial/pending은
그대로 유지하며 제품 작성 준비 수준과 전체 LVRS 이식 완료를 구분한다.

관측 자료의 어휘 수나 장식용 모형만으로 이 관문을 통과시키지 않는다. 사용자 C++ 뷰의
구성·실패 보존·입력·프레임 갱신, 기존 컨트롤과 반응형 연결의 회귀, Qt 없는 독립 소비자와
설치본의 해시·패키지 해석을 확인한다. [NativeView](NativeViews.md)는 사용자 정의 영역을
구성하는 공통 접점이다. 이 종료 기준이 Dreamscapes 제품 소스의 자동 변환이나 제품 앱의
재설치까지 포함하는 것은 아니며, 제품은 요구 관측 대상으로 보존한다.

## 기준과 관측 자료

- 언어 의미는 `DeclarativeSyntax.md`, `TypeImports.md`, `ReactiveState.md`,
  `DeclarationAnnotations.md`, `InvocationLifecycle.md`의 채택된 규칙을 따른다.
- 네이티브 컴포넌트의 상태·배치·표현은 LVUI가 소유하며, 앱이 공급하는 iiGUI와
  OS는 창·입력·표면 경계를 제공한다. 아직 남은 `FRAMEWORK LVRS` 경로는
  독립 구현으로 교체해야 한다. Cocoa·Qt 컨트롤로 이를 갈음하지 않는다.
- `.lvui`는 빌드 시 C++로 생성한다. 실행 중 소스 해석, 문자열 식 평가 또는 별도 VM으로
  반응형 동작을 구현하지 않는다. 최종 앱 수명과 진입점은 iiSDKCore가 소유한다.
- `catalog/dreamscapes-qml.json`은 `tools/observe_qml.py`의 읽기 전용 관측 결과이다.
  파일별 해시·위치와 타입·속성·반복·조건식 등의 어휘상 사용을 기록한다. 이 자료는
  완전한 QML 의미 분석이나 LVUI 지원 증명이 아니며 자동 변환 결과도 아니다.
- LVRS 원본 선언·상속·동작은 LVRS의 `catalog/native/parity.json` 및 실제 C++·QML
  소스와 대조한다. 예약어 등록이나 생성 문자열 일치만으로 위젯 구현을 완료로 표시하지 않는다.

## 누적 구현 기록

이 절은 각 기능을 추가한 시점의 누적 기록이다. 최신 실행·설치 상태는
[네이티브 뷰 작성 검증](NativeReadinessVerification.md)을 따른다. 현재 구현에는 [표현식 AST·상수 계산](Expressions.md),
[네이티브 의존성 추적](NativeBindings.md), 스칼라 파생식·동적 인덱스·C++ 호출 결과와
스코프별 고정 스냅샷의 C++ 생성·독립 소비자 실행이 있다. [지역 스코프](LocalScopes.md)는
창 본문·중첩 뷰의 선언과 import, 부모 값 차용과 이름 가림을 별도 생성 C++로 검사한다.
[고정 View 값](ViewValues.md)은 어휘 포획·사용 위치별 ID·독립 지역 객체를 정적 C++로
확장한다. 동기 콜백의 접수 차단·약한 참조·진행 중 호출 보존과 iiGUI의 종료 훅도 추가했다.
[이름이 있는 입력·타입 매개변수·View 슬롯](Components.md)은 호출 환경 포획, 부모 백엔드
차용과 전달, 기본값, 반응형 입력 및 고정 스냅샷을 생성 C++ 위젯으로 검사한다.
[순서가 있는 View 구성](ViewSequences.md)은 `[View]` 슬롯·빈 목록·중첩·별칭을 중간
레이아웃 없이 확장하고 사용 위치별 지역 수명과 실제 자식 타입·수량 검사를 유지한다.
[키 기반 반복](Repetition.md)은 재정렬·추가·삭제·중첩과 C++ 모델이 제공한 표시 범위에서
행의 지역 상태·ID·입력·포커스 및 실패한 후보의 보존을 창 없는 실제 위젯으로 검사한다.
일반 `let`·`var`·`@Static let` 목록 선언도 C++ 저장소와 생성 위젯에 연결한다.
[조건부 콘텐츠](ConditionalViews.md)는 실제 생성 코드를 창 없는 iiGUI 상태에 연결하여
교체·정체성 유지·오류 롤백·복구·지역 객체 퇴역까지 실행했다.
고정 크기 목록·그리드의 자동 네이티브 가상화·기준점 보존은 생성 C++와 창 없는 위젯으로
검증한다. [자연 높이 측정](MeasuredCollections.md)은 가변 행·그리드, 0 높이·희소 표시와
모델의 크기 변경 통지를 네이티브 배치에 연결한다.
[키보드 탐색·키 기반 선택](CollectionNavigation.md)은 화면 밖 항목으로의 공개 요청과
실제 생성 C++ 입력을 연결한다.
[C++ 반환 콜백](ReturnedCallbacks.md)은 의존 갱신·자원 퇴역과 실제 이벤트에 연결한다.
[타입 지정 이벤트 콜백](CallableInputs.md)은 재사용 뷰의 전달·기본값·네이티브 이벤트 서명을
명시하고 최종 메서드·payload·반환 타입을 생성 C++로 검사한다.
[공유 콜백 값](CallbackValues.md)은 컴포넌트 입력 하나를 다중 소비자와 자식이 공유하고

[반환 함수 값](FunctionValues.md)은 읽기 전용 함수 선언·함수 입력 호출·버전 추적·Static
팩터리와 함수 버전 스냅샷·타입 지정 결과와 네이티브 함수 인터페이스를 연결한다.

[네이티브 Color](NativeColors.md)는 iiColorManager의 공유 값 계약과 타입 입력·가변 상태·
Static 스냅샷·채널·함수 인자/결과 및 위젯의 색상 표시를 연결한다.
[공유 스칼라 입력](ScalarInputs.md)은 구성 인자를 활성화별 한 네이티브 값으로 계산하여

루트 소유 접점에 연결하고 사용자 크기·입력·포커스와 후보 실패 시 기존 창을 보존한다.

정밀한 원본·플랫폼 동등성과 LVRS 실행 검증은 최종 일괄 단계에 남긴다.

깊이·실행 가능 여부와 C++ 명령만 연결한다. 모델·생성 위젯 실행은 최종 일괄 단계에 남긴다.
[플랫폼 서비스](NativePlatform.md)는 Core의 실제 플랫폼 정보와 원본의 18개 속성·9개
조회·41개 프로필 필드를 C++로 연결한다. 선택 문맥은 뷰 상태이며 파일·OS·렌더러를
변경하지 않는다. 원본 전체 소스에 고정한 기대값·상속/플랫폼 동등성·실행 검증을 구분한다.
[Core 값과 모델 레지스트리](NativeCoreValues.md)는 실제 C++ 모델의 공개 속성, 키별
쓰기 권한과 수명 관측을 연결한다. [페이지와 모델 수명](NativeRouteModels.md)은 네이티브
PageRouter의 성공 후 연결·생성 실패 보존·논리 이력 제거·스코프 종료 정리를 추가한다.
실행 검증과 원본 전체 계약의 동등성은 최종 일괄 단계에 남아 있다.
[네이티브 계층 뷰](NativeHierarchy.md)는 기존 계층 모델/투영을 실제 행 위젯·가상화 목록,
C++ 선택/펼침/키보드/드래그 컨트롤러 및 LVUI의 반응형 입력에 연결한다. 모델/컨트롤러
교체는 후보 세대의 성공 후 게시하며 실패하면 이전 뷰를 보존한다. 실제 펼침 변경은 배치로
모두 전달하고 선택/파일 데이터의 수명을 구분한다. HierarchyItem의 LVUI countView는
타입 지정 행 핸들·지역 import·독립 Bindings와 퇴역을 연결하며 생성 실패 후 재시도를 지원한다. 모델 role,
HierarchyItem 루트 itemDelegate도 소스 옵션·원래 명령과 사용자 설정을 연결하고 같은
키의 지역 import·입력을 유지한다. 수동 행·전체 delegate 정책, 상속/모바일/플랫폼 및
실행 계약은 계속 남아 있다.
숨김 공유모듈의 TLS 분리 재현을 바탕으로 iiSDKCore::Observation 공통 실행부를 연결하고,
설치·재배치·창 없는 위젯의 일반·메모리 검사로 해당 경계를 확인했다. 호스트 AOT 도구의
미사용 관측 DLL 의존성도 제거하여 설치 도구 직접 실행을 검사한다. 다른 플랫폼의 실제
증거와 전체 언어·LVRS 완료 조건은 계속 구분한다.
[네이티브 생성 입력](BackendConstruction.md)은 기존 앱 Runtime·서비스를 비이동 백엔드의
생성자로 전달하고 중첩 활성화·실패 롤백·자원 순서를 연결한다.
[등록한 비동기 작업](ActivationWork.md)은 기존 Runtime·직렬 큐·TaskScope에서 수행하고,
패널 제거 시 대기 전달 취소와 실행 중 소유자 보존 후 UI 영역의 퇴역에 연결한다.
실제 창의 입력·그리기, 목록의 나머지 전체 계약, 매개변수와 슬롯의 전체 타입 계약·일반
callable 타입·일부 컴포넌트 및 비동기 스코프 퇴역·플랫폼 실행 계약은
계속 남아 있다.
이 목록을 작업 결과에 맞추어 축소하지 않는다.
문서의 오래된 구현 설명은 소스와 검증에 맞추어 갱신하되, 실행하지 않은 항목을 통과로
바꾸지 않는다.

LVRS 저장소의 지침에 따라 LVRS 앱·테스트의 실행 검증은 전체 작업의 최종 일괄 단계에
모은다. 중간 컴파일·링크·코드 생성·정적 검사와 실제 실행 통과를 구분한다.

관측 자료의 갱신·검사는 다음과 같다.

```sh
python3 -B tools/observe_qml.py
python3 -B tools/observe_qml.py --check
python3 -B -m unittest discover -s tests -p test_qml_observation.py
```


### 설치 소비자 검사 시간과 런타임 응답 기준

`LVUI.NativeInstalled`는 설치·재배치, 오래된 Core 거부, 부정 C++ 계약 검사와 별도의
소비자 세 개를 새로 빌드·실행한다. 2026-10-27 오류 검출 구성에서 기존 180초의 통합
제한을 두 차례 넘겼고, 두 번째 시도는 일반/컴파일러 소비자 두 개의 통과 후 마지막
런타임 소비자 빌드 중 종료됐다. 따라서 이 패키지 검사 한 항목의 제한을 360초로 한다.
개별 값·메서드 검사 제한이나 제품의 UI/런타임 지연 기준을 바꾸는 조정이 아니다.
원래 실패 기록, 동일 조건 재실행과 제한 변경 후 재실행을 별도로 보존한다.

패키지 소비자는 Release 최적화로 빌드하며 상위 검사의 sanitizer 플래그를 함께 전달한다.
따라서 Debug 라이브러리를 사용하는 패키지 검사도 최적화된 소비자 컴파일 비용을 가진다.
360초 제한에서 같은 오류 검출 소비자 검사가 321.05초에 통과했다. 이 값은 설치·컴파일·
검사 전체 시간이며 애플리케이션 또는 UI의 실행 지연 측정값이 아니다.
