# 안정적인 키를 갖는 네이티브 반복 구성

`for`는 C++ 컬렉션이나 비어 있지 않은 동종 목록으로부터 반복 뷰를 만든다. 키를 명시해야
하며 위치가 바뀌어도 키가 같은 행은 같은 위젯·지역 백엔드·입력 상태를 유지한다.

```lvui
import vm Backend
Window {
    for (item in vm.items, key: item.id, index: ordinal, id: "results") {
        VStack {
            Label(text: item.title)
            Label(text: ordinal)
        }
    }
}
```

이는 빌드 시 C++23 행 구성 함수와 `lvui::native::KeyedRows<T>`로 생성한다. 런타임에서
LVUI 소스·AST·표현식 문자열을 순회하거나 해석하지 않는다. `LVUI::Native`의 컬렉션 상태는
iiSDKCore 계약에만 의존하며, 생성한 UI가 iiGUI의 키 기반 콘텐츠 API를 연결한다.

일반 목록 값도 선언할 수 있다. `let` 목록은 원본 의존성을 따르는 읽기 전용 C++ 값,
`var` 목록은 Core Observable 저장소, `@Static let` 목록은 활성화 당시 스냅샷을 사용한다.

```lvui
let labels = ["A", "B", "C"]
let liveValues = [vm.first, vm.second]
@Static let initialValues = [vm.first, vm.second]
var choices = ["One", "Two"]
```

원소 타입은 C++로 추론한다. 문자열은 소유 문자열로 보관하며, 같은 C++ 정수 타입의
목록은 64비트 값을 유지한다. 서로 다른 숫자 타입은 기존 숫자 연산처럼 유한한 `double`
값으로 통합한다. 호환되지 않는 원소는 C++ 타입 검사에서 거부한다. 원소 타입을 결정할
정보가 없는 `[]` 선언과 아직 정의하지 않은 명시적 배열 타입 표기는 거부한다. 비어 있는
상태가 필요한 모델에는 원소 타입을 가진 C++ 컬렉션을 사용한다.
목록을 다른 이름의 값으로 연결해도 알려진 목록 타입을 유지하여 스칼라로 잘못 선언한
입력은 LVUI 소스 위치에서 거부한다.

## 키·행·지역 상태

- `key`는 고유하고 비어 있지 않은 UTF-8 문자열 또는 정확히 표현 가능한 정수이다.
  키당 최대 1,024바이트이며 NUL을 허용하지 않는다. 모델 전체에서 키를 검사하므로
  현재 표시 범위 밖에 있는 중복도 오류이다. 인덱스가 바뀌어도 유지되는 식별자를 사용한다.
  키를 계산하는 C++ 식은 원본 컬렉션의 구조를 변경하지 않는 계약을 따른다.
  C++ 정수 키는 원래 타입에서 직접 문자열화하여 64비트 식별자를 보존한다. 실수 키에만
  유한하고 정확한 정수 범위 검사를 적용한다.
- `index`는 선택적인 지역 이름이다. 현재 표시 범위 안의 순서가 아니라 전체 모델에서의
  0 기반 위치를 제공한다. 행 데이터와 위치는 하나의 Core Observable 값으로 발행한다.
- 같은 키의 값이 바뀌면 기존 행의 의존 값만 다시 계산한다. 지역 import·`var`·`@Static`
  선언을 초기화하지 않는다. 변경 없는 값은 추가 알림을 내보내지 않는다.
- 키가 사라지면 해당 행의 위젯 세대와 지역 객체를 퇴역한다. 같은 키를 나중에 다시
  추가하면 새 활성화와 스냅샷을 생성한다. 선택·검토 상태처럼 행보다 오래 유지할 상태는
  상위 C++ 모델이 키를 기준으로 소유한다.
- 각 반복 안에서 같은 명시적 자식 ID를 사용할 수 있다. iiGUI가 키별 독립 세대를
  제공하며 같은 자식 ID·키를 다른 중첩 목록에서 사용해도 충돌하지 않는다.

기존 [타입 매개변수 구성](Components.md)에 행을 전달할 수도 있다. C++ 범위가 정하는
실제 행 타입은 생성 C++에서 선언한 청사진과 대조하고 constness를 유지한다. 값 객체의
읽기 전용 행과 `shared_ptr`로 명시적으로 공유하는 변경 가능한 객체를 구분한다. 행 타입은
Core Observable의 복사·동등성·예외 없는 이동 대입 계약을 만족해야 한다.

## 표시 범위와 레이아웃

```lvui
for (item in vm.items, key: item.id, index: ordinal,
     first: vm.firstVisible, count: vm.visibleCount,
     spacing: 4, horizontal: false) {
    Label(text: item.title)
}
```

`first`와 `count`는 0 이상의 정수이며 기본값은 처음부터 전체 범위이다. 끝을 넘는 시작
위치는 빈 범위, 남은 항목보다 큰 수량은 남은 범위로 제한한다. 표시 범위만 행 데이터와
위젯을 생성하고, 겹치는 키는 기존 활성화를 유지한다. 범위 밖으로 나간 행은 숨김 상태로
보관하지 않고 제거한다. 단순 `visible: false`와 이 활성화 제거를 동일하게 취급하지 않는다.

이 수동 모드의 표시 범위는 C++ 뷰모델이 제공한다. `first`·`count`만으로 스크롤 위치와
논리 길이를 계산하지 않는다. 고정 크기 목록·그리드의 자동 모드는 다음 절의
`itemHeight` 계약을 사용한다. [가변 행 측정](MeasuredCollections.md)과
[키보드 탐색·선택](CollectionNavigation.md)은 자동 모드에 연결한다. 목록의 나머지 전체
계약은 [구성 완료 기준](Completion.md)에 계속 남아 있다.

반복은 독립적인 선형 콘텐츠 컨테이너이다. `horizontal` 기본값은 `false`, 내부 `spacing`
기본값은 0이다. 주변 스택의 자식 목록을 암묵적으로 평탄화하거나 간격을 복제하지 않는다.
필요한 방향·간격은 반복 입력으로 지정한다. 기본 LVRS 컨트롤의 크기·스타일은 바꾸지 않는다.

본문은 루트 View 하나를 가지며 여러 자식과 지역 선언은 `VStack` 같은 본문 View에 둔다.
중첩 반복과 조건부 구성은 같은 스코프 계약을 따른다. `TabBar`·메뉴 같은 타입 제한 자식
입력에 일반 콘텐츠 호스트를 삽입하여 제약을 우회하지 않는다.

## 자동 네이티브 가상화

고정 행 높이를 `itemHeight`로 제공하면 네이티브 스크롤이 표시 범위를 결정한다.
`itemWidth`를 함께 지정하면 뷰포트 너비와 간격에 맞추어 열 수를 정하는 그리드가 된다.

```lvui
Window {
    VStack {
        for (item in vm.results, key: item.id, id: "results",
             itemHeight: 180, itemWidth: 150, spacing: 8, overscan: 1) {
            ResultCard(backend: item)
        }
    }
}
```

표시 범위를 QML이나 제품 백엔드에서 매번 계산하지 않는다. AOT 출력은 iiGUI의
`ScrollView`, 키별 콘텐츠와 C++ `VirtualViewport`·`VirtualCollectionSource<T>`·
`virtual_collection_frame`을 연결한다. `LVUI::Native`에는 iiGUI 의존성을 추가하지 않는다.

| 입력 | 의미 |
|---|---|
| `itemHeight` | 양수인 고정 행·셀 높이, 자동 모드 선택 |
| `itemWidth` | 자동 열 계산의 기준 너비; 생략하면 세로 목록 |
| `columns` | 0이면 자동, 양수이면 명시한 열 수 |
| `overscan` | 표시 영역 전후에 유지할 추가 행 수, 기본 1 |
| `horizontal` | 가로 목록; 양수 `itemWidth`가 필요하며 다중 열과 함께 쓰지 않음 |
| `width`, `height` | 스크롤 뷰의 명시 크기, 0이면 주변 레이아웃 사용 |
| `flex` | 주변 선형 스택의 가용 공간 비율; 높이가 0이면 기본 1, 양수이면 기본 0 |

이 입력도 일반 반응형 값이다. `width`·`height`·`flex` 변경과 모델 변경은 뷰포트 상태와
독립적인 네이티브 바인딩으로 전달한다. 창의 루트 자체는 네이티브 루트 레이아웃 계약에
따라 전체 영역을 사용한다. 명시한 크기의 하위 목록은 예시처럼 레이아웃 안에 둔다.
자동 모드는 `first`·`count`를 동시에 받지 않는다. `measureHeight: true`를 추가하면
[네이티브 자연 높이 측정](MeasuredCollections.md)을 사용한다. 이 경우 `itemHeight`는
미측정 행의 추정값이며 공유 객체 모델의 변경 통지는 해당 문서의 계약을 따른다.
LVUI 입력에서 `itemHeight`는 0.000001~32,767, `itemWidth`·`spacing`은 0~32,767,
`width`·`height`는 0~8,192, `flex`는 0~4,096이다. `columns`·`overscan`은 0~65,536의
정수이다. 큰 여유 영역을 지정해도 아래의 실제 활성 노드 한계를 우회하지 않는다.

모델 또는 키 의존성이 발행될 때 전체 키의 유효성·중복·한계를 검사하고, 소유한 C++
값 스냅샷과 키 색인을 한 번 만든다. 스크롤 중에는 이 스냅샷을 재사용하여 표시·여유
범위의 값만 프레임으로 복사한다. 가시 행의 위젯과 지역 백엔드만 생성한다. 모델 전체의
값 스냅샷은 보유하므로 이를 전체 데이터의 메모리 사용이 없다는 의미로 해석하지 않는다.

현재 표시 영역의 첫 항목 키와 행 내부 픽셀 위치를 기준점으로 보관한다. 앞에 결과가
삽입되거나 창 너비가 바뀌어 열 수가 변경되어도 해당 항목을 같은 높이에 유지한다.
기준 키가 사라지면 이전 인덱스를 유효 범위로 제한한다. 사용자 스크롤은 별도의 이동
세대로 구분하므로 이전 기준점이 사용자 이동을 되돌리지 않는다. 그리드 행의 첫 열이
아닌 기준 항목도 열 수 변경 후 계속 기준으로 유지한다.

논리 스크롤 범위와 보유한 자식의 실제 크기를 분리한다. 긴 목록 전체를 거대한 위젯으로
만들지 않으며, 셀 좌표는 현재 뷰포트에 상대적이다. 같은 키가 유지되는 픽셀 이동에서는
행 세대와 래퍼를 재생성하지 않고 위치만 갱신한다. 가시 영역 밖 행은 종료한다. 따라서
행의 지역 상태는 화면 밖 퇴역 후 재진입까지 영속하지 않으며, 그러한 선택·평가 상태는
제품의 네이티브 모델이 안정적인 결과 ID에 따라 보관해야 한다.

`id: "results"`는 키별 콘텐츠 호스트, `"results/viewport"`는 해당 스크롤 뷰이다. 이 파생
ID도 중복 검사한다. 첫 배치 전에는 행을 추측하여 만들지 않는다. 창·측정 결과가 들어온
뒤 실제 범위를 활성화한다. 새 행 생성이나 모델 키 검증이 실패하면 기존 행을 보존하고
바인딩 오류로 남기며, 다음 유효한 모델 변경 또는 뷰포트 이동에서 다시 적용할 수 있다.
행 활성화 도중 더 새로운 크기나 스크롤 입력을 받으면 이전 프레임의 기준점 발행을
거부하고 새 입력을 반영한 계산을 수행한다. 이전 계산으로 사용자 이동을 덮어쓰지 않는다.

## 실패·종료·한계

신규 행은 후보 콘텐츠에서 먼저 생성한다. 하나라도 실패하면 기존 순서·행·입력 상태와
데이터를 보존하며 실패한 후보만 퇴역한다. 검증이 끝나면 유지할 행의 소유 관계를 옮기고
이전 래퍼·제거된 행을 정리한다. 다시 그리기·같은 키·같은 순서는 생성을 일으키지 않는다.

행 상태의 구조 반영이 성공한 뒤 데이터·인덱스를 발행한다. C++ 관찰자가 발행 중 실패한
경우는 바인딩 오류로 보고하며 이미 수행한 임의의 관찰자 동작을 되돌린다고 보장하지 않는다.
생성 실패의 구조 롤백과 사용자 C++ 콜백의 부작용 롤백을 구분한다.

활성화가 닫히면 새 구성을 거부하고 연결·지역 객체를 퇴역한다. 늦은 팩토리와 콜백은
약한 소유자·바인딩 접수 경계를 확인한다. UI 입력 상태를 바꾸는 작업은 파일 상태나
문서 저장·편집 이력의 변경으로 변환하지 않는다.

컬렉션은 최대 65,536개 항목과 합계 16 MiB 키를 허용한다. 실제 iiGUI 위젯은 기존의
활성 도메인 4,096개 노드와 콘텐츠 활성화 깊이 8단계 한계를 유지한다. 표시 범위는 이
실제 활성 자원 한계 안에서 정한다. 반복 교체 시 이전 래퍼가 노드 수에 누적되지 않으며,
임시 후보 허용량에서 재사용하는 행을 중복 계산하지 않는다.

## 검증

- `LVUI.Repetition.*`: 구문·어휘 스코프·네이티브 생성·범위·오류 및 CLI 표시.
- `LVUI.NativeCollection.*`: 키와 행 정체성, 데이터·위치의 일관된 발행, 실패 보존,
  1,000개 모델의 범위 제한, 종료·실행 영역과 잘못된 입력.
- `LVUI.NativeVirtualCollection.*`: 세로·가로·그리드의 실제 범위와 논리 길이,
  기준점·열 수 변경·사용자 이동, 색인 재사용·불변 스냅샷과 스레드·종료 계약.
- `iiGUI.keyed_content.*`: 실제 위젯의 편집·포커스·키보드 라우팅·ID 보존, 실패 복구,
  반복 교체의 자원 회수와 4,096개 노드 경계.
- `iiGUI.native_repetition.*`: 실제 생성 C++의 행별 지역 객체·스냅샷, 재정렬·반응형
  데이터·표시 범위·실패 복구·중첩 목록·일반 목록 선언과 전체 소유자 해제.
- `iiGUI.native_virtual_repetition.*`: 생성 C++의 자동 표시 범위·픽셀 위치 갱신,
  결과 삽입·반응형 크기·기준점 보존·실패 복구·전체 소유자 해제와 파일 리비전 비변경.

위의 iiGUI 검사는 창·렌더러를 열지 않는다. 실제 창·GPU·플랫폼 입력과 전체 LVRS 앱·
테스트 실행은 최종 일괄 검증과 구분한다.

`LVUILVRSRepetitionCompile`은 `FRAMEWORK LVRS`로 생성한 값 행·공유 백엔드 행·가상 그리드의
실제 팩토리를 현재 LVRS 공개 헤더에 대조하여 컴파일하는 오브젝트 대상이다. 실행 파일을
만들거나 LVRS 앱·테스트를 실행하지 않으며, 최종 LVRS 런타임 검증을 대신하지 않는다.
