# 반환값이 있는 네이티브 함수 값

서명을 생략하는 선언은 [C++ 타입 추론](InferredValues.md)을 사용한다.
함수 팩터리가 차용한 수신자와 임시 인자는 [포획 수명](FactoryCaptures.md)에 따라 해당
함수 버전이 보존한다. 가변 내부 상태와 외부 원본의 깊은 복사는 구분한다.

LVUI의 함수 값은 C++ 메서드 참조, [callable 필드](CallableFields.md) 또는 C++가 반환한 callable을 선언된 서명으로
연결한다. 처리 본문은 C++에 두며 `.lvui`에 실행 함수 본문이나 소스 인터프리터를 추가하지 않는다.

```lvui
import vm Model
let direct: (Int) -> String = vm.format
let dynamic: (Int) -> String = vm.makeFormatter(vm.amount)
@Static let frozen: (Int) -> String = vm.makeFormatter(vm.amount)
@Static let selected: (Int) -> String = dynamic

let Info(format: (Int) -> String, accepts: (Int) -> Bool = vm.accepts): View = VStack {
    Label(text: format(vm.count))
    PushButton(enabled: accepts(vm.count))
}
Window { Info(format: dynamic) }
```

## 선언·호출·타입

함수 매개변수와 읽기 전용 `let`은 `(입력 타입, ...) -> 결과 타입`을 사용한다.
기본값·별칭·다단계 전달은 호출 위치와 정의 위치의 기존 어휘 환경을 유지한다.
직접 호출과 괄호로 묶은 함수 값의 호출을 네이티브 C++로 생성한다. 인자 수가 다른 호출,
표시값이 필요한 곳의 `Void` 호출, 이벤트 입력에 결과가 있는 함수를 전달하는 경우는 거부한다.

입력과 결과에는 `String`, `Bool`, `Int`, `Float`, `Double`, `Metric`, `Color` 및
가져온 C++ 청사진 타입을 사용할 수 있다. `Void`는 결과에만 사용한다. 함수 결과의
String은 소유 `std::string`, Bool은 bool, Int는 범위 검사한 `std::int64_t`이다.
실수 결과는 유한 값과 선언 타입의 범위를 검사한다. 사용자 C++ 결과는 선언한 값 타입으로
검사하고 반환한다. 비복사·비이동 값도 C++ 복사 생략이 허용하는 직접 반환을 유지한다.
C++ 객체 결과의 값 반환 계약과 팩터리가 반환한 **함수 객체**의 참조 차용은 서로 다른 계약이다.

함수 호출에서 Int 인자는 기존 `integer` 규칙으로 검사한다. C++ 이벤트의 정수 payload
계약은 [이벤트 입력](CallableInputs.md)을 따른다. 최종 C++ 메서드의 존재·접근성·오버로드·
실제 반환 타입은 생성 C++의 검사 대상이다. 헤더를 문자열로 탐색하여 호출하지 않는다.

## 반응형 계산과 함수 버전

읽기 전용 함수 호출은 표시값을 계산하며 합성 백엔드 리비전이나 파일 리비전을 발행하지
않는다. 읽은 원본과 함수 값의 현재 버전을 네이티브 `ReadContext`에 등록한다. 따라서
호출 인자가 그대로여도 팩터리가 새 함수를 게시하면 기존 표시 위젯을 갱신한다.

리비전 비변경은 생성 어댑터가 불필요한 발행을 추가하지 않는다는 보장이다. C++ 함수
본문의 임의 변경을 차단하지는 않는다. 표시 계산용 함수는 모델이 읽기 연산으로 제공하고,
작업 실행과 파일 변경 명령은 명시적인 이벤트·작업 경로에 둔다.

함수 팩터리는 파생 값으로 평가하여 소비 효과보다 먼저 준비한다. 팩터리 실패는 이전
유효 함수를 유지하고 오류를 기록한다. 함수 호출이 실패하면 해당 표시 바인딩의 이전
유효 결과를 유지한다. 의존값이 복구되면 새 결과로 회복한다. 원래 C++ 메서드·팩터리의
합성 리비전 읽기 규칙은 유지하므로 그 리비전 변경도 계산을 갱신할 수 있다.

`@Static let`의 팩터리 식은 해당 활성화에서 한 번 평가하며 이후 입력 변경으로 팩터리를
다시 실행하지 않는다. 함수에 나중에 전달하는 호출 인자는 계속 반응형이다. C++ 함수가
참조한 원본 객체의 모든 내부 상태를 깊게 복사하는 기능은 아니다.

## 수명과 C++ 인터페이스

`CallbackValue<R(Args...)>`는 현재 함수 버전과 결과를 타입 지정 C++로 연결한다.
`read(context, ...)`는 함수 버전을 추적하며, 일반 호출은 현재 함수를 사용한다. 실행 중
교체·자기 제거는 호출한 버전과 수신자를 반환까지 보존한다. 닫힌 함수 또는 잘못된 실행
영역에서 결과를 요구하면 `logic_error`로 실패하며 0·빈 문자열 같은 결과를 만들지 않는다.
Void 이벤트의 닫힌 호출은 기존 접수 차단 규칙을 유지한다.

함수 원본은 기존 `Bindings::derive`와 `ReadOnlyValue`로 유지한다. 외부 값 핸들이 남아도
소유 그래프 종료가 함수 자원을 정리한다. C++ 객체를 반환하는 동안 수신자와 함수 버전을
보존하고 결과를 만든 뒤 해제한다. 명시적인 비동기 작업은 별도 [작업 수명](ActivationWork.md)을 사용한다.

`valueValidator` 같은 네이티브 함수 입력에는 선언한 결과와 인자를 갖는 범위 검사된
C++ callable을 전달한다. 결과가 있는 함수에는 읽기 전용 호출 경계를 적용한다.

## 현재 경계와 검증

`@Static` 함수 별칭은 선언 시점의 함수 버전을 선택한다. 함수 객체와 이동 전용 캡처를
복사하지 않으며, 선택한 버전의 가변 내부 상태는 같은 버전을 사용한 소비자들과 공유한다.
원본의 이후 버전 교체에는 반응하지 않지만 호출 인자는 계속 현재 값을 받는다. 선택한
버전의 자원은 스냅샷의 활성화가 소유하며, 원래 수신자가 종료되면 새 호출을 거부한다.
스냅샷 그래프가 종료되면 외부 값 핸들이 남아도 선택한 캡처를 정리한다. 이 계약의 구현·
검증은 아래의 기존 함수 연결 검증과 별도로 갱신한다.

공개 C++ `snapshot_callback_value(scope, bindings, value)`도 같은 버전 선택과 수명 규칙을
사용한다. 선택한 함수의 원래 수신자는 계속 차용하므로 원본 종료 후 사용할 수 없으며,
이동 전용 캡처의 정리는 선택한 스냅샷의 그래프가 종료될 때 수행한다. 실행 중인 스냅샷은
자기 화면을 제거해도 선택한 버전과 접수한 수신자를 결과 반환까지 보존한다.
팩터리가 반환한 좌측값 참조와 함수 참조는 복사하거나 소유 값으로 바꾸지 않는다.
그 버전의 주소와 constness를 유지하되 수신자를 보존하는 참조는 실행을 접수한 동안만
확보한다. 참조 대상의 외부 무효화는 원래 C++ API 계약을 따른다.

[가변 함수 값](FunctionVariables.md)은 명시적 대입·초기 버전 선택·현재 버전 공유와
C++ setter를 별도 네이티브 슬롯에 연결한다.
LVUI 함수 본문, 부분 적용, 중첩 함수 타입과
전체 일반 타입·프로토콜은 전체 완료의 남은 항목이다.

호출·추적·선택 메타데이터는 하나의 공유 상태로 접수한다. 사용자 C++ 접수 검사나 선택
콜백이 함수 값 자체를 제거해도 실행 중인 메타데이터는 반환까지 보존한다. 이 보존을
위해 매 호출마다 타입 소거 함수를 복사하거나 할당하지 않는다.

[네이티브 함수 값 검사](../tests/native_function_values.cpp)는 결과·함수 버전 변경·실패
복구·잘못된 실행 영역·종료 후 결과 요구를 검사한다.
[실제 생성 위젯 검사](../../iiGUI/tests/native_function_values.cpp)는 C++ 메서드·팩터리·
Static 값·여러 소비자·원본과 파일 리비전 비변경·실패·종료 중 반환을 확인한다.
스냅샷 검사는 선택한 함수 버전의 가변 내부 상태 공유·이후 버전 격리·반복 스냅샷·
Void 이벤트·원래 수신자 종료·자기 제거·다른 실행 영역 거부를 포함한다. 실제 생성 위젯은
부모와 조건부 자식의 독립 선택, 제거 후 재활성화 시점의 새 버전 선택을 확인한다.
실제 LVRS 앱·GPU·플랫폼 실행은 [전체 완료 감사](Completion.md)의 최종 검증으로 유지한다.
