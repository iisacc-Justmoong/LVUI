# C++ 반환 함수의 수신자·인자 보존

반환 함수의 C++ 객체를 소유하는 것만으로 그 함수가 차용한 수신자까지 보존되지는 않는다.
LVUI는 반환 함수를 선택하는 동안 선택된 공유 부모와 임시 수신자·인자를 함께 보존하고,
그 소유권을 현재 함수 버전에 연결한다. 실행 중 소스 해석이나 별도 객체 등록소를 사용하지 않는다.

```lvui
import vm Model
let render: () -> String = vm.selected.makeDescription()
@Static let original: () -> Void = vm.selected.makeHandler()
Window { VStack {
    PushButton(vm.temporary().makeHandler())
    PushButton(vm.capture(vm.makeArgument()))
    Label(text: render())
} }
```

`makeHandler()`를 평가하여 함수 객체를 받는 시점과 그 함수를 실행하는 시점은 다르다.
임시 수신자와 인자의 저장소도 첫 실행 전에 파괴되지 않아야 한다. C++ 팩터리가 참조로
함수를 반환하거나 값으로 반환한 함수가 `this`를 포획한 경우 모두 같은 수신자 보존을 적용한다.

## 생성과 C++ 계약

`Methods::callable(context, factory)`는 독립적인 읽기 문맥에서 팩터리를 평가하고 읽은
원본을 바깥 바인딩에 전달한다. 선택된 공유 부모와 중간 임시 객체는 반환한 네이티브 함수
참조가 보관한다. 값·우측값 반환은 소유 저장소로 만들고, 좌측값·함수 참조는 원래 정체성과
constness를 보존하여 차용한다. 소유한 함수 객체는 기존 계약대로 좌측값으로 호출하며,
이동·복사가 불가능한 값 반환은 C++ 직접 생성으로 소유한다.

생성기는 함수 팩터리의 수신 경로에 기존 `receiver_member`·`receiver_index`를 사용한다.
`Methods::argument`는 인자의 좌측값·우측값 참조 범주를 유지하고, 값으로 계산한 임시
인자는 먼저 소유한 뒤 원래 우측값으로 전달한다. 함수 인자를 받는 C++ 오버로드를 임의로
좌측값 오버로드로 바꾸지 않는다. 생성기는 C++ `requires`로 각 인자의 보존 가능성을
선택한다. 이동·복사 불가능한 값을 값 매개변수로 받는 경우는 원래 prvalue와 보장된 복사
생략을 유지하며, 같은 호출의 다른 참조 인자는 계속 보존한다. 선택은 컴파일 시 선형
검사이며 호출 시 오버로드 탐색이나 인자 해석을 수행하지 않는다.
값으로 전달되어 C++ 함수 안에서 다시 이동·복사된 인자와
함수의 지역 변수는 그 함수가 책임진다. 이미 파괴된 참조를 반환하는 C++ API를 복구하지 않는다.

소스의 일반 반응형 함수는 의존 원본이 바뀌면 새 버전으로 교체한다. 실행 중인 호출은
이전 함수·수신자·인자 저장소를 반환까지 보존한다. `@Static`과 가변 함수의 초기 선택은
같은 내부 소유권 수집을 사용하지만 바깥 문맥에 변경 의존을 연결하지 않는다. 차용한
외부 객체의 내부를 깊은 복사로 고정하는 계약은 아니다.

## 실패와 종료

실패한 이후 평가에서는 마지막 유효 함수와 그 소유자를 유지하며 복구 가능한 의존값의
구독을 보존한다. 최초 실패는 후보 활성화에 실패한다. 소유 뷰 종료나 다른 실행 영역의
새 호출은 기존 콜백·함수 값의 접수 경계를 따른다. 실행 중 자기 뷰를 제거해도 반환까지
필요한 소유자를 보존하며, 이후 외부 콜백 핸들이 백엔드를 되살리지 않는다.

검토 상태와 파일 상태는 별개이다. 함수 선택·버전 고정·표시 갱신은 파일 리비전이나 저장을
발동하지 않는다. 명령 실행 후 합성 백엔드 변경 발행은 기존 public 필드 갱신 계약을 따른다.

## 검증

실제 생성 위젯의 `native_factory_captures` 검사는 임시 수신자와 임시 인자의 조기 파괴를
함수 호출 없이 수명 카운터로 먼저 재현한다. 이후 수신자 선택·실행 중 교체·재진입·실패 복구·
고정 선택·문자열 이벤트·인덱스·조건부 재활성화·자기 제거와 편집 상태 보존을 검사한다.
일반 타입 추론과 전체 LVRS·플랫폼 계약은 [전체 완료 감사](Completion.md)의 별도 조건이다.

임시 수신자와 임시 인자가 첫 실행 전에 파괴되는 실패 2개를 수명 카운터로 먼저
재현했으며 파괴된 함수는 호출하지 않았다. 수정 후 참조·값 반환 함수, 이동 불가 값,
수신자 교체 중 재진입, Static·가변 초기 선택, 실패 복구와 자기 제거를 실행했다.
이동 불가 값 매개변수와 참조 매개변수가 같은 호출에 있는 경우도 타입·실행 검사로
확인했다. 기존 초기화 코드의 문자열 형태를 전제한 검사 한 곳은 새 내부 문맥과
인자 보존 형태에 맞춰 갱신하고 전체 검사를 다시 통과했다.

생성 위젯 실행 파일은 Qt 동적 의존성과 LVUI 파서·컴파일러 실행 심볼을 포함하지 않는다.
iiGUI 메모리 검사는 생성 C++와 WidgetState를 계측하며, 차용한 일반 Native 아카이브의
구현은 LVUI의 별도 메모리 검사로 검증한다. 이 결과는 실제 LVRS 앱·OS 창·GPU·다른
플랫폼의 실행이나 제품 UI 지연 개선률을 입증하지 않는다.

소스 해시·원시 로그·실패 재현·설치 소비자와 바이너리 의존성은
`build/lvui-completion/factory-captures-verification-20261026.json`에 기록한다. 언어의
전체 타입·프로토콜과 LVRS·플랫폼 완료 조건은 이 단계의 결과로 축소하지 않는다.
