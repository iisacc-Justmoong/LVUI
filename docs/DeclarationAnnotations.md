# 선언 어노테이션

상태: 선언 앞에 `@State`, `@Bindable`, `@Observable`, `@Static`을 붙일 수 있다.
`@State`와 `@Bindable`은 기본 의미를 선택적으로 명시하며 조합할 수 있다.
`@Static`은 불변 `const`만 허용하며 기본 상태·바인딩을 명시하는 두 표기와 충돌한다.
중복·충돌과 미확인 어노테이션은 진단한다. 상수 AOT와 외부 C++ 스냅샷의 구현 경계는
[Expressions.md](Expressions.md)를 참조한다. 이전 HTML 0.1 파서와 이 프런트엔드를 구분한다.

[AOT 컴파일러](CompilationModel.md)는 어노테이션을 네이티브 관찰·수명 동작으로 변환한다.
일반 변수를 포함한 [반응형 값과 바인딩](ReactiveState.md)은 언어의 기본 동작이다.
이 기본 의미는 `@State`와 `@Bindable`에 해당한다. 두 표기를 붙일 필요는 없다.
애플리케이션 실행 중 인터프리터가 소스 어노테이션을 평가하여 이 의미를 구현하지 않는다.

<a id="placement"></a>

## 배치 위치

어노테이션은 선언 키워드 앞에 온다. 채택한 선언 구문은 타입 앞에 콜론,
초기값 앞에 등호를 사용하며 세미콜론 종결자는 사용하지 않는다.

```text
@State @Bindable var draft: String = "Draft"
@Observable var value: Int = 6
@Static const initialValue: Int = 6
```

<a id="selected-meanings"></a>

## 채택한 의미

| 어노테이션 | 의미 |
|---|---|
| `@State` | 선언이 기본적으로 갖는 뷰 활성화 상태 의미를 명시한다. |
| `@Bindable` | 선언이 기본적으로 갖는 반응형 바인딩 의미를 명시한다. 쓰기 권한을 추가하지 않는다. |
| `@Observable` | 관찰을 명시한다. 정적 값이 아닌 값은 이미 기본적으로 변경 추적과 바인딩을 사용한다. |
| `@Static` | 해당 선언에 생성된 수명 동안 변경할 수 없는 값을 설정한다. |

`@State`, `@Bindable`, `@Observable`은 함께 사용할 수 있다. 같은 표기의 중복과
`@Static`에 `@State` 또는 `@Bindable`을 결합하는 선언은 오류이다. 현재 시각적
View 선언과 재사용 View 시그니처에는 이 두 기본 값 표기를 적용하지 않는다.
구문 트리는 명시적으로 작성된 두 표기를 `explicit_state`, `explicit_bindable`로
보존하지만, AOT 동작은 표기가 없는 동일 선언과 같다.

이 어노테이션은 `const`와 `var` 규칙에 선언 의미를 추가한다.
`const`는 재대입을 금지하며 일반 `var`는 타입 계약에 따라 재대입을 허용한다.
어노테이션으로 C++ 접근 제한을 우회하거나 읽기 전용 원본에 쓸 수는 없다.

<a id="bindings"></a>

## 바인딩

값은 기본적으로 반응형이며 ViewModel도 같은 일반 규칙을 따른다.
뷰는 바인딩 어노테이션이나 별도의 바인딩 래퍼 선언 없이 기존 VM의 공개 상태를 직접 사용한다.
다음 뷰 조각은 가져온 VM을 직접 사용하는 예이다.

```text
import vm CounterViewModel

Label(text: vm.value)
PushButton(vm.increment)
```

속성 바인딩은 원본 VM 상태를 읽고 해당 변경 계약을 따른다.
편집 가능한 바인딩은 검증·쓰기 계약에 따라 쓰기 가능한 원본 속성에 변경을 전달한다.
명시적인 편집 콜백을 지정하면 해당 C++ 명령이 쓰기와 거부를 결정한다.
기본 동작은 상태를 복사하거나 다른 VM을 생성하지 않는다.
전체 컴포넌트 입력과 바인딩 투영 구문은 추가 명세가 필요하다.

바인딩 접근은 가져온 VM의 소유권을 이전하지 않으며,
기존 [스코프 종료 경계](InvocationLifecycle.md)보다 수신 객체의 사용 가능 수명을 늘리지 않는다.
객체가 바인딩 가능하더라도 그 안의 읽기 전용 멤버는 계속 읽기 전용이다.

SwiftUI의 `$model.property` 투영 표기는 이번 결정에서 LVUI 구문으로 채택하지 않았다.
정확한 투영 방식과 컨트롤 입력은 추가 언어 설계가 필요하다.

<a id="observation"></a>

## 관찰

소비자는 읽은 비정적 값과 속성을 기본적으로 추적하며,
관련 변경이 발생하면 해당 의존 소비자를 무효화한다.
`@Observable`로 관찰 의도를 명시할 수 있으나 기능을 선택적으로 활성화하는 조건은 아니다.
이 어노테이션에 기본 동작 이상의 추가 동작은 채택하지 않았다.
지원하는 전체 선언 대상은 추가 명세가 필요하다.

반응형 동작은 멤버의 변경 가능 여부, C++ constness, 객체 소유권을 무시하지 않는다.
`const`는 계속 재대입할 수 없으며, 원본이 의존 뷰 갱신에 참여할 수 있더라도
읽기 전용 속성은 계속 읽기 전용이다.

LVUI 소유 값에는 읽기·변경 추적 구현이 필요하다.
가져온 C++ 값은 생성된 접근 경로나 백엔드 계약이 기본 반응형 계약에 필요한 변경 정보를 제공해야 한다.
공개 접근만으로 임의의 C++ 대입 감지를 구현할 수는 없다.
이는 값별로 관찰을 활성화하는 문제가 아닌 네이티브 연동의 책임이다.
구현 범위는 [RuntimeContracts.md](RuntimeContracts.md)를 참조한다.

<a id="static-value-lifetime"></a>

## 정적 값의 수명

`@Static`은 초기화된 값이 고정되는 수명을 설정한다.
해당 값을 변경하려는 시도는 거부해야 한다.
같은 수명 안에서는 뷰를 다시 그리거나 선언을 재평가하더라도 값을 교체할 수 없다.

채택한 보장은 해당 수명 동안의 값 안정성이다.
정확한 수명의 소유자와 길이는 미정이며, 프로세스 전역 저장소나 애플리케이션 세션 수명을 확정하지 않는다.
한 수명이 끝나면 새로운 수명에서 자체 초기값을 설정할 수 있다.

`const`는 재대입 허용 여부를 지정한다.
`@Static`은 같은 정적 수명 안에서 여러 번 평가하더라도 설정한 값이 고정됨을 추가로 지정한다.
스냅샷이나 깊은 불변성 요구사항을 포함하여,
외부에서 변경 가능한 객체를 참조하는 값의 동작은 미정이다.

<a id="core-query-integration"></a>

## Core 쿼리 연동

ViewModel은 계속 [iiSDKCore 객체 쿼리](ViewModelQueries.md)를 통해 값을 교환한다.
바인딩의 읽기·쓰기는 원본 VM의 읽기·쓰기 계약에 대응한다.
관찰은 변경 쿼리를 수신하고 읽기 계약을 통해 선택한 최신 값을 얻는다.

어노테이션은 새로운 `.lvui` 쿼리 키워드를 도입하거나 공개 멤버에 `@export`를 요구하거나,
가져온 인스턴스의 소유권을 바꾸지 않는다.
네이티브 읽기 추적과 쿼리 연결의 일부는 구현되어 있으며 적용 범위는
[네이티브 바인딩](NativeBindings.md)과 [쿼리 연결](QueryConnections.md)을 따른다.

<a id="open-questions"></a>

## 미정 사항

- 복합 View 값의 상태 소유와 교체 계약.
- 바인딩 투영·컨트롤 입력·의존성 추적 API.
- 정확한 `@Static` 수명 소유자·활성화 경계·초기화 시점.
- 정적 참조 값과 외부에서 변경 가능한 원본.
- 금지된 변경의 컴파일 타임 진단과 런타임 진단 구분.
