# LVUI 독립 표 데이터와 화면 상태

`LVUI/Table.h`는 Qt, QML, LVRS 및 호스트 위젯 없이 표의 읽기·편집 경계와
선택 상태를 제공한다. 앱은 `TableSource`로 불변 `TableSnapshot`을 제공하고
`TableEditor`로 리비전이 포함된 셀 변경 묶음을 처리한다. 두 인터페이스는 별도로
교체할 수 있다. `TableMemory`는 중간 크기의 표에 사용할 수 있는 선택적 메모리
구현이며, 편집 시 새 스냅샷을 복사한다. 큰 데이터나 영속 저장소는 앱이 별도의
소스와 편집기를 구현할 수 있다.

열과 행은 각각 고유한 UTF-8 키를 가지며 모든 행의 셀 수는 열 수와 같아야 한다.
최대 65,536행, 1,024열, 100만 셀과 64 MiB의 텍스트를 검증한다. 기본 행 높이는
24이며 18 미만이나 8192 초과는 거절한다. 열 너비 0은 유연한 크기를 뜻하며,
명시적 너비는 32 이상이다. `TableIndex`는 불변 스냅샷의 키를 빠르게 찾는다.
셀의 `value_type`은 앱에 전달되는 메타데이터다. 기본 메모리 편집기는 텍스트와
편집 가능 여부를 검증하며 숫자·날짜 파싱이나 앱별 타입 검증은 하지 않는다.

[셀 편집 세션](TableEditing.md)은 입력 초안과 원본을 분리하고 교체 가능한
편집기가 검증과 확정을 수행하도록 한다. [표 범위 클립보드](TableClipboard.md)는
복사할 문자열과 원자적 붙여넣기 요청을 플랫폼에 의존하지 않고 준비한다.
[표 행 정렬](TableSorting.md)은 계산 정책과 행 순서의 원자적 게시를 분리한다.
[표 구조 편집](TableStructure.md)은 키 기반 삽입·삭제와 크기 변경을 한 번에 검증한다.

`TableEdit`은 관찰한 리비전과 최대 4,096개의 키 기반 셀 변경을 담는다. 기본
편집기는 모든 셀을 먼저 검증하고, 중복·읽기 전용·비활성·누락 셀 또는 잘못된
텍스트가 있으면 전체 변경을 거절한다. 실제 변경이 없으면 리비전을 발행하지
않고, 성공한 묶음은 한 번만 증가시킨다. 오래된 리비전과 동시 편집은 기존
스냅샷을 보존한다. `replace()`는 구조나 크기를 포함하는 새 전체 스냅샷을 같은
리비전 규칙으로 게시한다.

`TableController`는 소유 스레드에서 단일 셀 또는 사각 범위 선택을 관리한다.
선택, 방향키 탐색, 범위 확장과 선택 해제는 문서 편집을 호출하지 않는다. 행과 열이
재정렬되어도 살아 있는 키로 선택을 유지하며 선택된 셀이 제거되거나 비활성화되면
선택을 정리한다. 범위의 경계는 현재 스냅샷의 행·열 인덱스이며 양 끝을 포함한다.
`none` 모드는 선택을 비우고 새 선택을 거절한다. 새 내용은 증가하는 고유한
스냅샷 리비전을 가진 불변 객체로 제공해야 한다.

`TableViewportSource`는 스냅샷과 표시 폭을 기준으로 행·열의 누적 위치를 한 번
만든다. 이후 양축 스크롤은 보이는 행과 열, 제한된 여유 범위만 반환한다. 셀마다
위젯을 생성하지 않으며, 가변 행 높이와 고정·유연 열 너비를 함께 계산한다.
소스 삽입 후에는 행·열 키와 내부 위치를 각각 기준으로 스크롤을 유지하고, 한 축을
사용자가 새로 움직이면 그 축의 이전 기준점만 무시한다. 특정 셀의 행과 열을
시작·끝·중앙 또는 최소 이동으로 표시할 수 있다. 표시 폭이 달라지면 열 배치를
다시 만들고 그 결과를 재사용한다.

`LVUI.OwnedTable.Model`은 모델 검증, 원자적 셀 묶음, 읽기 전용 거절, 불변
스냅샷, 오래된 요청, 키 기반 선택, 탐색, 구조 변경과 동시 편집을 검사한다.
`LVUI.OwnedTable.Viewport`는 양축 표시 범위, 삽입 후 기준점, 셀 공개, 유연 열과
1만 행 표의 제한된 행·열 계산을 검사한다. 현재 이 문서는 데이터와 배치 모델의
범위다. [독립 표 호스트](NativeOwnedTable.md)는 양축 스크롤·그리기·선택을 연결한다.
셀 편집, 범위 붙여넣기, 행 정렬과 구조 변경은 교체 가능한 편집기를 통해 연결된다. 셀 병합 및 플랫폼
접근성은 별도 구현이 필요하다.
