# 예약어·컴포넌트 프런트엔드 검증

이 문서는 앞선 프런트엔드 작업의 검증 기록이다. 이후 구현한 AOT·Cocoa 실행의
검증은 [NativeAOTVerification.md](NativeAOTVerification.md)에 별도로 기록한다.

검증일은 2026-10-22이며 실행 환경은 macOS arm64, AppleClang 21, C++23 Debug이다.

## 소스 조사 범위

저장소 전체의 코드·빌드 파일 347개도 읽고 해시를 기록했다.
모듈 코드 209개, 예제 44개, 테스트 78개, 빌드·도구 16개이며
`build/lvrs-repository-source-audit.json`에 경로와 분류를 남겼다.
예제 애플리케이션과 테스트 전용 화면 이름은 SDK 모듈의 컴포넌트 이름에 포함하지 않는다.

LVRS 커밋 `13b657b21a8ca9babe40ac790bb547c3f7758eea`의 `src/` 소스 213개 파일을
읽고 CMake 등록·QML 루트 상속·인라인 선언·C++ 등록 타입을 대조했다.
조사 선언은 149개이며 시각 선언 108개, 시각 보조 3개, 비시각 선언 38개이다.
시각 선언의 중복 이름 하나를 합쳐 `View` 예약어 107개를 등록했다.
기본 언어 예약어 6개까지 포함한 전체 예약어는 116개이다.

조사 결과와 LF 개행으로 정규화한 SHA-256은 `catalog/lvrs-components.json`,
실제 C++ 테이블은 `src/Language/Keywords.def`, 사람이 읽는 목록은 [ReservedWords.md](ReservedWords.md)에 있다.
LVRS 소스와 작업 트리는 수정하지 않았다.

## 빌드·테스트

- `cmake --build build --parallel 4`: 네이티브 라이브러리·테스트·`lvui-check` 빌드 성공.
- CTest 15개 그룹 통과: 기존 파서 4개, 컴포넌트 파서 6개, 스냅샷·실제 소스 조사·조사 도구 3개, 예제 2개.
- 107개 시각 예약어 모두를 실제 생성 구문으로 파싱하고, 전체 116개 예약어의 변수·import 이름 충돌을 검사했다.
- UTF-8·CRLF·문자열 escape·주석·자식 뷰·입력·호출과 참조·중복 입력·잘린 소스·입력 한계를 검사했다.
- 조사 도구 단위 검사 6개는 인라인·C++·비시각 분류, 문자열 오인 방지, 알 수 없는 기반 타입,
  누락된 CMake 등록, 소스 내용 변경, 중복 이름의 원본 유지와 CRLF 정규화를 검사한다.
- 실제 `lvui-check`로 12개 뷰 예제를 검사하고 예약어 충돌의 `1:5` 위치·오류 종료 1·사용법 종료 2를 확인했다.

## 설치 소비자

`build/install`에 스테이징하고, 그 설치 패키지만 참조하는 별도 C++23 소비자를
`build/reserved-word-consumer/build`에서 빌드했다. 소비자 테스트 2개가 통과했다.
설치된 헤더와 라이브러리로 107개 시각 예약어, 전체 116개 예약어, 새 `View` 트리와
기존 `Document` API를 검사하고, 설치된 `lvui-check`와 설치된 예제 파일도 실행했다.

`otool -L`에서 검사 도구와 소비자는 libc++·libSystem만 사용하며 Qt 라이브러리는 없다.
일반 `~/.local` 설치본은 교체하지 않았다.

## 증거와 구현 경계

- `build/reserved-words-ctest.txt`
- `build/reserved-words-consumer-ctest.txt`
- `build/reserved-words-verification.json`
- `build/lvrs-repository-source-audit.json`

이번 증거는 실제 어휘·구문 분석, 예약어 판정, 소유 `View` AST, 설치 패키지의 검증이다.
OS 위젯·가속 코드 생성과 iiGUI 마운트·런타임 동작 구현을 입증하지 않는다.
Windows·Linux의 빌드 또는 실행은 이번 Mac 검증에 포함하지 않았다.

## 이벤트 스크립트 제어 흐름 검증 — 2026-11-09

macOS arm64 C++23에서 파서·AOT·Python API, 기존 조건부 뷰·반복 뷰, 뷰 세션과
쿼리 연결을 포함한 관련 CTest 34개가 통과했다. 이벤트 스크립트의 `if`·`else if`·
`else`, 컬렉션 `for`, 중첩 반복의 `break`·`continue`, 재사용 스크립트의 `return`,
타입이 지정된 C++ 함수와 피연산자·인자의 평가 순서를 검사했다.

생성 C++를 iiGUI의 헤드리스 호스트에 연결하여 이벤트 전 미실행, 원본 변경에도
유지되는 스냅샷, 쿼리 요청과 조건·인자 평가 중 퇴역, 복사 중 퇴역, 복사 실패의
오류 보존 및 다음 이벤트에서의 복구를 확인했다. 제품 앱 창, GPU 표시, 다른 운영체제와
설치 소비자는 이번 변경에서 검증하지 않았다.

## 명시적 스택 배치 검증 — 2026-11-09

macOS arm64 C++23에서 파서·AOT·Python API·배치 값과 생성 C++를 연결한
헤드리스 검사를 포함한 관련 CTest 13개가 통과했다. `HStack`, `VStack`, `ZStack`의
중첩과 생성 순서, 가로·세로 좌표 및 겹친 원점을 확인했다. 표준 LVUI에서 선언하지
않은 `div`와 레거시 변환기의 `div`·`flex-direction`은 명시적인 스택을 안내하며
거부한다. 사용자가 직접 선언한 같은 이름의 View는 보존한다.

제품 앱 창, GPU 표시, 다른 운영체제와 설치 소비자는 이번 변경에서 검증하지 않았다.

## 태그 없는 이벤트 스크립트 검증 — 2026-11-09

아래는 당시의 검사 기록이다. 이름 붙인 스크립트 본문은 이후 뷰 전용 경계에서
제거했으며, 현재 계약은 [뷰 전용 아키텍처](ViewOnlyArchitecture.md)를 따른다.

macOS arm64 C++23에서 언어 파서, AOT 컴파일러, Python 브리지, 생성 C++ 검사와
뷰 세션 검사를 포함한 관련 CTest 18개가 통과했다. 별도의 `<script>` 태그 없이
이벤트 안에 쓴 상태 대입과 C++ 메서드 호출, 이름 붙인 `Void` 스크립트 호출,
애플리케이션 종료 요청의 생성과 진단을 검사했다. 반환값이 없는 함수를 화면
값으로 사용하거나 잘못된 인자 수로 호출하는 경우도 거부한다.

생성 C++를 연결한 헤드리스 검사에서는 이벤트 전에는 실행되지 않으며 대입 후의
값을 C++에서 읽는 것과, 이벤트 중 뷰가 종료되면 나머지 문장이 실행되지 않고
스코프가 해제되는 것을 확인했다. 제품 앱은 실행하지 않았고 다른 운영체제와
설치 패키지는 이번 변경 범위에서 검증하지 않았다.

## 즉시 선언형 문법 검증 — 2026-11-09

macOS arm64 C++23 Release에서 선언형 본문의 쉼표와 줄바꿈, 고정 식별자,
스택 `gap`, 아이콘 버튼 `label`, 이벤트 호출 및 명시적 콜백 팩토리를 검사했다.
언어·AOT·토큰 등 12개 검사와 기존 함수 포획·수명 등을 포함한 23개 검사가 각각
통과했다. 두 범위에는 중복 검사가 있다. 사용자 예시의 `Metric.sideBar`는 기본
카탈로그에 없으므로 별도 시험 프로파일에서 제공해 같은 구문의 AOT 생성을
검증했다.

생성 C++를 연결한 헤드리스 검사에서는 클릭 전 미호출, 클릭당 호출, 이벤트 시
최신 인자, 팩토리 의존값 변경, 재사용 뷰와 종료 후 해제를 확인했다. Python
브리지와 앱·창 수명 경로를 포함한 관련 검사 8개가 통과했다. 이전 태그 입력으로
작성된 여덟 앱 구성도 선언형으로 빌드·링크했다. 제품 앱 창, GPU 화면, 다른 OS의
실행은 확인하지 않았으며 시스템 설치본은 변경하지 않았다.

설치 패키지 전체 경계 검사 `LVUI.PackageBoundary`는 외장 저장소의 임시 설치
복사에서 기존 600초 제한에 걸려 완료하지 못했다. 같은 조건의 재시도도 600초
시간 초과였다. 제한 시간과 검사 항목은 변경하지 않았다. 현재 빌드의 Python
브리지 검사는 통과했지만, 패키지 전체 설치 검사가
성공한 것으로 해석하지 않는다.


## Alert·AlertButton AOT 추가 검증 — 2026-10-23

`Alert`과 `AlertButton`을 단순 예약어 등록에서 실제 LVRS C++ 생성 경로로 연결했다.
현재 전체 LVUI 검사 30개가 통과했으며 기록은 `build/alerts-full-tests.xml`이다.
원본 속성과 별칭 충돌, 정수 액션 개수, 금지 자식, 이미지 입력, shape와 잘못된 메서드 호출을
진단한다. 생성 코드는 C++23의 종속 `requires`로 ButtonEvent 인자 메서드와 인자 없는
메서드를 선택하고 부모 스코프 인스턴스를 재사용한다. 런타임 이름 조회를 추가하지 않는다.

원본 LVRS와 네이티브 API를 합친 소스 229개를 다시 조사했다. 선언 149개·시각 예약어
107개·시각 수정자 3개·전체 예약어 116개라는 분류는 유지한다. 새 네이티브 API 네 파일의
해시를 포함하며 기존 원본 QML 선언을 제거하거나 구현 완료로 바꾸지 않았다.
`examples/NativeAlertGallery`의 생성 헤더는 실제 C++23 앱으로 빌드되어 여섯 액션 위치와
독립 버튼, 메서드→클릭 순서, 원본 SVG, 실제 GPU 흐림과 Core 수명을 검사한다.
전체 이식 상태와 플랫폼 범위는 [LVRS 검증 기록](../../LVRS/docs/native/Verification.md)을 따른다.

## 뷰 전용 선언 경계 검증 — 2026-11-09

macOS arm64의 기존 `build/`에서 현재 소스로 코드 생성 검사 바이너리를 다시 빌드했다.
객체 리터럴과 이름 붙인 스크립트 본문 거부, C++ 객체·메서드 import, 지역 상태,
이벤트 블록, `TableColumn` 뷰, 빈 생성자와 본문 생략을 포함한 언어·세션·컴포넌트·
AOT·Python 관련 CTest 121개가 통과했다. 둘 다 비어 있는 View의 이름만 사용한 표기와
필수 입력 누락도 검사한다. 이는 전체 CTest 실행 결과가 아닌 선택한 검사 범위이다.

LVUI에서 검색된 `.lvui` 파일 294개와 제품 View 파일 12개가 파서 검사를 통과했다.
제품의 별도 스타일 프로파일은 View 파일 수에서 제외했다. Congregation의 iOS arm64
Debug 빌드는 코드 서명 없이 성공했으며, 제품의 UI 경계·스타일 검사는 창을 열지 않고
통과했다. 이 결과는 앱 실행, 실제 기기, 다른 플랫폼 또는 설치 소비자 검증이 아니다.
