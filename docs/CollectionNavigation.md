# 네이티브 가상 목록의 탐색과 선택

`CollectionNavigation`은 표시 위젯과 독립적인 C++ 뷰 상태이다. 화면 밖 항목의 키를 포함한
논리적 포커스·선택·범위 기준점을 보관한다. 생성·파일 저장·문서 편집 상태를 소유하지 않는다.
행이 퇴역해도 이 상태를 유지하므로 탐색을 위해 전체 모델의 위젯을 생성할 필요가 없다.

```lvui
import vm ResultsModel
import nav lvui.native.CollectionNavigation
Window {
    VStack {
        Label(text: nav.state.current_key)
        for (item in vm.items, key: item.id, itemHeight: 100, itemWidth: 150,
             navigation: nav, selectionMode: .multiple,
             navigationFilter: item.enabled,
             onCurrentChanged: vm.focusChanged,
             onSelectionChanged: vm.selectionChanged,
             onActivate: vm.openResult) {
            VStack {
                Label(text: item.title)
                CheckBox(checked: nav.is_selected(item.id))
            }
        }
    }
}
```

예제의 모델 메서드는 각각 `std::string`, `std::vector<std::string>`, `std::string` 인자를
받는다. 이들은 지연된 C++ 메서드 참조이며 선언 시 호출하지 않는다. 항목 데이터의 조회와
제품별 열기·비교·후보 선정 같은 동작은 해당 C++ 모델이 수행한다.

## 입력 계약

자동 모드인 `itemHeight` 반복에서 다음 입력을 사용할 수 있다.

| 입력 | 의미 |
|---|---|
| `navigation` | 안정적인 스코프의 C++ 탐색 객체 |
| `selectionMode` | `.none`, `.single`, `.multiple`; 기본 `.single` |
| `selectOnMove` | 일반 탐색 키로 이동할 때 선택도 이동; 기본 `true` |
| `selectOnClick` | 행 배경 클릭 시 선택도 변경; 기본 `true` |
| `navigationFilter` | 항목과 원래 인덱스를 사용하는 순수 C++ 탐색 가능 조건; 기본 전체 |
| `onCurrentChanged` | 현재 키 변경 알림 |
| `onSelectionChanged` | 선택한 키 목록 변경 알림 |
| `onActivate` | 현재 항목 활성화 명령 |

객체는 `import`로 소유하거나 상위 스코프에서 안정적으로 차용한다. 교체될 수 있는 행
데이터 내부의 탐색 객체를 고정 포인터로 보관하지 않도록 컴파일러가 그러한 입력을 거부한다.
사용자 C++ 객체도 같은 상태·명령 인터페이스를 구현하면 어댑터에 연결할 수 있다.

`selectOnMove: false`이면 일반 방향키는 포커스만 옮긴다. 명시적인 Shift 범위나 Space
선택은 계속 가능하다. `.none`은 선택 없이 포커스만 관리한다. 모드 변경도 네이티브
바인딩으로 전달하며 새 탐색 객체를 만들지 않는다.

`selectOnClick: false`이면 보조키 없는 행 클릭은 포커스만 옮긴다. Cmd/Ctrl 클릭의
개별 선택 전환과 Shift 클릭의 범위 선택은 계속 사용할 수 있다. 이 동작은 입력 필드나
버튼처럼 행 안에 있는 대화형 컨트롤의 원래 입력을 대체하지 않는다.

C++ 탐색 설정의 `anchor_on_unselected_focus`는 기본적으로 `false`이다. 이를 `true`로
설정하면 선택을 변경하지 않는 일반 포커스 이동도 다음 Shift 범위의 기준점을 바꾼다.
포커스·기준점 변경은 하나의 상태 알림으로 전달되고 기존 선택은 유지된다. 자체 탐색
스코프에서 이를 사용할 때는 위젯이 `configure`를 호출할 때도 설정을 보존해야 한다.

## 키와 포인터

- 좌우는 이전·다음 항목, 세로 그리드의 상하는 한 줄의 열 수만큼 이동한다.
- Home·End는 첫·끝의 탐색 가능 항목으로 이동한다. 경계를 넘어서 순환하지 않는다.
- Page Up·Down은 현재 표시 영역의 행 수에 따른 페이지 단위로 이동한다.
- Shift는 기준점부터의 범위를 선택한다. Ctrl/Cmd를 함께 사용하면 기존 선택에 더한다.
- Ctrl/Cmd 방향키는 기존 선택을 유지하며 포커스만 이동한다.
- Space는 현재 키의 선택을 전환하고 Enter는 활성화 명령을 보낸다.
- Ctrl/Cmd+A는 현재 투영의 탐색 가능 항목을 선택한다. 필터로 숨긴 기존 선택은 유지한다.
- 목록의 Escape 범위는 선택을 해제한다. 텍스트·조정 컨트롤의 키 조작은 가로채지 않는다.
- 행의 비대화형 배경 클릭은 키를 찾아 포커스·선택을 변경한다. 내부 버튼·입력 컨트롤의
  클릭과 활성화는 해당 컨트롤이 계속 처리한다.

필터 조건은 UI 입력 중 평가하므로 모델·탐색 상태를 변경하지 않는 순수 읽기이어야 한다.
사용자가 필터로 제외한 항목은 방향 이동·범위·전체 선택에서 건너뛴다. 제품별 문자 단축키는
여기에 하드코딩하지 않으며 기존 C++ 이벤트 경로에 연결한다.

## 입력 경계와 포커스

iiGUI는 콘텐츠 세대 안쪽으로 전달하기 전에 상위 입력 처리기에 키를 전달할 수 있다.
`WidgetInput`의 `text_input_active`, `native_control_active`, `native_navigation_active`는
중첩된 실제 포커스까지 확인한다. 텍스트 편집, 슬라이더·스테퍼·콤보박스·색상 조정과
탭·메뉴의 자체 탐색을 목록 방향키로 대체하지 않는다. 버튼 내부에서 방향 이동을 시작하면
그 버튼이 속한 논리 행을 기준으로 이동하되 Enter는 원래 버튼 동작으로 남긴다.

키 이동은 키 기반 공개 요청을 `VirtualViewport`에 전달한다. 창의 실제 너비·높이가
들어오기 전에는 요청을 완료했다고 처리하지 않는다. 모델에서 목표 키를 찾은 뒤 필요한
표시 범위를 만들고, 해당 행이 보이도록 오프셋을 보정한다. 사용자의 새 스크롤은 이전
프로그램 요청보다 우선한다. C++의 `nav.set_current(key)`도 같은 경로를 사용한다.

## 상태와 수명

공개 읽기 소스 `nav.state`는 `current_key`, `anchor_key`, 정렬된 `selected_keys`를
제공한다. 쓰기는 탐색 객체의 메서드로 수행한다. 선택은 필터에 없는 키도 유지한다.
모델에서 영구 삭제한 키의 정리는 제품의 선택 수명 정책에 따라 수행한다.

`nav.set_state(snapshot)`은 제품 모델이 소유한 포커스·범위 기준점·선택을 한 번에
복원한다. 현재 보이는 행에 없는 키도 허용하므로 필터로 숨긴 선택이 유지된다.
키는 일반 컬렉션과 같은 UTF-8·길이 규칙으로 검증하고, 선택 키를 정렬하여 중복을
제거한다. 설정된 선택 모드와 맞지 않는 선택이나 잘못된 키는 전체 요청을 거부하며
이전 상태와 변경 세대를 유지한다. 변경이 있을 때만 한 번 관찰자를 호출한다.
호출자는 실제 결과가 영구 삭제되면 자신의 모델 정책에 따라 키를 제거한 스냅샷을
전달해야 한다. 이 메서드는 파일·문서의 복원이나 영속화를 수행하지 않는다.

행은 기존처럼 가시 범위에서만 활성화한다. UI 어댑터는 적용된 프레임과 원본 모델
스냅샷을 함께 보관하여 범위 밖의 재정렬도 다음 명령에 반영한다. 알림과 입력은 닫힌
스코프의 접수를 확인하며, 실행 중에는 스코프를 잠시 보유해 콜백 중 종료에도 객체가
미리 파괴되지 않게 한다. 활성화가 끝나면 관찰과 프레임을 해제한다. 차용한 탐색 객체를
자식 뷰 퇴역 때문에 임의로 닫지 않는다.

코어 모델은 `NativeCollectionNavigation.h`와 iiSDKCore 계약에만 의존한다. 선택적
`NativeCollectionWidgets.h` 어댑터와 생성된 뷰는 iiGUI 헤더·호스트를 사용한다.
`LVUI::Native`의 코어 탐색 소비자에 iiGUI나 Qt 의존성을 강제하지 않는다.

## 검증 범위

`LVUI.NativeCollectionNavigation.*`와 `LVUI.NativeVirtualCollection.reveal`은 논리 탐색·
선택·필터·상태 수명·공개 요청을 검사한다. `iiGUI.ancestor_input.*`는 중첩 키의 전달과
텍스트·조정 입력 보존을, `iiGUI.native_navigated_repetition.*`는 실제 생성 C++의 화면 밖
이동·선택·C++ 알림·초기 포커스·포인터·콜백 중 퇴역을 검사한다. 실제 OS 창·접근성·IME·
플랫폼의 전체 동작과 [전체 완료 기준](Completion.md)은 별도의 검증 대상이다.

가변 높이와 조건부 행을 결합한 생성 뷰에서는 측정 피드백 이후에도 공개한 키가 보이는지
검사한다. 현재 표시 항목을 유지한 채 범위 밖에서만 모델 순서가 바뀌는 경우에도 새 원본
스냅샷을 다음 키 명령에 사용한다. 재배치 때문에 기존 가시 행을 다시 만들지는 않는다.

1,000개 중 끝 항목으로 이동하여 필요한 행만 활성화하는지, 비활성 항목을 건너뛰고
범위·추가 선택을 유지하는지 검사했다. 초기 C++ 포커스·필터로 숨긴 선택·화면 밖 재정렬·
실제 입력 컨트롤의 키 보존·가변 높이 측정과 조건부 행의 결합·콜백 중 종료도 검사했다.
선택은 생성·파일 상태와 분리한 뷰 상태이며, 탐색 중 원본 모델·파일 리비전이 바뀌지 않는
검사가 포함된다. 제품별 알림을 연결한 메서드의 변경 발행은 해당 메서드 계약을 따른다.

검사한 `lvui-compile`과 탐색 위젯 검사 실행 파일은 Qt 동적 의존성이 없다. 후자에는
LVUI 파서·컴파일러 실행 심볼이 없다. Dreamscapes 관측 기준선의 QML 81개 파일은
변경하지 않았다. 이 결과는 실제 제품 프레임 지연이나 모든 플랫폼의 완료를 의미하지
않는다. 원시 로그·소스 해시·범위는
`build/lvui-completion/collection-navigation-verification-20261026.json`에 기록한다.
