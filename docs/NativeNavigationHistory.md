# LVUI 탐색 이력과 변경 후보

`NavigationHistory`는 LVUI가 직접 소유하는 C++ 이력 모델이다. Qt·QML·LVRS와
위젯 호스트를 참조하지 않는다. 각 `NavigationEntry`는 정규화된 경로, 타입을
보존하는 `ii::core::Value` 매개변수, 선택적인 `NavigationPage` 객체와 활성
상태를 담는다. 페이지 객체를 직접 전달하고 경로를 생략하면 빈 경로를 보존한다.
null 매개변수는 빈 객체로 정규화한다.

`prepare`는 push, replace, set_root, pop, pop_to_root, clear의 입력·예산을
확인하고 불변 `NavigationPlan`을 반환한다. 이때 이력은 바뀌지 않는다. 페이지
호스트는 후보의 `destination()`으로 새 뷰를 준비한 다음 성공한 경우에만 `commit`을
호출할 수 있다. 같은 이력의 revision이 변경된 뒤 오래된 후보를 적용하면 `busy`,
다른 이력에 속한 후보를 적용하면 `invalid_argument`이다. 유효한 무동작은 false를
반환하고 revision을 바꾸지 않는다. pop은 마지막 루트를 제거하지 않는다.
`destination()`의 포인터는 같은 후보 스냅샷을 소유하는 계획 객체가 살아 있는 동안
유효하다. 그보다 오래 보관해야 하는 앱은 항목을 값으로 복사한다.

이력은 최대 65536개 항목, 항목당 계산 예산 2 MiB, 전체 계산 예산 16 MiB이다.
매개변수는 링크와 같은 4096개 노드·깊이 64·문자열 및 바이트 1 MiB 한도를
따른다. 계산 예산에는 경로·값의 크기와 노드별 고정 비용을 포함하지만 외부 페이지
객체, 보유 중인 후보 사본이나 allocator의 실제 메타데이터까지 포함하지 않는다.
예산 초과나 잘못된 후보는 기존 이력을 보존한다. `state()`는 현재 항목과 revision,
깊이·계산 예산만 복사하고 `entries()`는 명시적으로 전체 이력 사본을 만든다.

변경과 조회는 이력을 만든 스레드에서만 허용한다. 항목 제거·교체 중 객체 소멸자가
이력에 재진입하면 부분 상태를 노출하지 않고 `busy`로 거절한다. 외부 페이지 객체가
별도로 일으킨 부수 효과를 되돌린다는 뜻은 아니다.

이 모델은 화면을 게시하거나 탐색 이벤트를 자동으로 발생시키지 않는다. 독립
[페이지 라우터](NativePageRouter.md)는 후보 뷰의 생성과 이력 확정, 호스트 게시를 연결한다.
경로 패턴은 [경로 계약](NativeRoutes.md), 앱이 주입하는 탐색 경계는
[링크 계약](NativeLinks.md)을 따른다.
