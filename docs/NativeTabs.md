# LVUI 독립 탭 전환

`iiGUI/TabModel.h`가 탭과 탭 묶음의 상태·배치 모델을 소유한다. 탭은 텍스트·아이콘·배지의
배치, 선택된 밑줄 또는 표면, 비활성·호버·눌림·포커스 상태를 정의한다. 기본
아이콘 크기는 18, 높이는 32, 좌우 여백은 12, 콘텐츠 간격은 8이다. 레거시 디자인
값을 참고하여 새로 작성했으며 레거시 실행 코드나 타입에 의존하지 않는다.

탭 묶음 모델은 선택과 키보드 포커스 이동을 구분한다. 다음·이전 이동은 비활성
항목을 건너뛰고 양 끝을 순환하며 처음·마지막 이동도 가능한 항목을 찾는다.
자동 선택이 꺼져 있으면 활성화해도 인덱스를 변경하지 않는다. 동일 너비 계산은
최소 폭과 간격을 고려하고 잘못된 설정과 4096개 초과 항목은 거절한다.

`iiGUI/NativeTabView.h`의 탭 호스트는 이름 기반 아이콘과 범용 액션 표면·텍스트 측정을
연결하며 잘못된 입력은 이전 탭을 유지한다. 공급자 호출 중 새 설정이 들어오면
오래된 후보가 덮지 않는다. 기본 선언형 `Tab`은 이 어댑터를 사용한다. 이름,
공급자 및 반응형 revision은 [독립 아이콘 계약](NativeIcons.md)을 따른다.

`iiGUI/NativeTabBarView.h`의 탭 막대는 직접 등록한 자식의 임시 선택 상태와 동일 폭을 조정하고, 좌우·
Home·End 키로 비활성 항목을 건너뛰어 포커스를 이동한다. 포커스 이동은 선택하지
않으며 활성화가 선택을 변경한다. 자동 선택 중 선택된 탭이 숨겨지거나 비활성화되면 사용 가능한
첫 탭으로 선택을 옮기고 변경을 알린다. 상위 컨테이너만 숨겨지거나 비활성화된
경우에는 자식이 직접 지정한 선택 가능 상태를 유지한다. 부모 설정은 자식의 원래 선택 값을 덮지 않고,
부모가 선택을 관리하지 않으면 최신 원래 값을 복원한다. 실패한 자식 갱신은 이전
설정으로 되돌리며 비동기 레이아웃·활성화 오류는 `status()`로 확인한다. 기본
선언형 `TabBar`는 직접 자식뿐 아니라 정적인 재사용 `View`와 `[View]` 슬롯을
통해 전달한 `Tab`도 연결한다. 슬롯의 실제 자식 타입을 검사하며, 중첩 스코프는
상위 탭 묶음의 약한 등록 포트를 빌려 선택·콜백·반응형 입력을 유지한다.
조건부와 키 기반 반복으로 탭을 생성할 수도 있다. 분기 또는 반복 행에는 탭
하나나 여러 탭으로 확장되는 재사용 `View`·`[View]`를 배치할 수 있으며, 이 묶음
안의 조건과 반복을 중첩할 수 있다. 반복 자체는 부모의 가로 방향과 간격을 따르고
`id`, `first`, `count`만 별도로 받는다. 각 조건 분기에는 지역 import·값·View를
선언할 수 있으며, 탭이 아닌 항목은 컴파일 시 거절한다. 분기 수명은
[조건부 View](ConditionalViews.md)를 따른다.

```lvui
import vm TabsModel
Window {
    TabBar(currentIndex: vm.index, onCurrentIndexChanged: vm.changed) {
        Tab(text: "Canvas", iconName: "home")
        if (vm.showLayers) { Tab(text: "Layers", iconName: "home") }
        for (item in vm.documents, key: item.id) {
            Tab(text: item.title, iconName: "home")
        }
    }
}
```

동적 섹션은 선언 순서를 지키며 재정렬된 키의 위젯과 선택을 유지한다. 자동 선택 중
선택한 탭의 인덱스가 달라지면 콜백에 새 인덱스를 전달하며, 선택한 탭이 사라지면 사용 가능한
첫 탭을 고른다. 비어 있던 묶음에 처음 탭이 들어온 경우에도 자동 선택이 켜져 있으면
첫 탭을 고른다. 후보가 잘못되거나 자식 표시·등록 또는 선택 콜백이 실패하면 가능한
한 이전 콘텐츠와 선택으로 되돌린다. 후속 변경이 콜백에서 재진입한 경우 더 새로운
설정을 덮지 않는다. 공통 `SectionCapture`와 `SectionRepeatedRows`는 메뉴와 탭에서
후보를 모아 게시하고 섹션 퇴역 뒤에는 갱신을 거절한다. 그룹 타입은 전달된 항목에서
결정하므로 이 조합 계약 자체는 iiGUI에 직접 의존하지 않는다.

반응형
`currentIndex`를 쓰는 앱은 선택 콜백에서 해당 모델 값을 갱신해 나중의 다른
입력 변경에도 선택을 유지해야 한다.
중첩 탭의 반응형 오류는 [최상위 바인딩 진단](NativeBindings.md)에서도 확인할 수 있다.
범용 호스트에는 탭 그룹과 탭 역할 및 선택 상태를 전달한다. 그룹의 `accessibilityName`을
명시할 수 있다. macOS의 탭 그룹·버튼 접근성 역할과 iOS의 선택 특성은 코드에서
연결되며 실제 보조 기술을 통한 플랫폼 실행 검증은 별도로 남아 있다.

`LVUI.OwnedTabBar.SlotsGenerated`는 정적 `[View]` 슬롯과 중첩 컴포넌트가 생성한
실제 C++를 창 없는 위젯 트리에 연결하여 등록·선택·콜백·반응형 텍스트·퇴역을
검사한다. `LVUI.OwnedTabBar.Sections`는 조건부 교체·키 재정렬·빈 묶음·선택·
방향키·가려진 항목·실패 복구를, `LVUI.OwnedTabBar.Dynamic`은 조건과 반복이
중첩된 선언의 생성 코드·반응형 갱신·접근성 소속을 창 없이 확인한다. 실제 창이나
기기의 시각·접근성 검증은 아니다.
`LVUI.OwnedMenu.Conditional`은 탭 분기의 지역 백엔드와 재사용 View가 생성·갱신·
퇴역하는 경우도 같은 헤드리스 위젯 트리에서 확인한다.

LVUI의 `TabBinding`은 디자인 값과 아이콘 원천을 전달하며 iiSDKCore 외 SDK를 직접 참조하지 않는다. 생성된 앱이 iiGUI 호스트를 조합한다. 동일한 입력과 원천 리비전은 아이콘을 다시 읽지 않고, 더 늦은 요청이 먼저 조회하던 결과를 무효화한다. 퇴역하면 아이콘 원천과 콜백을 해제한다. 탭 막대 호스트도 iiGUI가 소유하며 LVUI는 `TabBarBinding`과 독립 포트 계약을 제공한다. macOS arm64에서 탭·탭 막대의 선택·동적 섹션·생성 코드와 격리된 소비자를 창 없이 검사했다.

탭 막대가 선택 콜백 중 폐기되면 진행 중인 호출이 끝난 뒤 자식 포트와 콜백을 해제한다. macOS arm64에서 동적 섹션·슬롯·선택·포커스와 독립 설치 소비자를 창 없이 검사했다.
