# LVUI 독립 툴팁 모델

`LVUI/Tooltip.h`는 툴팁 값과 독립 바인딩을 제공한다. 배치·시간 상태는
`iiGUI/TooltipModel.h`, 교체 가능한 표시·예약 포트의 제어는
`iiGUI/TooltipController.h`가 소유한다. 앱이 두 계약을 조합하며 시스템 시계나
Qt, QML, LVRS에 의존하지 않는다.

`layout`은 가용 영역, 앵커와 측정된 콘텐츠 크기를 받는다. 기본 최대 크기는
320×320, 콘텐츠 여백 12, 화면 가장자리 여백 8, 반경 12, 꼬리 길이 10,
꼬리 폭 16 논리 px이다. 선호 방향에 완전히 들어가는 배치를 먼저 선택하고,
들어가지 않으면 다른 방향을 살핀다. 모두 잘려야 하면 표시 면적이 가장 큰
후보를 사용한다. 결과는 본문·전체 프레임·꼬리 끝과 양 끝점·반경이며, 본문은
가용 영역의 내부 여백을 벗어나지 않는다. 기본적으로 앵커도 그 영역 안에 있어야
하지만 별도의 앵커 허용 영역을 지정하면 대상이 본문 영역 밖에 있어도 배치할 수 있다.
앵커가 허용 영역 밖이거나 유효한 본문 공간이 없으면 결과가 없다. 측정과 그리기는
호스트 책임이다.

`iiGUI/TooltipOutline.h`는 배치 결과의 본문과 꼬리를 하나의 검증된 SVG 경로 데이터로
변환한다. 값과 방향이 일치하지 않는 윤곽은 거절한다. 경로를 실제로 래스터화하거나
플랫폼에 그리는 작업은 교체 가능한 호스트가 담당한다.

`iiGUI/NativeTooltipPresentationView.h`의 `BasicNativeTooltipPresentation`은 앱이 주입한 재질과
윤곽을 범용 팝업에 연결한다. LVUI는 표시 값과 바인딩 계약만 제공한다. 앱은 `content_root()`에 유지할 콘텐츠를 구성하고 예약 함수를
주입한다. 본문만 입력을 받고 꼬리는 입력을 통과시킨다. 생성 중인 세대는 표시할 수
없으며 퇴역 시 예약을 취소하고 캡처된 예약 함수와 재질 자원을 해제한다. 콘텐츠는 별도 스크롤 뷰포트 안에서 고유 크기를
유지하므로 텍스트가 바뀌면 다시 측정해 팝업 크기를 갱신할 수 있다. 기본적으로 본문이
뷰포트보다 길면 세로로 스크롤하고 표시기를 그린다. 휠·트랙패드와 호스트가 전달하는
터치 스크롤 입력을 사용하며, 내용이나 영역이 줄어들면 오프셋을 유효 범위로 제한한다.
`TooltipPresentationStyleValue<Motion>::scroll_content=false`는 콘텐츠를 뷰포트 높이로 클리핑하고
오프셋을 0으로 되돌린다. 다시 켤 때 이전 오프셋은 복원하지 않는다. 전환 중 콘텐츠와
위젯 상태는 유지한다. 툴팁이 숨겨진 상태에서 설정을 꺼도 오프셋을 초기화하며,
이 초기화는 다른 위젯의 현재 포인터 호버를 지우지 않는다. 터치 관성과 표시기 직접
드래그는 iiGUI의 별도 미구현 범위다.
C++ 표시 포트의 `set_style`은 기존 콘텐츠를 유지하면서
재질을 갱신하며 유효하지 않은 스타일을 거절한다. 게시 전 스타일 갱신은 후보에만
저장하며 실제 팝업을 열지 않는다.
부분 변경 복구가 실패하면 표시 포트는 복구 필요 상태를 보고한다.

진입 시 크기는 0.94에서 1까지 OutBack으로
`animationDuration` 동안 변하고 불투명도는 0에서 1까지 그 시간과 160ms 중 짧은
시간 동안 변한다. 퇴장 시 현재 크기를 유지하고 불투명도는 그 시간과 150ms 중 짧은
시간 동안 0으로 변한다. `motionEnabled=false`, 지속 시간 0 또는 공유 모션 설정의
비활성화·축소 모션은 즉시 완료한다. 진행 중 닫기와 재열기는 현재 표시값에서
이어지며 논리적 닫기와 입력 차단은 즉시 수행한다. 시간과 스타일의 반응형 변경이
실패하면 이전에 확정된 값으로 복구한다. 프레임 공급자가 없는 헤드리스 호스트는
즉시 표시하며, 그 외 프레임 예약 실패는 조용히 무시하지 않는다. `motion`은 선택적
`std::shared_ptr<ii::gui::MotionPreferences>`이고 생략하면 호스트의 공유 설정을
사용한다. 이 설정의 속도와 축소 모션 변경은 두 트랙에 함께 반영된다. 모션을
표시하는 픽셀은 닫힘 이후에도 퇴장 전환이 완료될 때까지 유지될 수 있다.

자동 표시 상태는 대상의 사용 가능 여부와 hover·press·focus를 합친 활성 값,
표시된 풍선의 hover 값을 입력받는다. `advance`에는 감소하지 않는 0 이상의
정수 밀리초를 전달한다. 표시 지연의 기본은 500ms, timeout은 5000ms,
숨김 지연은 120ms이고 애니메이션 시간 값은 420ms이다. timeout 0은 시간 제한이
없다는 뜻이다. 값 모델은 애니메이션 시간을 저장하고 독립 네이티브 표시 포트가
이를 화면 전환에 사용한다.
지연 중 조건이 없어지면 대기 요청을 취소한다.
시간 초과 또는 명시적 닫기 뒤 대상이 계속 활성 상태면 비활성화될 때까지
자동으로 다시 열지 않는다. 대상이 사라지면 표시를 즉시 종료한다.

`open`·`close`는 수동 제어이고 `next_deadline`은 호스트가 깨워야 할 다음
시각을 반환한다. 수동으로 연 툴팁은 자동 hover 종료를 적용하지 않지만 timeout과
대상 소실은 적용한다. 대상이 없는 수동 툴팁은 `target_present=false`를 전달한다.
옵션을 바꾸면 진행 중인 지연은 최초 시작 시각과 새 시간 값으로 다시 계산한다.
잘못된 크기·방향·시간과 역행하는 시각은 거부하며 이전 상태를 유지한다.
값 모델의 시간 값은 오버플로 방지를 위해 최대 정수에서 하루를 뺀 값 이하로
제한한다. 네이티브 표시 포트의 애니메이션 시간은 24시간 이하로 제한한다.

`BasicTooltipController`는 주입된 모델을 교체 가능한 `TooltipPresentationPort`에 연결한다.
포트는 표시 레이아웃과 다음 기한을 각각 반영하며 실패 시 해당 호출 전의 상태를
유지하거나 `needs_reconciliation`으로 부분 변경을 알려야 한다. 포트 호출은 소유 스레드에서 동기적으로 끝나야 하고 예약된 알림은
컨트롤러의 갱신 호출이 끝난 뒤 전달해야 한다. 포트 호출 중 같은 컨트롤러를 다시 변경하면 `busy`를
반환한다. 표시가 거절되면 앞서 바꾼 기한을 되돌리고 모델을 확정하지 않는다.
기한 복구까지 실패하면 오류를 반환하며 호스트의 예약 상태는 불확실하다.
이 경우 일반 갱신을 거절하고 `snapshot`에 복구 필요 상태를 표시한다. 앱이
`reconcile`을 호출해 마지막 확정 표시와 기한을 다시 적용하거나 `retire`로
표시와 예약을 모두 해제할 수 있다. 포트의 같은 값 재적용은 멱등이어야 한다.

`weak_tick`은 컨트롤러를 보유하지 않는 시간 알림 함수이다. 늦은 알림은 현재 상태를
다시 계산하며 퇴역했거나 소유자가 사라진 경우 거절된다. 표시·닫힘 콜백은 상태가
확정된 뒤 호출하므로 다시 변경할 수 있다. 콜백 예외는 원인을 보존한 오류로
반환하며 이미 확정된 표시나 외부 부수 효과는 되돌리지 않는다. `retire`는 표시와
기한을 해제하고 이후 호출을 차단한다.

`iiGUI/TooltipScheduler.h`의 `TooltipScheduler`는 선택적인 iiSDKCore 이벤트 루프 연결이다. 하나의 기한만
유지하며 새 예약이 수락된 다음 이전 예약을 취소한다. 큐가 가득 차 새 예약이
거절되면 기존 예약을 보존한다. 수신자는 약한 참조로 연결하고, 이전 예약의 늦은
알림과 퇴역 후 알림은 무시한다. 이벤트 루프는 소유 UI 스레드에서 실행해야 하며,
다른 스레드에서의 전달과 콜백 오류는 `last_failure`로 확인할 수 있다.
기한이 살아 있는 동안 수신자를 교체하려면 먼저 예약을 취소해야 한다.
알림 처리 중 다음 기한을 예약할 때도 이벤트 루프에 빈 슬롯이 필요하며, 없으면
예약 실패를 호출자에게 전달한다.
앱은 스케줄러를 소유하고 `weak_schedule`을 표시 어댑터에, 컨트롤러의 `weak_tick`을
스케줄러에 연결한다. 컨트롤러에 직접 전달하는 시각도 같은 스케줄러의 `elapsed`를
기준으로 해야 한다. 스케줄러가 먼저 사라지면 약한 예약 접점은 `closed`를 반환한다.

`iiGUI/NativeTooltipTargetView.h`의 `BasicNativeTooltipTarget`은 대상과 팝업의 포인터·포커스·가용 상태를 범용 위젯
관찰 포트로 구독한다. 입력 핸들러를 교체하지 않으며 다른 위젯 도메인의 대상을
거절한다. 대상 좌표와 측정된 콘텐츠로 배치를 갱신하고 퇴역한 대상의 알림을
무시한다. 대상 결합을 사용할 때는 컨트롤러 대신 대상 결합의 `weak_tick`을
스케줄러에 연결하고, 수동 표시는 결합의 `open`·`close`를 사용한다. 콘텐츠가
바뀐 직후 앱은 `refresh`로 크기를 즉시 다시 측정할 수 있다.
컨트롤러는 같은 표시 포트를 사용해야 하며, 앱은 결합과 포트에 같은 스케줄러를
전달한다. 관찰 또는 열림·닫힘 콜백 중 대상이 바뀌면 마지막 요청을 보류했다가
처리한다. 보류 요청이 실패해도 현재 대상의 비활성화·퇴역은 계속 처리한다. 다른
스레드에서 관찰 값이 도착하면 UI 상태를 바꾸지 않고 `last_failure`에 보고한다.
표시 중 콘텐츠의 측정 크기가 변하면 내부 측정 핸들러가 배치를 다시 계산한다.
이 핸들러는 콘텐츠 루트에서 어댑터가 소유하며, 앱은 그 아래 자식을 구성한다.

`iiGUI/NativeTooltipView.h`의 `BasicNativeTooltip`은 앱의 위젯 빌더에서 Core 이벤트 루프를 얻어 표시 포트,
스케줄러, 컨트롤러와 대상 관찰을 함께 구성한다. 앱은 `content_root` 아래에
콘텐츠를 작성하고 `set_target`으로 대상을 지정한다. 수동 표시와 해제는
`open`, `close`를 사용하며 내용 크기가 변경되면 `refresh`로 다시 측정한다.
대상을 비운 수동 툴팁의 앵커는 표면 좌표이며 기본값은 `(0, 0)`이다. 대상이 있으면
앵커는 그 위젯의 로컬 좌표이고 생략 시 중앙이다. 본문 가용 영역은 표면과 교차해
제한하며, 대상의 앵커는 그 본문 영역 밖에 있어도 대상의 클립과 표면 안이면 된다.
대상이 없을 때는 앵커가 가용 영역 안이어야 한다. 표시 중 영역이 더 이상 유효하지
않으면 툴팁을 닫는다. 물리 화면 경계와 운영체제 안전 영역의 자동 관찰은 별도다.
모델과 표시 스타일의 콘텐츠 패딩은 같아야 한다. 이벤트 루프가 없는 호스트는
생성을 거절하며, 빌더의 콘텐츠가 퇴역하면 관찰과 예약도 더 이상 유효하지 않다.
표시 스타일을 직접 바꾸는 경우 모델의 콘텐츠 패딩도 함께 갱신해야 한다.

`BasicNativeTooltip::options()`와 `set_options()`는 모델 설정, 표시 스타일 및 대상 로컬
앵커·가용 영역을 `TooltipInputValue<Motion>` 하나로 읽고 바꾼다. 모델과 표시의 콘텐츠 패딩은
같아야 하며 범위를 벗어나거나 유한하지 않은 설정은 기존 상태를 바꾸지 않는다.
열린 콘텐츠와 대상은 설정 변경 중 유지한다. 예약이 거절되는 등 설정 확정에 실패하면
이전 모델과 표시 스타일 및 유효한 스크롤 위치로 되돌린다. 복구가 불확실해진 경우 `reconcile()`로 마지막
확정 상태를 호스트에 다시 적용한다. 게시 전 설정도 바꿀 수 있으며 실제 표시는
게시 후에만 허용한다.

열림·닫힘 및 대상 관찰 콜백 안의 설정 변경은 관찰이 끝날 때까지 보류해 마지막 값을
적용한다. 이 보류 갱신의 실패는 `last_failure()`와 읽기 전용 `diagnostic_source()`에
표시하며, 선언형 뷰는 이를 활성화의 `binding_failures()`에 포함한다. 실패한 보류
설정은 이후 관찰 또는 `refresh()`에서 다시 시도하고, 더 새 설정이 오면 이를 우선한다.
설정 자체가 확정된 뒤 호스트 재측정이나 콜백이 실패할 수도 있으므로 해당 오류가
발생했다고 이미 실행된 콜백의 외부 효과까지 되돌렸다고 가정해서는 안 된다.

기본 선언형 `Tooltip`은 이 독립 구성을 사용한다. 같은 구성 스코프의 정적 `targetId`
또는 백엔드의 `ii::gui::Widget`을 받는 `target` 중 하나를 사용한다. `target`은 관측
가능한 위젯으로 교체·해제할 수 있고, 다른 위젯 도메인의 대상은 거절한다. 해제할
때는 기본 생성한 `ii::gui::Widget{}`을 전달한다. `availableRect`는 백엔드의
`ii::gui::Rect`, `lvui::TooltipRect` 또는 이들의 `std::optional`을 받으며 관측할 수
있다. 빈 optional은 기본 표면 영역을 사용한다. 배치·크기·앵커·시간·자동 표시·재질·
접근성 이름과 표시 콜백도 사용할 수 있다. 색상은 다른 LVUI 색상 입력과 같은 방식으로
제공한다. 시간은 0부터 86400000까지의 정수 밀리초이며 잘못된 반응형 값은 바인딩
오류로 보고하고 이전 설정을 유지한다.
`text`는 자동 라벨로 구성하며
반응형으로 갱신하고, 직접 작성한 콘텐츠를 대신 사용할 수도 있다. 현재는 두
콘텐츠 방식을 동시에 지정할 수 없다. `scrollContent`는 기본 `true`이며 상수 또는
관측 가능한 Bool을 받아 열린 툴팁의 스크롤을 바꿀 수 있다. `motionEnabled`와
`animationDuration`도 상수 또는 관측 가능한 값을 받는다. `motion`은 관측 가능한
네이티브 공유 설정 포인터를 받는다. 앱 호스트에 Core 이벤트 루프가 필요하다.

실제 플랫폼 표시·접근성 검증과 나머지 선언형 입력이 남아 있다. 제거된 기존 경로는
[과거 툴팁 생성 기록](NativeTooltip.md)에 설명한다.

LVUI의 툴팁 값·포트·바인딩은 iiSDKCore 외 SDK를 직접 참조하지 않는다. 앱이 iiGUI 구현과 이를 명시적으로 조합하며 AOT 생성 코드도 같은 방식을 쓴다. 명시적으로 퇴역한 제어기는 표시 포트와 콜백을 해제한다. macOS arm64 독립 설치 소비자와 LVUI 모델·윤곽·표시·예약·대상 관찰·생성 경로를 창 없이 검사했다.
