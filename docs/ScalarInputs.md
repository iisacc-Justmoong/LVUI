# 네이티브 스칼라 구성 입력

타입 매개변수가 있는 재사용 View의 동적 스칼라 입력은 활성화에 속한 하나의 값이다.
QML 객체·스크립트·문자열 식 평가기를 만들지 않고 AOT로 생성한 C++23과
`LVUI::Native`의 의존성 그래프를 사용한다. 기존 앱 Runtime·서비스·파일 모델을 새로
생성하는 기능이 아니다.

```lvui
import vm Model
let Heading(title: String, subtitle: String = title): View = VStack {
    Label(text: title)
    Label(text: title)
    Label(text: subtitle)
    @Static let initial: String = title
    Label(text: initial)
}
Window { Heading(title: vm.compute(vm.count)) }
```

`compute()`의 결과를 활성화별 `ReadOnlyValue<std::string>`에 보관한다. 최초 실제
활성화에서 한 번 평가하며, 의존 원본 변경이 있으면 네이티브 그래프가 다시 평가한다.
위젯 생성·표시·스냅샷 조회는 이미 계산한 입력을 읽는다. 위젯 수만큼 메서드를 호출하지
않으며 파일 revision을 발행하거나 다른 ViewModel을 복사하지 않는다. 동일한 구성을
두 번 활성화한 경우의 두 입력은 독립적이다. 외부 원본의 여러 변경은 기존
[배치·의존성 갱신 계약](NativeBindings.md)을 따른다.

## 타입·포획·기본값

- `String`, `Bool`, `Int`, `Float`, `Double`, `Metric`, `Color`를 정규화한 읽기 전용
  입력으로 보관한다. 문자열은 소유하는 값이며 `Color`는 공유 색상 계약을 사용한다.
- 상수 인자는 빌드 시 결정하는 기존 경로를 유지한다. 동적 입력을 창의 정적 생성
  옵션으로 암묵적으로 변환하지 않는다.
- 명시한 식은 모든 매개변수 이름을 연결하기 전에 호출자 환경에서 포획한다. 앞선
  매개변수나 자식의 import가 같은 이름을 사용해도 원래 C++ 수신자를 유지한다.
- 기본값은 정의 환경과 앞서 연결한 입력값을 사용한다. 앞선 입력에 포함한 원래 계산식을
  다시 펼치지 않는다. 자식 구성·이름이 있는 슬롯·순서가 있는 `[View]`도 같은 값을 읽는다.
- 앞선 함수 입력의 호출 결과를 기본값으로 사용하면 입력 함수의 현재 버전과 호출 인자를
  추적한다. 함수 팩터리·실제 호출·결과 입력은 각각의 의존 계약을 유지한다.
- 구성 내부 `@Static let`은 현재 입력을 한 번 읽어 고정한다. 일반 소비자는 변경을 따른다.

## 소유권·실패

컴파일러가 입력마다 충돌하지 않는 내부 저장소를 만들고 본문 활성화에 배치한다.
루트 Window 전달·위젯이 없는 중간 구성·View 목록에도 동일한 순서를 적용한다.
`NativeComponentInputs.h`는 생성 C++의 필드 선택자로 활성화 부모를 따라 저장소를
차용한다. 타입 검사는 C++에서 결정되며 런타임 문자열 검색이나 전역 저장소를 사용하지
않는다. 선택자는 필드의 lvalue 참조를 반환해야 한다. 원시 포인터는 타입 추론용 저장소
접두부에서도 사용하며, 실행 코드는 기존 소유 활성화의 수명을 유지한다.

최초 계산 실패는 해당 활성화 실패로 반환한다. 활성화 이후 계산이 실패하면 마지막 정상
입력과 표시를 유지하고 네이티브 그래프의 실패 경로에 기록한다. 다음 유효한 원본 변경으로
복구할 수 있다. 조건부 자식 제거 시 입력의 구독을 닫고, 다시 활성화하면 새로운 값과
Static 스냅샷을 만든다. 부모 백엔드는 기존 소유자를 유지한다. 닫힌 값 읽기는 거부한다.

## 검증과 범위

- `LVUI.NativeScalarInputs`: 생성 C++에서 계산 횟수·여러 소비자의 동일 결과·앞선 입력의
  기본값·Static·실패 보존·복구·종료를 검사한다.
- `iiGUI.native_scalar_inputs.*`: 창 없는 실제 위젯 상태에서 포획·여러 단계 전달·모든
  스칼라 타입과 Color 채널·조건부 재활성화·Window/목록 전달·함수 기본값을 검사한다.
- 설치 후 재배치한 `LVUI::Native` 소비자가 공개 헤더로 같은 저장소를 원시/공유 포인터에서
  차용하고, 미초기화·부모 부재를 거부하는지 실행한다. 공개 컴파일러 소비자도 두 기본값
  경로를 생성한다. 저장소를 복사하는 선택자와 소유 활성화를 벗어난 선택자는 독립 C++
  소비자의 컴파일 실패 검사에 포함한다.
- LVRS 프레임워크용 동일한 6개 AOT 구성을 실제 C++ 팩터리까지 컴파일한다. LVRS 앱·
  테스트 실행은 저장소 지침에 따라 전체 작업의 최종 일괄 검증에 남긴다.

이 문서는 타입을 지정한 스칼라 구성 입력에 대한 것이다. 추가한
[C++ 구성 입력](ObjectInputs.md)은 값·객체 핸들을 같은 활성화 저장소에 연결한다.
가변 View·깊은 Static·모든 LVRS 입력의 완료를 의미하지 않는다.
스택의 동적 간격·여백·크기는 이후 추가한 [네이티브 배치](NativeLayout.md)를 따른다. 실제 창·GPU·IME·
접근성과 다른 플랫폼의 실행 증거를 창 없는 테스트로 대신하지 않는다.
