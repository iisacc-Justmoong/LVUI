# 네이티브 자연 높이를 사용하는 가상 목록

`measureHeight: true`는 반복 행의 실제 콘텐츠 높이를 iiGUI에서 측정하고 C++ 배치 색인에
반영한다. `itemHeight`는 아직 측정하지 않은 행의 추정값이다. 세로 목록과 세로 방향의
반응형 그리드에 적용하며, 가로 목록의 가변 너비 측정은 이 입력의 계약에 포함하지 않는다.

```lvui
import vm ResultsModel
Window {
    VStack {
        for (item in vm.items, key: item.id, id: "results",
             itemHeight: 80, measureHeight: true,
             measureRevision: vm.layoutRevision, spacing: 4) {
            VStack(spacing: 2, alignment: .stretch) {
                Label(text: item.title)
                Label(text: item.description)
            }
        }
    }
}
```

## 크기와 배치

- `Widget::measure(width)`와 자연 크기 알림은 배정된 사각형과 별도로 선호 콘텐츠 크기를
  계산한다. 사각형 높이가 그대로인 상태에서 텍스트가 길어져도 이를 감지한다.
- 실제 셀 너비를 사용해 줄바꿈을 측정한다. 너비·열 수·모델·공통 뷰 조건이 바뀌면 관련
  측정 세대를 바꾸고 오래된 세대나 다른 너비에서 도착한 알림을 무시한다.
- 그리드의 한 줄은 해당 줄의 가장 큰 측정 높이를 사용한다. 미측정 셀은 추정 높이를
  사용한다. 아직 화면에 들어오지 않은 행의 높이와 전체 스크롤 길이는 추정값일 수 있다.
- `VirtualLineIndex`는 Fenwick 누적 색인이다. 행 시작점·표시 범위 검색과 줄 높이 변경을
  매 스크롤마다 전체 행을 더하는 방식으로 처리하지 않는다. 모델·너비·공통 조건 변경 시
  색인 재구성은 전체 모델을 순회할 수 있다.
- 측정한 높이가 바뀌면 현재 항목 키와 행 내부 픽셀 위치에 맞추어 오프셋을 보정한다.
  보정은 뷰 상태이며 파일 저장·문서 리비전·백엔드 메서드 호출로 변환하지 않는다.

같은 키의 행이 활성 상태라면 콘텐츠 크기가 바뀌어도 지역 객체와 입력 상태를 유지한다.
화면 밖 행은 기존 반복 계약대로 퇴역한다. 크기 캐시는 지역 뷰모델의 영속 저장소가 아니다.

## 0 높이와 희소 표시

0 높이의 행은 실제 가상 영역을 차지하지 않는다. 서로 멀리 떨어진 모델 인덱스 사이에
빈 행이 많아도 양수 높이의 표시 행만 마운트할 수 있다. 원래 인덱스는 그대로 제공한다.
모든 행의 논리 높이가 0이면 한 개의 관측용 활성화만 남기고 유령 스크롤 길이를 만들지
않는다. 이 보이지 않는 활성화를 사용자가 보고 있는 항목의 기준점으로 보관하지 않는다.

이를 위해 네이티브 `CollectionOptions::sparse`는 비연속적인 표시 인덱스를 허용한다.
인덱스는 모델 범위 안에서 엄격히 증가해야 하고 첫 인덱스·키·수량도 검증한다. 수동
`first`·`count` 모드의 연속 범위 의미는 바꾸지 않는다.

## 변경 발행 계약

뷰에 실제로 연결된 행의 콘텐츠 변경은 자연 크기 알림으로 반영한다. 컴파일러는 행
템플릿이 읽는 상위 반응형 값·C++ 속성과 메서드의 리비전을 별도로 수집하여 공통 조건
변경 시 화면 밖의 크기 캐시도 무효화한다. 타입 매개변수를 통해 전달한 스칼라의 의존
읽기도 보관한다. 이 의존성 수집은 컴파일 단계에 수행하며 런타임 AST를 사용하지 않는다.
공통 변경을 감지하기 위해 사용자 C++ 메서드를 추가로 호출하지 않는다.

화면 밖 공유 C++ 객체의 내부 변경은 컬렉션의 값 변경과 같은 사건이 아니다. 그러한
변경이 저장된 크기에 영향을 줄 수 있으면 네이티브 모델이 `measureRevision`에 연결한
Observable을 발행한다. 위 예제의 `layoutRevision`이 이 역할이다. 값 타입 컬렉션의 값
변경과 실제 너비 변경에는 별도 수동 무효화가 필요하지 않다. 공유 객체를 사용하는 모델의
변경 통지를 추측하거나 객체 내부의 임의 쓰기를 자동 관측한다고 보장하지 않는다.

`measureRevision`은 뷰 크기 캐시의 변경 신호이며 문서 파일의 수정 번호와 같을 필요가
없다. 기존 모델이 적절한 변경 통지를 제공하면 이를 연결한다. 이 입력도 일반 반응형
표현식이며 `itemHeight`가 있는 자동 모드에서만 받는다.

## 수명·오류·경계

측정 소유자는 UI 실행 영역을 확인하고 닫힌 뒤의 알림을 무시한다. 행의 측정 콜백은
스코프·바인딩·측정 소유자를 약하게 참조한다. 잘못된 크기·중복 측정 키·오래된 세대와
종료 중 호출을 구분한다. 자연 높이는 0~32,767, 너비는 0~8,192이며 기존 컬렉션·위젯
노드 한계도 유지한다. 무한한 레이아웃 피드백은 기존 바인딩·배치 정착 한계로 차단한다.

검사 대상은 다음과 같다.

- `LVUI.NativeMeasuredCollection.*`: 누적 색인, 실제 높이·그리드 최대값·기준점·공통
  변경, 희소 인덱스·스레드·퇴역·잘못된 측정.
- `LVUI.Repetition.*`: 입력 진단과 상위 속성·전달 매개변수·메서드 리비전의 C++ 생성.
- `iiGUI.keyed_content.measurement`: 고정 사각형 안의 자연 크기 변경과 관찰 해제·퇴역.
- `iiGUI.native_measured_repetition.*`: 생성 C++의 줄바꿈·본문 변경·그리드·기준점·
  0 높이·공유 객체의 화면 밖 변경 통지와 소유자 해제.

실제 창·GPU·플랫폼과 전체 LVRS 실행의 완료 증거는 별도이다. 전체 목표의 완료 여부는
[완료 기준](Completion.md)을 따른다.
