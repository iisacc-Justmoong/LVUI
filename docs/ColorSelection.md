# LVUI 색상 선택 상태

`LVUI/ColorSource.h`는 교체 가능한 색상과 리비전 읽기 인터페이스를 제공한다.
`LVUI/ColorSelection.h`의 `ColorEditing`은 편집 토큰, 리비전 비교와 원자적 완료를
제공하는 교체 가능한 인터페이스다. `ColorSelection`은 이를 구현하는 표준 C++ 색상 상태다. GUI,
Qt, QML 또는 LVRS 없이 앱과 여러 컴포넌트가 공유할 수 있다. 색상은 encoded sRGB의
독립 RGBA 채널이며 각 채널은 유한한 0~1 값이다.

`begin()`은 현재 색상을 되돌릴 기준으로 기억하고 고유한 편집 토큰을 발급한다.
`begin_if_current(revision)`은 관찰한 리비전이 그대로일 때만 세션을 열고 그 토큰,
기준색과 새 리비전을 원자적으로 반환한다. 편집 시작과 외부 색상 변경이 경합해도
오래된 입력이 새 색상을 자신의 취소 기준으로 가로채지 않는다.
같은 토큰의 `edit()`은 후보 색상을 갱신하고 `accept()`는 현재 값을 확정하며
`cancel()`은 해당 세션의 기준을 복원한다. 한 번에 한 세션만 허용한다. `set_color()`로
앱이 외부 색상을 대체하면 진행 중 토큰은 만료된다. 이후 늦게 도착한 이전 취소나
편집은 새 색상을 덮어쓰지 못한다. 잘못된 색상과 만료된 토큰은 기존 상태를 보존한다.
외부에서 같은 색상을 설정하더라도 편집 중이면 세션을 만료한다. 생성 시 초기 색상이
잘못된 경우에는 `std::invalid_argument`를 발생시킨다.
공유 편집 표면의 `edit_if_current()`는 관찰한 리비전이 여전히 유효할 때만 색상을
수정하며, 활성 세션의 취소 기준은 보존한다. 오래된 입력은 오류로 거부한다.
색상이 같은 검정색이더라도 숨은 색조를 변경한 표면은 리비전을 발행할 수 있다.

상태와 세션 변경마다 리비전을 발행하고 동시 읽기·쓰기를 직렬화한다. 스냅샷은 마지막
세션이 확정·취소·외부 대체 중 어떤 방식으로 종료됐는지도 제공한다. 같은 외부
색상으로 활성 세션 없이 다시 설정하는 경우는 변경하지 않는다. `snapshot()`은 색상,
기준, 편집 토큰과 리비전을 한 번에 제공한다. `ColorSource` 자체는 구독을 강제하지
않으므로 선언형 버튼을 연결할 때는 앱이 변경 리비전을 관측 가능한 `modelRevision`으로
발행해야 한다. 이 모델은 색 공간 변환이나 색상 피커 화면을 만들지 않는다.

`complete(token, accepted)`는 세션을 끝내고 그 순간 확정 또는 복원된 색상과 리비전을
같은 잠금 안에서 반환한다. 완료 직후 다른 스레드가 색상을 바꾸더라도 호출자는 실제
완료된 값을 구분할 수 있다. 기존 `accept()`와 `cancel()`도 이 경로를 사용한다.
