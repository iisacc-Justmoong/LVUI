# LVUI 독립 목록 모델

`List.h`는 평면 목록의 데이터와 화면 선택을 LVUI가 소유하는 독립 경계다.
`ListSource`는 고유 키·레이블·설명·아이콘 이름·활성 상태를 가진 불변
`ListSnapshot`을 제공한다. `ListEditor`는 삽입, 키를 유지하는 교체, 삭제와 순서
이동을 관찰한 리비전과 함께 받는다. 앱은 파일, 데이터베이스 또는 다른 저장소에
맞는 구현으로 두 경계를 교체할 수 있다. 계층 목록, Qt, QML이나 LVRS의 데이터
타입을 요구하지 않는다.

`ListMemory`는 선택적인 메모리 구현이다. 한 편집을 검증한 뒤 불변 스냅샷을
게시하며 오래된 리비전은 거절한다. 같은 내용의 교체나 같은 위치로의 이동은
리비전을 늘리지 않는다. 항목은 최대 65,536개, 전체 텍스트는 64 MiB이며 키는
비어 있지 않은 고유한 UTF-8이어야 한다. 이전 스냅샷은 이후 편집에도 유지된다.

`ListController`는 키 기반 선택을 문서와 분리해 보관한다. 선택은 문서 리비전을
변경하지 않는다. 앱이 외부 변경 후 `refresh()`를 호출하면 새 스냅샷을 검증하고,
선택 항목이 제거되었거나 선택할 수 없게 된 경우에만 선택을 비운다. 소스가 게시한
리비전은 단조 증가해야 한다. 컨트롤러는 생성한 스레드에서 사용하며 새로고침 중
재진입을 거절한다.

`ListViewportSource`는 불변 스냅샷과 키 색인을 사용해 고정 높이 목록의 보이는 행과
앞뒤 여유 행만 계산한다. 행 삽입 뒤에는 가능한 한 같은 키와 행 내부 위치를 유지하며,
사용자의 새로운 스크롤이나 특정 키 표시 요청은 이전 기준점보다 우선한다. 계산에는
문서 편집이 수반되지 않는다.

`LVUI.OwnedList.Model`은 스냅샷 보존, 선택과 문서 상태 분리, 원자적 편집, 유효성,
오래된 요청, 동시 편집과 스레드 경계를 검사한다. `LVUI.OwnedList.Viewport`는
10,000개 항목의 부분 조회, 스크롤 기준점, 표시 요청과 입력 한도를 검사한다. 일반
[독립 목록 화면](NativeOwnedListView.md)과 [기본 목록 선언](NativeOwnedListPanel.md)은
이를 직접 사용한다.
