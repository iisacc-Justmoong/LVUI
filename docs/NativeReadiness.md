# Dreamscapes 뷰 작성 준비 검증

2026-10-27 사용자가 지정한 종료 기준은 LVUI·iiGUI로 Dreamscapes의 뷰를 Qt/QML 없이
새로 작성할 수 있는 상태와 시스템 SDK 설치이다. 제품 소스의 자동 변환은 이 단계에
포함하지 않는다. 준비 수준은 원본 LVRS 전체 API의 동등성과 별도로 검증한다.

## 요구 관측과 해석

`catalog/dreamscapes-qml.json`은 제품 QML 81개의 읽기 전용 관측 자료이다. 타입 표기
273개·함수 411개·핸들러 1,377개는 어휘 수이며 지원 기능 수가 아니다. 앱 내부 구성과
업무 메서드를 모두 SDK의 고정 컴포넌트로 추가하지 않는다. 배치는 LVUI 구성으로,
상태·명령·투영은 C++, 사용자 정의 표면은 NativeViewSource로 작성하는 계약을 검증한다.

| 제품에 필요한 영역 | 네이티브 작성 경로 | 증거·관문 |
|---|---|---|
| 창·반응형 배치·패널 | Window, 스택, flex, 동적 배치 입력 | NativeWindow·NativeLayout 검사, 작업 공간 크기 변경 |
| 프롬프트·숫자·파라미터 | 실제 InputField·선택·버튼, C++ 검증·상태 | 생성 C++ 입력 검사와 작업 공간 파라미터 |
| 상태·진행·큐 결과 | Core Observable, 소유 루프 전달, NativeBindings | ActivationWork 검사와 실제 비동기 픽셀 작업 |
| 최근 파일·결과·검토 | 키 기반 반복·가상화·선택과 C++ 모델 | Repetition·CollectionNavigation 및 생성 결과 행 |
| 캔버스·오버레이 | NativeView, WidgetDrawing/이미지, C++ paint handler | 실제 장면 데이터·GPU 픽셀 대조 |
| 포인터·펜·휠·드래그 | typed WidgetInput, 캡처·포커스·취소 | NativeView 입력 검사, 실제 캔버스 팬·타임라인 탐색 |
| 타임라인·눈금·재생 | 유지되는 C++ 뷰와 기존 Core 프레임 루프 | 눈금·탐색·프레임 진행 및 문서 revision 비변경 |
| 이미지·비디오 프레임 | 불변 RasterImage, 유지되는 위젯의 프레임 데이터 갱신 | 24프레임 검사, 대기 중 마지막 정상 프레임 유지 |
| 텍스트·IME·키보드 | 기존 iiGUI 텍스트 서비스·입력·조상 단축키 경계 | 네이티브 텍스트·편집기·입력 회귀 |
| 메뉴·툴팁·팝업·대화상자 | LVRS 네이티브 구성과 Host 서비스 | 해당 모델·위젯·실제 호스트 최종 실행 |
| 색상·계층·도구 패널 | 기존 LVRS C++ 모델과 구성, 필요 시 NativeView | 모델·AOT·수명 검사와 공개 API 소비자 |
| 게시·설정 등 동적 폼 | 같은 입력·목록·조건부 뷰와 C++ 명령 | 폼 작성 가능성을 검증하며 외부 SNS 업로드 실행과 구분 |
| 배포·설치 | AOT 코드·iiSDKCore 앱·iiGUI/LVRS 네이티브 패키지 | Qt/QML·소스 해석기 없는 설치 소비자·해시 검증 |

표의 경로는 작성 계약이며 각 행의 실행 통과를 자동 의미하지 않는다. 최종 준비 보고서는
실제 실행·컴파일·설치 증거를 구분하고, 실패와 재실행 이력을 보존해야 한다. 다른 OS와
GPU, 사용하지 않는 원본 API의 미완료 상태를 준비 보고서에서 숨기지 않는다.

## 통합 예제

LVRS의 `example/NativeCreationWorkbench`는 배치와 입력 전달을 LVUI에 두고,
파라미터 검증·절차적 RGBA 계산·결과 선택·팬·탐색·재생을 C++에 둔다. 실제 작업 큐에서
프레임 24개를 만들고 같은 앱의 소유 루프로 전달한다. 캔버스와 타임라인은 두 개의 유지되는
NativeView이며 프레임마다 원천이나 트리를 재생성하지 않는다.

self-test는 실제 GPU 캔버스 픽셀, 포인터 탐색·팬, 결과 행의 C++ 명령, 편집 값 보존,
창 크기 변경, 프레임 콜백과 종료를 확인한다. AI 추론·파일 저장소·SNS 전송의 제품 통합을
실행한 것으로 표현하지 않는다. 최종 단계 전의 빌드 성공은 self-test 통과가 아니다.

## 종료와 설치 관문

1. 언어·네이티브 접점·기존 동작의 적절한 일반/오류 검출 회귀를 수행한다.
2. 대표 작업 공간과 필요한 LVRS 앱·테스트를 최종 일괄 단계에서 실제 실행한다.
3. 실패 보존·퇴역·입력·프레임·뷰/파일 상태 분리를 확인한다.
4. 독립·재배치한 소비자의 컴파일·링크·실행과 Qt/QML 의존성 부재를 확인한다.
5. 문서·JSON 색인·공개 헤더·라이브러리·패키지 출처를 대조한다.
6. 검증된 패키지를 시스템 SDK 위치에 설치하고 설치본만 참조하는 소비자로 다시 확인한다.

실행·설치 완료 여부는 [최신 검증 기록](NativeReadinessVerification.md)과 최종 JSON으로 판정한다. 설치 대상은
SDK이며 Dreamscapes 제품의 기존 기능이나 생성 파라미터를 제거하는 작업은 하지 않는다.
설치된 다른 패키지·기존 Qt SDK·활성 앱·작업을 보존한다.
