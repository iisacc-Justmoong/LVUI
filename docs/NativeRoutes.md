# LVUI 경로 해석

LVUI의 경로 정규화와 매칭은 C++ 값으로 동작하며 Qt·QML·LVRS 타입이나 런타임을
사용하지 않는다. 문자열 소스를 실행하지 않고 경로 문자열과 앱이 등록한 패턴을
비교한다. 경로 해석과 실제 페이지 생성·이력 변경은 별도 책임이다.

`normalize_route`는 앞뒤 Unicode 공백을 제거하고, 빈 경로를 `/`로 정하며,
필요하면 앞에 `/`를 붙이고 루트가 아닌 경로의 끝 `/`를 제거한다. 내부의 연속된
`/`, 대소문자와 문자열의 Unicode 정규화 형태는 유지한다. URL 해석, 퍼센트
디코딩, query 분리나 파일 권한 검사는 수행하지 않는다. 경로는 최대 65536바이트의
NUL 없는 UTF-8이며 최대 4096개 세그먼트로 제한한다.

`RoutePattern`은 리터럴 세그먼트, 한 세그먼트의 `[name]`, 나머지 세그먼트의
`[...name]`를 지원한다. 나머지 캡처는 빈 값도 허용하고 그 뒤 패턴은 검사하지
않는다. 중복 이름은 나중에 캡처한 값이 우선한다. 매칭 실패에서는 부분 캡처를
내보내지 않는다. 빈 원본 패턴은 비활성 슬롯이며 공백만 있는 패턴은 루트이다.

`RouteResolver`는 패턴을 선언 순서대로 검사하고 결과를 불변 객체로 반환한다.
같은 경로의 캐시 적중은 같은 결과를 재사용하며, 결과를 소유한 호출자는 캐시
축출이나 패턴 교체 이후에도 안전하게 읽을 수 있다. 캐시는 기본 256개, 최소
16개, 최대 65536개와 계산 예산 8 MiB로 제한하고 오래 사용하지 않은 항목부터
축출한다. 패턴은 최대 65536개, 원본 합계 8 MiB, 컴파일된 세그먼트 262144개이다.
잘못된 패턴 목록은 기존 설정과 캐시를 유지한다. resolver의 캐시와 변경은 생성한
스레드에서만 접근한다.

경로 모델 자체는 페이지 빌드나 이력 변경을 수행하지 않는다. 별도의
[이력 모델](NativeNavigationHistory.md)은 준비와 확정을 분리하고,
[독립 페이지 라우터](NativePageRouter.md)가 이 두 모델과 앱의 페이지 팩터리를 연결한다.
플랫폼별 실제 표시와 접근성은 별도 검증이 필요하다. 앱에서 공급한 탐색 대상과 링크의
연결은 [링크 계약](NativeLinks.md)을 따른다.
