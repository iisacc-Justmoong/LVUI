# C++ 타입으로 추론하는 네이티브 값

LVUI의 일반 선언은 C++ 초기화 식의 실제 타입으로 값과 함수를 구분한다.
헤더 텍스트를 검색하거나 실행 중 타입 이름을 해석하지 않는다. 생성된 C++의
템플릿 인스턴스화와 실제 호출 가능성이 최종 검사이다.

```lvui
import vm Backend
let count = vm.count
let action = vm.run
let render = vm.makeFormatter()
let alias = render
@Static let frozen = alias
var manual = alias
Window { VStack {
    PushButton(onClick: action)
    Label(text: render(2))
} }
```

## 저장소와 호출 규칙

- 일반 `let`은 기존 Bindings 그래프에서 C++ 의존 읽기를 추적한다. 함수의 선택 버전이
  바뀌면 함수 별칭과 호출 결과를 사용하는 뷰도 갱신한다.
- `@Static let`은 초기 값 또는 함수의 초기 선택 버전을 고정한다. 함수 실행 결과나
  함수 내부 상태를 복제하지 않는다. 선택된 수신자의 수명·실행 영역 검사는 유지한다.
- `var`는 초기 버전을 선택한 뒤 기존 C++ setter로 교체한다. 원래 원천이 바뀌어도
  자동으로 다른 버전을 선택하지 않는다. 함수의 네이티브 팩터리 교체도 지원한다.
- 함수 참조를 선언하거나 버튼에 연결할 때 작업을 실행하지 않는다. `render(2)`는
  해당 식을 평가할 때 실행한다. 함수 호출 중 관측 값의 읽기도 Core에 수집한다.
- 일반 스칼라·구조체·목록은 기존 값 의미를 유지한다. 임시 객체와 인자를 차용하는
  함수는 [FactoryCaptures.md](FactoryCaptures.md)의 소유권 규칙을 적용한다.
- Void 작업은 원래 백엔드의 변경 발행 경계를 사용한다. 함수 별칭이 이를 중복 발행하지
  않는다. 뷰에서 함수 버전을 선택하는 것 자체는 파일 저장이나 생성 요청이 아니다.

`NativeInferredValues.h`는 값 저장소와 함수 저장소를 컴파일 시 선택한다. C++ 함수는
기존 `CallbackValue`·`FunctionVariable`·스코프 입장 검사에 연결한다. 독립적인 실행기나
두 번째 반응형 그래프를 추가하지 않는다. 함수 버전 관측과 선택은 소유 스레드에서만
가능하며, 소유자 종료 후 새 호출과 관측은 기존 종료 규칙을 따른다.

위 예제의 활성화된 View 객체에서는 다음처럼 가변 함수만 C++에서 교체할 수 있다.
이때 입력 프롬프트나 다른 위젯을 다시 만들지 않는다. 반환되는 `Result<void>`로
종료된 뷰·실행 영역 오류와 팩터리 실패를 확인한다.

```cpp
auto replaced = view.set_manual_native([] {
    return [](std::int64_t value) { return std::to_string(value); };
});
```

## 추론 범위와 명시적 타입

비모호한 C++ 멤버 함수, 함수 포인터, `std::function`, 단일 호출 연산자가 있는 함수
객체와 그 공유·고유 핸들, 관측 가능한 함수 필드가 추론 대상이다. 함수 결과와 인자는
기존 LVUI 정규화에 따라 문자열은 `std::string`, 정수는 `Int`로 연결한다.

오버로드 집합이나 범용 호출 연산자는 하나의 서명이 결정되지 않을 수 있다. 이 경우
`let render: (Int) -> String = vm.render`처럼 명시적 서명을 사용한다. 임의의 C++ 함수
타입을 모두 자동 추론한다고 주장하지 않는다. 잘못된 인자 수, Void의 표시 값 사용,
일반 값의 함수 호출은 생성 C++의 검사에서 거부한다.

## 회귀 검사

`native_inferred_values.cpp`는 값·메서드·이동 전용 반환 함수와 별칭의 저장소 규칙을
검사한다. `native_inferred_value_validation.py`는 실제 생성한 C++의 허용·거부 계약을
검사한다. iiGUI의 `native_inferred_values.cpp`는 생성된 위젯의 클릭·표시·별칭·교체,
입력 보존·실패 복구와 종료 수명을 창 없이 검사한다. OS 창·GPU·LVRS 원본 전체 동작의
검증과 이 검사 결과를 구분한다.

## 2026-10-26 검증 기록

일반 LVUI 전체 276개 검사를 수행했다. 최초 실행은 275개 통과, 이전 arity 오류 문구를
요구하던 음성 검사 1개 실패였다. 실제 잘못된 호출은 C++ 제약에서 거부되고 있었다.
새 제약 진단을 검사하도록 갱신한 뒤 관련 7개를 재검사하여 모두 통과했다. 전체 실행과
재검사 로그를 별도로 보존하며 한 번의 전체 실행이 모두 성공했다고 표시하지 않는다.

| 범위 | 결과 |
|---|---|
| 관련 ASan·UBSan 검사 | 206개 통과 |
| 메모리 검사 SDK의 재배치 설치 소비자 | 1개 통과, 내부 네이티브·컴파일러·런타임 소비자와 CLI 검사 포함 |
| iiGUI 창 없는 일반·메모리 검사 | 각 220개 통과 |
| 추론 타입 계약 | 각 구성에서 유효한 14개 컴파일, 잘못된 5개 거부 |
| LVRS 생성 뷰 팩터리 | 각 구성에서 57개 컴파일, 실제 실행은 수행하지 않음 |
| Dreamscapes QML | 81개 파일 변경 없음 |

새 기능의 직접 검사는 네이티브 값 6개와 실제 생성 위젯 11개이다. 결과 파일은 소스
저장소의 `build/lvui-completion/inferred-values-verification-20261026.json`에 기록한다.
실제 창·GPU·다른 플랫폼·전체 LVRS 동등성이나 Dreamscapes의 체감 속도 개선을
이 결과만으로 주장하지 않는다. LVUI 전체 완성 작업은 계속 진행 중이다.


Core Value 객체·문자열 키 맵의 점 표기 속성도 자동 타입 판정에 포함한다. 이 데이터 조회는
메서드 포인터를 요구하지 않는다. 일반 파생 값은 원천 변경을 따르고, @Static과 가변
저장 값은 각 저장 규칙을 유지한다. C++ 객체의 실제 메서드·callable 필드·멤버 참조 판정은
기존 수명 경계를 공유하며, 존재하지 않는 데이터 키는 원천 삽입 없이 오류로 보고한다.
