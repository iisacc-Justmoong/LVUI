# LVUI 독립 스테퍼

파괴적 톤은 공통 버튼의 상태 정책과 컴파일 시 선택한 빨강 호버·누름 토큰을 사용한다.
명시적인 스테퍼 상태색은 공통 토큰보다 우선한다.

`LVUI/Stepper.h`는 선언에 필요한 크기·방향·색상 값을 제공한다. 스테퍼의 방향
허용과 버튼 시각 상태는 `iiGUI/StepperModel.h`가, 입력·그리기와 위젯 수명은
`iiGUI/NativeStepperView.h`가 소유한다. 기본 표면은 18×18 논리 px, 모서리는
4이며 기본 방향은 위와 아래이다. 위쪽 절반은 +1, 아래쪽 절반은 -1을 요청한다.
단일 화살표는 허용된 방향만 발생시키고 비활성 상태는 요청을 무시한다. 수치
자체는 앱 모델이 소유한다. LVUI 디자인 정책과 바인딩은 iiSDKCore 외 SDK를
직접 참조하지 않으며 앱이 iiGUI 모델과 호스트를 주입한다.

`ii::gui::NativeStepper`는 독립 C++ 앱에서 사용할 수 있고 정책 기반
`BasicNativeStepper`는 앱이 값과 콜백 계약을 지정할 수 있다. 기존 C++ 소비자는
제거된 `lvui::Stepper` 대신 `ii::gui::StepperModel` 또는 LVUI 입력을 조합하는
`StepperBinding`을 사용한다.
포인터의 위·아래 위치, 방향키와 접근성 증감 요청은 같은 방향 정책을 따른다.
허용하지 않는 방향은 접근성 행동에서도 제외한다. 눌림, 놓음, 취소, 클릭 및
증감 콜백을 제공하며, 콜백 중 설정이 바뀌거나 위젯이 폐기되면 이전 요청이
새 상태에 영향을 주지 않는다. 비활성 상태와 비활성 조상은 입력을 받지 않는다.

기본 선언형 `Stepper`는 LVUI 어댑터를 생성하고 방향, 톤, 크기, 색상, 활성 상태와
콜백을 연결한다. 반응형 입력은 유효한 설정만 적용하며 동일한 설정은 진행 중인
입력을 중단하지 않는다. 포인터 취소는 눌림을 종료하고 퇴역 시 콜백 소유권을
해제한다. macOS arm64에서 iiGUI 독립 모델·호스트·설치 소비자와 LVUI 생성·목록
내 스테퍼의 헤드리스 검사를 통과했다. `method`와 `methods`는 [공통 버튼 메서드 계약](NativeButton.md)을
따른다. 실제 OS 입력 및 스크린 리더 검증은 수행하지 않았으며, Windows와 Linux의
호스트 접근성 구현은 아직 미완성이다.

macOS arm64에서 Core 단독 바인딩과 생성 코드, 복합 목록·버튼 메서드, 설치 헤더를
창 없이 검사했다. 다른 운영체제의 실제 렌더링은 검사하지 않았다.
