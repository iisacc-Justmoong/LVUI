# LVUI 독립 구현 현황

> 현재 채택한 책임은 [LVUI 언어와 iiGUI 프레임워크의 경계](GraphicsBoundary.md)이다.
> 아래의 LVUI 소유 위젯 설명은 현재 코드와 과거 작업의 기록이며, 목표 구조나
> iiGUI 이전 완료를 뜻하지 않는다.

LVUI는 `.lvui` 선언을 네이티브 C++로 컴파일하는 독립적인 선언형 UI 언어이다.
현재 구현에서는 컴파일러와 다수 위젯의 코드·상태·동작·그리기가 LVUI에 있다.
목표는 위젯 구현을 iiGUI로 분리하고 LVUI에 선언·생성·바인딩을 남기는 것이다.
과거 시각 언어 이전에서 LVRS 네이티브 코드·테스트·자산 일부를 LVUI에 복제하거나
리팩터링했으며, 그 결과가 아직 LVUI에 남아 있다. 기존 디자인 값은 유지하고
실행 시 LVRS 위젯을 참조하지 않는다. 빌드·공개 타입·링크·런타임은 LVRS 및
Qt/QML에 의존하지 않아야 한다.

현재 공통 Figma 디자인 라이브러리는 사용자가 기존 LVRS를 개명한
[LVUI](https://www.figma.com/design/0GkItQYSNIR0lZ3iJhfJzc/LVUI)이다.
Congregation은 이 라이브러리의 기존 키와 인스턴스를 계속 사용한다. 별도로 만든
동명 설계 파일은 다른 라이브러리이며 이름이 같다는 이유만으로 그 자산에 일괄
교체하거나 기존 파일을 삭제하지 않는다. 디자인 라이브러리의 개명과 Qt 기반
레거시 SDK 소스의 독립 LVUI 이식은 서로 다른 작업이다.
원본과 SDK의 기존 공통 변수 233개는 해석 값이 일치했다. SDK 검색 필드에 추가한
다섯 변수도 원본 라이브러리에 게시하고 두 파일의 서로 다른 ID를 SDK 조회에
연결했다. 원본에서 없어진 과거 Action 변수 네 개는 호환 이름으로만 유지한다.
상세 범위는 [스타일 토큰 계약](StyleTokens.md)을 따른다.

기존 Figma 변수 스냅샷의 이름과 식별자는 디자인 자료 및 호환 식별자로 남을 수
있으나, 원본 저장소나 Figma 접속은 빌드·실행의 필수 조건이 아니다. 사용자가
2026-10-29에 명확히 한 이전 방식과 실행 순서는
[네이티브 이전 우선순위](NativeMigrationRoadmap.md)를 따른다.

## 현재 구현

- 선언형 `Application`의 이름 있는 독립 창은 상수 또는 이벤트 시점의 반응형
  문자열로 열고 닫을 수 있다. 창 대상은 접수할 때 결정하고, 앱·창의 소유
  스코프와 지연된 창 생성 경계를 유지한다. [앱 수명 명세](NativeApplication.md)를 따른다.
- 기본 코드 생성의 창 appearance는 LVUI의 토큰에서 값으로 구성하고
  `ii::gui::lvrs_appearance()`를 호출하지 않는다.
- 스택의 정적·반응형 배경과 테두리 그리기는 iiGUI가 소유하며 LVUI는
  디자인 값과 그래픽 SDK에 독립적인 변경 바인딩을 제공한다.
- 기본 `ProgressBar`의 상태·배치·접근성·모션 및 그리기는 독립 iiGUI 위젯이
  소유한다. 생성된 앱 코드는 LVUI 토큰과 반응형 값을 위젯에 전달한다.
- 생성 코드는 반응형 범위·크기·모양·색상 및 명시적 표시 구간을 지원한다.
  기본 색상은 LVUI가 보유한 디자인 스냅샷에서 컴파일 타임에 결정한다. 자세한 지원과 한계는
  [진행 상태 뷰](NativeProgress.md)에 있다.
- 진행 표시기는 iiGUI의 상태 제공자 인터페이스와 반응형 스냅샷을 받아
  LVRS 모델 없이 값과 키를 갱신할 수 있다. 소스 포인터 내부의 비관측 변경은
  앱이 관찰 가능한 스냅샷으로 전달해야 한다.
- 진행 표시기의 모션 상태·보간·재목표는 iiGUI의 표준 C++ 모션 모델이 소유하며,
  앱 호스트의 프레임 시각을 주입한다. 축소 모션 설정도 앱이 전달한다.
- 진행 표시기는 범용 호스트 의미 정보로 역할과 정규화된 목표값을 전달한다.
  macOS·iOS 소스의 플랫폼 매핑과 실제 접근성 기기 실행은 별개이다.
- 기본 `AbstractButton`, `PushButton`, `LabelButton`과 `IconButton`은 iiGUI의
  버튼 모델과 호스트를 사용한다. LVUI는 상태별 토큰·치수·아이콘과 콜백을
  전달한다. 이 버튼과 `HelpButton`, `AlertButton`의 `motionEnabled`는 반응형으로
  변경할 수 있으며 배경색과 포커스 테두리 전환을 제어한다. 전역 축소 모션은
  계속 우선한다. 다른 구성 요소가 사용하는 구형 LVUI 버튼 값 모델은 남아 있다.
  제한된 기본
  [이름 아이콘과 교체 가능한 공급자](NativeIcons.md)를 사용한다. 원본 자산을
  이식하고 필터가 있는 원본 하나는 고정 대체 자산으로 출력한다. 범용 SVG 필터와
  레거시 전체 버튼 API는 남아 있다.
- 독립 아이콘은 iiGUI `IconView` 또는 LVUI `Image(iconName: ...)`으로 생성하며
  원본의 기본 크기와 교체 가능한 자산 공급자를 사용한다. 구형 LVUI 아이콘 위젯은
  제거했다. 자산 계약은 디코더를 주입받으며 iiGUI를 직접 참조하지 않는다. 상세 범위와 고정
  래스터 배율의 한계는 [아이콘 계약](NativeIcons.md)을 따른다.
- `MenuDivider`와 `ContextMenuDivider`는 LVUI의 표준 C++ 모델이 자연 크기와
  선의 배치를 소유한다. 기본 메뉴의 직접 자식으로도 등록할 수 있다. 상세 계약은
  [독립 구분선](NativeDivider.md)을 따른다.
- 기본 `Menu`, `ContextMenu`의 선택·닫기 계획·배치와 개별 항목의 상태·기하·
  그리기·입력 호스트는 iiGUI가 소유한다. LVUI는 Core 외 SDK 참조 없는 디자인
  값과 바인딩을 제공한다. [메뉴 호스트](NativeMenu.md)의 입력·그리기·수명도
  iiGUI가 관리한다. 직접 재사용 항목 묶음,
  조건·키 기반 반복 항목과
  직접 중첩한 하위 메뉴의 키보드·포인터 탐색, 조상 닫기를 지원한다. 조건·반복
  분기에서도 여러 항목 묶음과 묶음 안의 조건·중첩 반복을 사용할 수 있다.
  조건문 본문에도 지역 선언을 둘 수 있다. [최상위 바인딩 진단](NativeBindings.md)은
  하위 콘텐츠의 오류도 조회한다. 실제 운영체제 보조 기술 검증은 아직 남아 있다.
- 기본 `Popover`는 [iiGUI 모델과 호스트](NativePopover.md)를 앱에서 LVUI의
  Core 전용 바인딩과 조합한다. 플랫폼별 실제 표시 검증은 아직 남아 있다.
- 모달의 [iiGUI 모델과 호스트](NativeModal.md)가 배치·액션과 열림 단위 본문
  수명을 소유하며 LVUI 정책은 스타일과 자산을 전달한다. 선언형 `open`은 상수·
  반응형 값과 게시 후 초기 열림을 지원한다. 구형 LVUI 계산 모델은 제거했고
  바인딩은 Core 외 SDK를 직접 참조하지 않는다. 실제 플랫폼 검증은 남아 있다.
- [경고 버튼](NativeAlertButton.md)의 모델 계산과 호스트는 iiGUI에 있으며 LVUI
  정책 어댑터가 토큰·선언형 입력·이벤트를 연결한다. 구형 LVUI 모델을 제거하고
  경고창과 모달도 같은 iiGUI 모델을 사용한다. 버튼 값과 바인딩은 Core 외 SDK를
  참조하지 않는다. 실제 플랫폼 검증은 아직 남아 있다.
- 합성 [경고창](NativeAlert.md)의 액션·배치·텍스트와 아이콘 표현 및 호스트는 iiGUI가
  소유한다. LVUI 바인딩은 Core 외 SDK를 참조하지 않는다. 재질 세부 기능 및 플랫폼
  검증은 남아 있다.
- [시트](NativeSheet.md)의 데스크톱·모바일 배치와 드래그 정책, 고정 본문·스크롤은
  iiGUI가 소유한다. 생성된 앱은 닫기 버튼의 디자인 값과 콜백을 iiGUI에 전달한다.
  별도 LVUI 시트 그래픽 어댑터는 제거했으며 구형 버튼 값 모델 이전, 일부 모션 및
  플랫폼 검증은 남아 있다.
- 모달·경고창·시트의 내장 및 중첩 콘텐츠는 [팝업 열림 바인딩](NativePopupOpen.md)으로
  게시 후 초기값과 반응형 변경을 적용한다. 바인딩 헤더는 호스트 핸들을 주입받으며
  iiGUI에 직접 의존하지 않는다. 사용자에 의한 닫힘은 앱이 원본 상태에
  반영하며, 게시나 바인딩 실패는 해당 활성화의 진단에서 확인한다.
- [표 데이터 모델](OwnedTableModel.md)은 교체 가능한 읽기·원자적 셀 편집 경계와
  문서를 변경하지 않는 선택·탐색과 양축 표시 범위 계산을 제공한다. [독립 표 호스트](NativeOwnedTable.md)는
  가상 그리기·선택, 셀 입력, 범위 클립보드, 행 정렬, 구조 편집·크기 조절과 기본
  선언형 생성과 병합, 행·열 추가 및 삭제 메뉴를 연결한다. 빈 축의 첫 행·열 추가는
  이름이 있는 버튼과 키보드·접근성 활성화도 제공한다. 보이는 셀, 열 머리글과
  기존 행·열별 추가 조작은 개별 접근성 요소로 제공한다. 별도의 행·열 객체와
  실제 운영체제 보조 기술 검증은 남아 있다.
- [목록 도구 모음](NativeOwnedListToolbar.md)의 세 슬롯 기하·입력·그리기와
  수명은 iiGUI에 있다. 단독 선언은 생성된 앱 코드가 iiGUI에 토큰과 자산을
  전달한다. 목록 툴바와 목록 패널의 디자인 바인딩은 Core 외 SDK를 참조하지 않으며
  생성된 앱이 iiGUI 모델과 호스트를 조합한다. 일반 목록의 가상 행 호스트도 iiGUI에 있다.
- [도구 버튼](NativeOwnedToolbarButton.md)의 상태·배치·그리기와 호스트는 iiGUI에
  있으며 LVUI 정책은 토큰·자산·기존 값과 반응형 선언을 연결한다. 구형 계산 모델은
  제거했고 계층 도구 모음의 배치도 iiGUI가 소유한다. 도구 버튼의 값과 바인딩은
  iiSDKCore 외 SDK를 직접 참조하지 않는다.
- [목록 푸터](NativeOwnedListFooter.md)의 슬롯 배치·입력·명령·호스트는 iiGUI가
  소유한다. LVUI 정책은 기존 토큰·아이콘·값과 반응형 선언을 연결한다. 구형
  배치 모델은 제거했고 목록과 계층 패널이 같은 iiGUI 모델로 검증한다. 푸터의
  값과 바인딩은 iiSDKCore 외 SDK를 직접 참조하지 않는다.
- [계층 도구 모음](NativeOwnedHierarchyToolbar.md)의 키 기반 선택·탐색·배치와
  버튼 호스트 수명은 iiGUI에 있다. LVUI는 디자인 값과 바인딩만 제공하며 생성된
  앱이 두 모듈을 조합한다. 직접 자식 등록과 개별 이름 이벤트는 남아 있다.
- 기본 선언형 [계층 패널](NativeHierarchyPanel.md)은 iiGUI의 도구 모음·목록·푸터
  조합을 사용한다. LVUI는 독립 값과 바인딩을 제공한다. 직접 자식과 플랫폼 검증은 남아 있다.
- [코드 문서 모델](CodeDocument.md)은 공유 불변 조각, UTF-16 위치, 교체 가능한
  읽기·편집 인터페이스, 별도의 커서·선택 제어, 제한된 가상 줄 조회와 확정 전 입력
  조합 투영과 입력 세션을 소유한다. 기본 선언형 [코드 편집 화면](NativeCodeEditor.md)의
  텍스트·입력·그리기·위젯 수명은 iiGUI에 있으며 앱이 문서 계약을 주입한다.
  풍부한 편집 기능과 플랫폼 검증은 남아 있다.
- [계층 데이터 모델](OwnedHierarchyModel.md)은 교체 가능한 읽기·이동 인터페이스와
  문서를 변경하지 않는 펼침·선택 투영을 소유한다. [독립 계층 행](NativeOwnedHierarchyItem.md)의
  상태·배치·입력·그리기와 수명은 iiGUI가 소유한다. [독립 계층 목록](NativeOwnedHierarchyList.md)의
  가상 행 호스트도 iiGUI에 있으며 키별 가변 높이 가상 행, 행 데이터를 관찰하는 선언형 개수 View와 사용자 행,
  행별 C++ 관찰 컨텍스트 및 교체 가능한 편집기에 대한 드래그 이동을 제공한다.
- [일반 목록 모델](OwnedListModel.md)은 계층 타입과 분리된 읽기·편집 경계와
  독립 선택 상태를 소유한다. [가상 목록 화면](NativeOwnedListView.md)은 이를 직접
  사용하고 [기본 목록 패널](NativeOwnedListPanel.md)은 도구 모음·푸터와 조합한다.
  사용자 행 대리자의 생성·관찰·가상화 수명과 외부 선택 갱신, 자연 높이에 따른
  가변 배치와 행별 활성화 명령, 교체 가능한 편집기를 통한 이름 편집과 드래그 정렬을 지원한다.
  `scrollable`과 상호작용 상태는 사용자 스크롤을 제어한다. 푸터의 추가·삭제는
  원본처럼 앱에 명령만 전달하며 실제 문서 변경과 이력은 앱이 소유한다. 실제 플랫폼
  검증은 남아 있다.
- 기본 `ColorPickerButton`은 [iiGUI 버튼과 교체 가능한 색상 공급자](NativeColorPickerButton.md)를
  사용한다. 실제 플랫폼 표시 검증은 별도로 남아 있다.

## 아직 남은 전환

이전 `FRAMEWORK LVRS` 생성 코드와 LVRS 소스를 읽는 선택적 CMake 검사 경로를
제거했다. 컴파일러 API·CLI·CMake에서 해당 프레임워크를 명시하면 오류로
진단한다. `lvrs::` 타입이나 `LVRS/Widgets.h`를 생성하는 코드도 제거했다.
레거시 조사 도구와 과거 문서는 역사적 자료이며 현재 빌드·검사의 입력이 아니다.

2026-10-29 macOS에서 전역 SDK 헤더·라이브러리 검색 경로를 제거하고 LVRS와
Qt의 CMake 패키지 탐색을 비활성화한 환경으로 설치 소비자를 확인했다. 기본 구성과
선택적 색상 어댑터 구성 각각의 공개 헤더 174개와 CMake 설정, 기본 구성의 생성
헤더 53개 및 색상 구성의 생성 헤더 3개에는 LVRS 타입·헤더나 Qt 헤더가 없었다.
정적 탭 슬롯 소비자와 색상 어댑터 소비자는 각각 컴파일·링크했으며, 두 바이너리의
직접 연결 목록과 공개 심볼에서 LVRS·Qt를 확인하지 못했다. 창이나 앱은 실행하지 않았다.
전역 검색 경로는 제거했지만 시스템에서 레거시 소스와 설치본 자체의 접근을 차단한
완전 클린 환경은 아직 검증하지 않았다. 이는 해당 환경·구성의 증거이며 다른 플랫폼의
동작이나 모든 기능의 이전을 뜻하지 않는다.

기본 구성의 자동 검사는 최초 522건 중 520건이 통과했고 저장장치 지연으로 시간
초과된 2건은 순차 재실행에서 통과했다. 색상 어댑터와 갱신된 언어 예시를 포함한
추가 검사 18건도 통과했다. 실행을 요청받지 않은 예제 애플리케이션은 검사에서 제외했다.
이 수치는 레거시 경로 전용 회귀를 제거한 현재 등록분이며,
제거된 기능이 독립 구현으로 이식되었다는 뜻은 아니다.

이번 창 강조 색·버튼 설정·계층 개수 View 변경 후에는 자동 검사 525건 중
524건이 첫 실행에서 통과했다. 패키지 경계 검사는 시간 초과 후 단독 재실행에서
한 번 실패했고 이후 세 차례 연속 통과했다. 실패는 재현되지 않아 원인을 확정하지
못했다. 추가 기능과 조합을 다루는 검사 13건, 설치 패키지를 사용하는 두 소비자
프로그램의 컴파일·링크와 직접 의존성 검사는 통과했다. 실제 GUI 애플리케이션은
실행하지 않았다.

생성된 창 강조 색과 계층 개수 View의 통합 검사는 iiGUI 개발 패키지와
`LVUI_BUILD_STYLE_EXAMPLE=ON` 설정이 있어야 등록된다. 해당 설정으로
`LVUIWindowAccentGeneratedTests`, `LVUIHierarchyCountViewGeneratedTests`를 빌드한 뒤
`LVUI.Window.AccentGenerated`, `LVUI.OwnedHierarchyItem.CountViewGenerated` 검사를
실행한다. 이 두 검사는 실제 창을 열지 않는다.

컴파일 타입 검사는 LVUI가 빌드 시 생성하는 자체 아이콘 헤더 경로를 직접 사용한다.
설치 소비자 검사는 개발자의 전역 SDK 검색 경로에 기대지 않으며, 임시 설치의
manifest를 분리해 기존 빌드의 설치 기록을 보존한다.

창 `accent`는 LVUI 소유 타입과 스타일 값으로 구현되어 호스트, 기본 버튼·재질과
입력·선택·메뉴·링크 컨트롤 일부에 반영된다. 기본 버튼은 폭·글꼴 크기·선·상태별 색상도 선언할 수 있다. 실제로
지원하는 입력과 상속 범위는 [Window 계약](NativeWindow.md)과
[버튼 계약](NativeButton.md)을 따른다.

독립 `HierarchyItem`의 `countView`는 단일 사용자 View와 반응형 내용, 재사용 View
전달을 지원한다. [행 계약](NativeOwnedHierarchyItem.md)에 표시·수명과 데이터 전달
범위를 명시한다. 기존 LVRS 네이티브 구현의 모든 기능이 이전된 것은 아니다.
계층 목록과 패널은 `countRow`를 통해 생성 행의 사용자 개수 View에 행 데이터를
제공하고 `itemDelegate`와 `itemRow`로 기본 행 콘텐츠를 교체한다.
이전 경로 전용 컴파일러 회귀는 독립 위젯
검사와 구분해 등록을 중단했다.
복제와 리팩터링은 허용된 이전 방법이다. 공개 타입·생성 코드·자산·빌드·링크와
설치 소비자까지 확인하기 전에는 완전한 검증을 주장하지 않는다.

개별 교체는 외부 SDK 공개 타입을 LVUI 코어의 필수 API에 추가하지 않고 앱에서
주입하는 호스트 경계를 사용한다. 각 교체마다 디자인 값, 오류·상태·수명과
접근성을 명시하고, LVRS 소스와 설치본이 없는 구성 및 생성 코드 소비자를 검증한다.
미구현 입력을 조용히 무시하거나 이전 회귀 결과를 새 구현의 실행 증거로 사용하지 않는다.

Windows는 iiGUI의 MSAA 기본 접근성 경로를 사용한다. Linux는 iiGUI의 기본
AT-SPI 역할·동작, 일부 텍스트와 숫자 값 전달을 사용한다. 추가 UI Automation
패턴, AT-SPI의 나머지 기능과 실제 스크린 리더 확인은 아직 남아 있다. 지원·검사
범위는 [iiGUI 접근성 계약](../../iiGUI/docs/AccessibilitySemantics.md)을 따른다.
새 iiGUI와 LVUI의 Windows x64 설치 스테이징을 사용해 입력 필드와 버튼을 가진
선언형 `Application`을 생성하고 교차 링크했다. 생성 실행 파일과 확인 가능한
비시스템 DLL 세 개의 선언된 연결에서 Qt·QML·LVRS 이름은 발견되지 않았다.
Windows 시스템 DLL, 실행 중 선택되는 플러그인·드라이버 및 실제 앱 실행은 이
확인 범위 밖이며, Vulkan은 공식 내보내기 정의로 만든 임시 import 라이브러리로
링크했다.

Wayland 조합 입력은 iiGUI의 `text-input-v3` 호스트 소스에 연결했다. 실제
Wayland 위젯 표면과 모의 연결을 사용한 헤드리스 검사에서 LVUI 소유 입력 필드와
코드 편집기의 한글·이모지 조합, 선택 대체, 주변 삭제와 실행 취소를 확인했다.
조합 커서 숨김과 선택 양 끝의 순서도 같은 경로에서 표시 모델까지 유지한다.
호스트 소스의 Linux aarch64 교차 컴파일도 통과했다. 실제 Linux compositor와
IME의 조합이나 완전한 Linux 링크·실행은 아직 검증하지 않았다.
