# 조건에 따라 활성화하는 View

조건부 뷰는 Bool 조건과 각 분기의 단일 루트 View로 구성한다.

```lvui
import document Backend
Window {
    VStack {
        if (document.ready) {
            Label(text: document.title)
        } else {
            Label(text: "Waiting")
        }
    }
}
```

분기에는 지원하는 LVUI 네이티브 뷰 또는 선언한 고정 View 값을 사용한다.
`else`는 생략할 수 있고 `else if`로 연결할 수 있다. 분기에 여러 뷰를 넣으려면 명시적인
스택으로 묶는다. 루트 창 자체를 조건부로 생성하는 대신 창 안의 콘텐츠를 조건부로 둔다.

각 분기의 중괄호 안에 `import`, `const`, `var`와 재사용 `View`·`[View]`를 선언할
수 있다. 선언은 그 분기에서만 유효하고 루트 View는 여전히 정확히 하나여야 한다.
메뉴와 탭의 분기는 루트로 해당 컴포넌트 묶음을 사용할 수도 있다.

```lvui
if (document.ready) {
    import details DetailsModel
    const title: String = details.title
    const Heading: View = Label(text: title)
    Heading()
} else {
    const title: String = "Waiting"
    Label(text: title)
}
```

분기 안쪽의 View가 같은 이름을 선언하면 분기 이름을 가린다. 분기의 값은 다른 분기나
다음 형제에서 접근할 수 없고 조건식을 평가하기 전에는 존재하지 않으므로 조건식에도
사용할 수 없다. `View` 이름은 사용하기 전에 선언한다. 중복 이름, 루트가 없거나 두 개인
분기는 오류다. 조건이 이미 선택한 분기와 같으면 지역 객체와 위젯을 재생성하지 않는다.

AOT는 네이티브 `content_host`와 두 C++ 구성 함수를 생성한다. 조건의 실제 의존 값이
바뀔 때만 계산하고, Bool 결과가 그대로이면 기존 세대·지역 import를 유지한다. 분기가
바뀌면 후보 세대를 구성·검증한 뒤 교체한다. 후보 구성이 실패하면 기존 콘텐츠를 보존한다.
미선택 분기의 지역 백엔드를 미리 생성하지 않는다. 새로 선택한 지역은 새 활성화를 가진다.

새 사용을 막고 구독을 분리한 뒤 이전 세대를 퇴역한다. 없어진 분기를 그린다고 전체 파일
백엔드를 재시작하거나 LVUI 소스를 해석하지 않는다. 가져온 C++ 객체의 자체 작업 수명은
별도의 Core 계약을 따라야 한다.

분기 호스트의 초기 높이를 더미 숫자로 고정하지 않는다. 선택한 자식의 자연 높이를 사용하며,
빈 분기는 높이 0이다. 자식이 크기를 바꾸면 부모의 측정을 갱신한다. 독립 콘텐츠 활성화의
기존 깊이·노드 한계와 잘못된 구성의 오류 계약도 유지한다.

분기가 없거나 선택한 루트가 숨겨지면 분기 호스트는 주변 스택의 자식 간격·입력·접근성
노출에서도 빠진다. 분기 제거로 포커스 경로가 사라지면 포커스를 해제하며, 다시 활성화해도
이전 포커스를 임의로 복원하지 않는다. 루트가 일반 스택이라면 그 스택 자체의 `visible`
상태를 기준으로 한다. 자식이 모두 숨겨졌다고 사용자 스택을 임의로 제거하지는 않는다.
이는 화면 배치 상태이며 앱 문서의 리비전을 수정하지 않는다.

현재 검사는 구문·C++ 생성·생성한 실제 C++의 컴파일·지역 값 실행을 포함한다.
iiGUI의 `native_conditional` 검사는 실제 생성한 구성 함수를 위젯 세대에 연결하여 분기 전환,
변경 없는 정체성, 자연 높이, 생성 실패 시 기존 콘텐츠 보존, 복구와 지역 객체 파괴를 실행한다.
`LVUI.ConditionalSpacing.Generated`는 실제 생성한 위젯에서 분기 제거·복구 전후의 스택
간격과 포커스, `else` 후보 실패 시 기존 분기 보존과 복구, 문서 리비전 불변을 창 없이
확인한다. `LVUI.OwnedMenu.Conditional`은 일반 뷰·메뉴·탭에서 분기 지역 백엔드와
값의 생성·관찰·퇴역, 지역 이름 가리기와 실패 복구를 검사한다. 같은 검사는 메뉴의
지역 `[View]` 묶음 안에서 중첩 조건을 교체하고, `LVUI.OwnedMenu.Repeated`는 반복
행마다 분기 지역 바인딩이 독립적으로 갱신되는지 검사한다.
이 검사는 창·표면·렌더러를 만들지 않는다. 실제 창에서의 포커스·입력·그리기와 플랫폼별
표시 검증은 최종 통합 단계까지 별도로 남겨 둔다.
