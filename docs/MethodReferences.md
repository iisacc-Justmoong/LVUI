# 메서드 참조·호출과 컴포넌트 콜백

상태: 2026-10-20에 채택한 LVUI 언어 설계이다. 이 규칙은 AOT로 컴파일되는
컴포넌트 언어에 속한다. 현재 LVUI 0.1 파서는 이를 구현하지 않는다.

<a id="references-and-calls"></a>

## 참조와 호출

| 표현식 | 평가 시 의미 |
|---|---|
| `vm.increment` | 기존 `vm` 수신 객체에 연결된 메서드 참조를 만든다. 메서드는 호출하지 않는다. |
| `vm.increment()` | 지금 메서드를 호출하고 선언된 결과를 얻는다. |
| `PushButton(vm.increment)` | 연결된 메서드 참조를 컴포넌트의 첫 번째 인자로 전달한다. 해당 callable의 허용 여부는 입력 계약으로 결정한다. |
| `PushButton(vm.increment())` | 즉시 호출 결과를 컴포넌트의 첫 번째 인자로 사용한다. 결과를 입력 계약에 따라 검사한다. |

메서드 표현식에 괄호를 붙이면 호출을 뜻한다. 참조를 전달하거나 읽거나 다시 평가하는 것만으로
암묵적인 호출이 발생하지 않는다. 메서드 참조는 수신 객체의 정체성을 유지하며,
참조를 만드는 과정에서 새 VM을 생성하거나 상태를 복사하지 않는다.

즉시 호출은 네이티브 애플리케이션 실행 중 표현식을 평가하는 시점에 호출을 시작한다는 뜻이다.
컴포넌트 이벤트까지 연기하지 않는다. AOT 컴파일 중 표현식을 분석하는 것 자체로
런타임 VM의 메서드를 실행하지 않는다. 완료 시점은 호출 대상 작업에 선언된
동기·비동기 및 실행 영역 계약을 따른다.

<a id="component-owned-callback-semantics"></a>

## 컴포넌트가 소유하는 콜백 의미

언어는 일반적인 멤버 접근, 호출 가능한 값, 호출 표현식, 인자 전달을 제공한다.
컴포넌트 인터페이스는 매개변수 타입을 선언하고,
구현은 전달받은 콜백을 언제 호출할지 결정한다.

현재 버튼 예제의 `PushButton` 인터페이스는 다음 계약을 가정한다.

| 계약 항목 | 예제의 요구사항 |
|---|---|
| 첫 번째 위치 인자 | 인자와 반환값이 없는 콜백이다. |
| 호출 계기 | 버튼 구현이 허용된 클릭에 대해 해당 콜백을 호출한다. |
| 생성 시 동작 | 콜백을 전달받는 것만으로는 호출하지 않는다. |

이는 예제의 인터페이스 의미이며, 콜백 타입 표기나 컴포넌트 정의 문법을 확정한 것은 아니다.
이미 구현된 iiGUI 컨트롤 API를 설명하는 것도 아니다.

이 계약에 따라 컴포넌트는 나중에 호출할 `vm.increment`를 저장한다.
파서는 해당 표현식을 클릭 처리기로 해석하지 않는다.
다른 컴포넌트도 같은 callable을 받아 자신의 계약에 따라 호출할 수 있다.
모든 컴포넌트의 첫 번째 인자가 자동으로 이벤트 콜백이 되는 것은 아니다.

예를 들어 사용자 정의 `CustomControl`이 호환되는 콜백을 첫 번째 입력으로 선언하면
같은 인자 구문을 사용할 수 있다.

```text
CustomControl(vm.increment)
```

이벤트의 의미는 해당 컴포넌트의 인터페이스와 구현이 정한다.
언어 문법에 컨트롤별 새 규칙을 추가할 필요는 없다.

<a id="type-checking-and-returned-callables"></a>

## 타입 검사와 반환되는 callable

AOT 타입 검사기는 멤버와 수신 객체를 확인하고 호환되는 오버로드를 선택한 뒤,
전달한 인자를 컴포넌트가 선언한 입력 타입에 따라 검사한다.
callable의 인자·결과 계약은 해당 입력과 호환되어야 한다.
일반적인 C++ 접근 제한과 constness도 계속 적용된다.

`increment()`가 인자와 반환값이 없다고 가정한다.
메서드 참조는 예제의 콜백 계약을 충족할 수 있지만 호출 결과는 충족할 수 없다.
따라서 이 가정에서 `PushButton(vm.increment())`는 컴파일 타임 타입 오류이다.
유효하지 않은 프로그램의 오류를 진단하는 과정에서 메서드를 실행하지 않는다.

다른 메서드는 호환되는 callable을 반환할 수 있다.
이 경우 `PushButton(vm.makeHandler())` 같은 표현식은 유효할 수 있다.
인자를 평가할 때 `makeHandler()`를 평가하고 반환된 callable을 컴포넌트에 전달한다.
콜백 인자 위치에 있다는 이유만으로 호출 구문을 거부해서는 안 된다.
호환 여부는 결과 타입으로 결정한다.

정확한 callable 타입 표기, 변환 규칙, 오버로드 진단, 네이티브 callable 표현은 추가 명세가 필요하다.
컴파일러는 컴포넌트 이름·멤버 이름·인자 위치만으로 추측하지 않고,
해당 컴포넌트 인터페이스를 확보해야 한다.

<a id="aot-execution-and-query-integration"></a>

## AOT 실행과 쿼리 연동

컴파일러는 메서드 참조, 명시적 호출, 컴포넌트 콜백 매개변수를 네이티브 코드로 생성한다.
이벤트 동작은 컴포넌트의 컴파일된 구현이 소유한다.
버튼 동작을 인식하기 위한 소스 인터프리터나 런타임 표현식 평가기는 없다.

[VM 쿼리 연동](ViewModelQueries.md)에서 메서드 참조를 생성하거나 전달하는 것은
메서드 호출 쿼리를 발행하지 않는다. 콜백을 호출할 때 해당 쿼리를 시작할 수 있다.
명시적 호출 표현식은 평가 시 호출을 시작하며, 같은 실행·결과 전달 규칙을 따른다.

[기본 반응형 값 모델](ReactiveState.md)은 메서드 호출과 독립적이다.
정적 값이 아닌 상태를 읽으면 필요한 실시간 값 바인딩을 설정한다.
메서드에 접근하면 명령을 실행하는 대신 callable을 얻는다.
의존성 갱신은 메서드 참조를 암묵적으로 호출하지 않는다.

<a id="receiver-lifetime"></a>

## 수신 객체의 수명

연결된 메서드 참조는 기존의 가져온 수신 객체를 사용한다.
저장되어 나중에 호출될 수 있는 callable은 수신 객체의
[스코프 수명](InvocationLifecycle.md)을 따르는 미래 사용 경로이다.
소유권을 이전하거나 암묵적으로 VM의 수명을 늘리지 않는다.

소유 스코프가 닫히면 콜백 접수와 연결을 종료한다.
활성 호출과 캡처는 파괴 전에 모두 종료되어야 한다.
마운트 해제 이후나 늦은 비동기 전달을 포함하여,
컴포넌트는 사용이 종료된 수신 객체를 통해 콜백을 호출해서는 안 된다.

<a id="future-implementation-validation"></a>

## 향후 구현 검증

- 예제 버튼에 메서드 참조를 전달해도 컴포넌트 생성·레이아웃·참조 재평가 중에는 호출하지 않는다.
- 허용된 버튼 클릭은 기존 VM에서 전달받은 콜백을 호출한다.
- 유효한 명시적 메서드 호출은 표현식을 평가할 때 시작한다.
- 예제의 콜백이 필요한 위치에서 반환값 없는 호출 결과는 거부한다.
- 명시적 호출이 반환한 호환 가능한 callable은 인자로 전달할 수 있다.
- 사용자 정의 컴포넌트는 같은 일반 구문으로 호환되는 콜백을 받고 자체 호출 계기를 사용한다.
- 스코프 종료 후 콜백은 사용이 종료된 수신 객체에 접근할 수 없다.

이는 향후 컴파일러·컴포넌트의 수용 기준이며, 테스트 통과 결과가 아니다.

<a id="open-questions"></a>

## 미정 사항

- 컴포넌트 인터페이스 선언 구문과 빌드 시 인터페이스 탐색.
- callable 타입 표기, 네이티브 표현, 인자·결과 변환.
- 모호한 메서드 참조의 오버로드 선택과 진단.
- 클로저·캡처·부분 적용과 인자가 있는 콜백.
- 평가 순서, 반응형 문맥의 효과 제한, 콜백 오류.
