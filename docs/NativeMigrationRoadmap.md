# LVUI 네이티브 이전 우선순위 — 2026-10-29

## 목표와 이전 기준

LVUI는 `.lvui` 형식의 선언을 작성하고 iiGUI를 통해 운영체제에 맞춘 위젯을
그리는 선언형 UI 언어이다. 채택된 경로는 `.lvui`를 빌드 시 네이티브 C++로
생성하고, LVUI 소유 컴포넌트와 앱이 조합한 iiGUI 호스트를 통해 각 운영체제의
표면·입력·텍스트·접근성을 연결한다. LVUI는 LVRS의 시각 언어, 스타일과 디자인
파라미터를 계승한다.

2026-10-29 사용자는 LVRS에 이미 있는 iiGUI 기반 네이티브 C++ 구현을 LVUI로
**복제·리팩터링하는 방법을 명확히 허용했다.** 기존 네이티브 소스·헤더·테스트·
자산을 이전 대상으로 삼고, 이미 작성한 LVUI 구현과 비교해 통합한다. 이전한
코드는 LVUI의 소유 코드가 된다. LVUI는 완성 시 LVRS 저장소·설치본·공개 타입·
라이브러리와 Qt/QML을 빌드, 코드 생성, 링크 또는 실행에 필요로 하지 않는다.
LVRS와의 연결을 남긴 채 이름만 변경한 상태나 복제만 한 상태는 완료가 아니다.

iiGUI와 필요한 플랫폼 서비스는 앱이 조합할 수 있게 경계를 유지한다. LVUI 코어의
공개 계약은 상위 모듈을 참조하지 않으며, 교체 가능한 인터페이스와 SDK 간 의존성
규칙을 따른다. 현재 패키지의 실제 의존성은 조사 결과로 기록하고, 이전 과정에서
이미 해결된 것으로 가정하지 않는다.

이 문서는 작업 재개 시의 순서이다. 문서 작성은 이전 작업·제품 실행·설치를
재개하거나 완료했다는 뜻이 아니다. 중단 시점의 구현과 검증은
[기존 작업 기록](IndependenceWorkSnapshot-2026-10-29.md)에 보존한다.

## 2026-10-29 독립 경로 전환 상태

이후 사용자의 요청에 따라 `FRAMEWORK LVRS` 코드 생성과 LVRS 소스를 읽는
선택적 CMake 검사 경로를 제거했다. 컴파일러 API·CLI·CMake에서 레거시 선택을
거부한다. 레거시 분기 제거 직후, 정적 탭 조합을 추가하기 전의 기본 `.lvui`
예제 163개는 변경 전후 생성 결과와 진단이 일치했다. 대표 독립 생성과 CLI의
레거시 거부 검사는 통과했다. 전역 LVRS 검색 경로를 제거한 설치 소비자에서
53개 화면의 헤더를 생성하고 정적 탭 슬롯 소비자를 컴파일·링크했다. 색상 어댑터를
포함한 별도 설치 소비자도 컴파일·링크했다. 두 구성의 생성 헤더와 패키지 공개
헤더·CMake 파일, 소비자 바이너리의 직접 링크에는 LVRS·Qt 참조가 없었다.
기본 구성의 자동 검사는 522건 중 최초 520건이 통과했고, 시간 초과 2건은 순차
재실행에서 통과했다. 색상과 언어 관련 추가 검사 18건도 통과했다. 예제 애플리케이션
실행은 제외했다. 레거시 소스와 설치본에 대한 접근 자체를 차단한 클린 환경과 다른
운영체제의 검증은 아직 남아 있다.

독립 `HierarchyItem`의 `countView`와 창 `accent`는 이후 LVUI 자체 구현으로
연결했다. 계층 목록의 `itemDelegate`와 목록 행의 사용자 개수 View 등은 여전히
지원하지 않는다. 창 강조색은 호스트와 기본 버튼에 반영된다. 레거시 경로 전용 회귀의 등록을 중단했으며,
이 기능들을 완료로 간주하지 않고 아래 위젯 이전·기능 보완에 포함한다.
정적인 재사용 `View`와 `[View]` 슬롯의 탭은 LVUI 소유 탭 묶음으로 연결하고
생성 C++의 선택·콜백·반응형 입력·수명을 창 없는 위젯 검사로 확인했다.

## 확인된 출발점

- LVRS의 [네이티브 CMake 구성](../../LVRS/cmake/LVRSNative.cmake)은
  `src/LVRS/`의 테마·위젯·입력·표·계층·목록·카드·코드 편집기 등을 iiGUI 기반
  C++ 라이브러리로 묶는다. 실제 이전 범위는 소스·공개 헤더·테스트·자산을
  조사하여 확정한다.
- LVRS 네이티브 아이콘 생성은 현재 [아이콘 생성 도구](../../LVRS/tools/embed_native_icons.py)가
  `src/qml/Theme.qml`의 별칭을 읽는다. 이는 QML 엔진의 실행 의존성은 아니지만
  **QML 파일에 대한 빌드 입력 의존성**이다. LVUI로 옮길 때 별칭 데이터를 LVUI
  소유 자산으로 분리해야 한다.
- 중단 당시 LVUI에는 자체 컴포넌트와 `.lvui` 생성 경로 외에 LVRS 타입과
  팩터리를 생성하는 경로가 있었다. 해당 경로는 이후 제거되었다.
  [독립 구현 현황](LVUIIndependence.md)의 현재 지원과 미완성 범위를 함께 본다.
- 중단 당시 macOS 전체 빌드와 목록·메뉴 집중 검사 28개가 통과했다. 그 시점에는
  최신 소스의 전체 회귀와 독립 소비자 링크를 확인하지 못했다. 이후 결과는 위의
  독립 경로 전환 상태에 별도로 기록한다.

## P0 — 이전 범위와 현재 기준선을 확정한다

1. LVRS 네이티브 타깃의 소스·헤더·공개 타입·CMake 구성, 생성 자산·리소스와
   관련 테스트를 목록화한다. 각 항목의 iiGUI·다른 SDK·플랫폼·LVRS·Qt/QML
   연결과 소유 위치를 함께 기록한다.
2. 같은 기능의 현재 LVUI 구현과 `.lvui` 입력·이벤트를 대조해 `LVUI에 있음`,
   `LVRS 네이티브에서 이전`, `양쪽에 있어 통합 필요`, `아직 구현 필요`로
   분류한다. 컴포넌트별 공개 계약과 검사 근거를 연결한다.
3. 사용자와 다른 작업의 기존 변경을 보존하고, 이전 대상 충돌을 확인한다.
   작업을 재개하면 현재 소스의 전체 빌드·관련 검사와 독립 소비자 검증을
   기준선으로 기록한다.

**완료 조건:** 이전할 코드와 자산, 재사용할 LVUI 코드, 실제 누락 기능과 각
의존성 제거 방법을 확인할 수 있다. 파일 수나 예약어 수를 구현 완료로 취급하지
않는다.

## P1 — 공통 기반과 자산을 LVUI 소유로 옮긴다

1. LVRS의 네이티브 공통 값·테마·배치·그리기·입력·모션 구현을 기능별로
   복제·리팩터링한다. 기존 LVUI 모델이 같은 책임을 갖는 경우 계약과 동작을
   비교해 한 구현으로 통합하고 기존 개선과 테스트를 보존한다.
2. 필요한 SVG·이미지·글꼴과 생성 입력을 LVUI `resources/`에 두고 LVUI의 생성
   도구와 빌드 설정으로 연결한다. `Theme.qml`에서 읽던 아이콘 별칭은 LVUI 소유
   데이터로 옮겨 QML 파일 없이 생성한다.
3. 소스와 헤더, 네임스페이스·공개 타입·자산 경로와 오류 처리를 LVUI 소유로
   정리한다. iiGUI의 범용 위젯 표면과 플랫폼 서비스를 연결하되 앱에 제공하는
   인터페이스와 호스트의 책임을 분리한다.

**완료 조건:** 공통 기반을 LVRS 체크아웃과 QML 파일 없이 빌드할 수 있고,
디자인 값·입력·상태·자산에 대한 해당 기능의 검사가 LVUI에서 유지된다.

## P2 — 네이티브 위젯과 복합 컴포넌트를 이전한다

1. 버튼·입력·메뉴·선택 컨트롤·팝업·모달·시트·색상·재질·이미지 등 기본
   위젯을 이전하고, 레이아웃·상태·이벤트·수명과 디자인 파라미터를 보존한다.
2. 목록·계층·도구 모음·푸터·표·카드·내비게이션·코드 편집기와 그 데이터
   모델·편집 경계를 이전한다. 사용자 콘텐츠와 교체 가능한 데이터 공급자도
   각 컴포넌트의 계약에 포함한다.
3. 이전한 기능의 C++ 사용과 `.lvui` 생성 경로를 함께 연결하고, 원본 및 기존
   LVUI 검사에서 필요한 사례를 LVUI 소유 테스트로 옮긴다. 선택·스크롤 같은
   화면 상태와 문서 편집 상태를 분리한다.

**완료 조건:** P0 목록의 LVRS 네이티브 구성요소별 이전·통합 상태가 확인되고,
해당 기능이 LVUI 코드와 자산으로 구성된다. 원본 네이티브 구현에 없거나
미완성인 기능은 별도로 표시한다.

## P3 — 선언형 생성 경로를 통합하고 LVRS 연결을 제거한다

1. `.lvui` 컴파일러가 이전한 LVUI 위젯·모델·이벤트를 생성하도록 연결한다.
   기존 LVUI의 타입·반응형 값·스코프·호출 수명 계약을 유지한다.
2. **현재 지원 경로에서 완료:** `FRAMEWORK LVRS` / `--framework LVRS`,
   `LVRS/Widgets.h`와 `lvrs::` 팩터리 생성, LVRS 전용 패키지 탐색과 연결을
   제거했다. 기존 선택값은 명확한 진단으로 거부한다.
3. **현재 빌드·검사 경로에서 완료:** 레거시 소스 조사·계약 검사와 예제는
   LVUI 소유 자료와 검사로 이전하거나
   현재 빌드·검사 경로에서 분리한다. 과거 기록과 디자인 식별자는 이력으로
   보존할 수 있지만 필수 빌드 입력이 되어서는 안 된다.

**완료 조건:** 공개 헤더·CMake·컴파일러·생성 코드·테스트·설치 패키지의 지원
경로가 LVRS와 Qt/QML에 연결되지 않으며, `.lvui` 선언이 LVUI 소유 위젯을 생성한다.

## P4 — 기능 차이와 운영체제별 위젯 연결을 완성한다

1. P0 비교표를 기준으로 아직 없는 복합 목록 항목과 사용자 슬롯, 계층 행 대리자,
   표 병합·편집 UI·셀 접근성, 카드 세부 표현과 코드 편집 기능 등을 채운다.
   LVRS 네이티브 구현에 이미 있는 기능은 이전을 우선한다.
2. 메뉴의 동적 자식, 포커스·키보드·IME·Unicode, 입력 취소, 모션과 상태 변경,
   콜백 중 제거와 비동기 작업 종료 등 선언된 LVUI 동작의 누락을 보완한다.
3. iiGUI의 각 운영체제별 표면·텍스트·입력·접근성 연결을 점검한다. 현재
   Windows·Linux 입력 경로와 Android·웹 편집용 글자 배치 등은 별도 확인이
   필요하며, 운영체제별 그리기와 디자인 파라미터를 LVUI 선언에서 사용할 수 있게
   연결한다.

**완료 조건:** 지원하기로 한 `.lvui` 선언과 위젯 계약의 미완성 항목이 해결된다.
지원 범위 밖의 선언은 명확하게 진단하고, 플랫폼별 구현 범위와 실제 검증 범위를
구분한다.

## P5 — 독립 패키지와 전체 회귀를 검증한다

1. 소스 변경마다 관련 테스트와 사람용 Markdown·에이전트 JSON을 함께 갱신하고,
   `build/`에서 빌드와 자동 검사를 수행한다. 최종 상태에서 전체 회귀와 필요한
   선택 구성을 확인한다.
2. LVRS·Qt 패키지 검색을 끄고 해당 소스·헤더·라이브러리가 제공되지 않는
   독립 환경에서 LVUI를 빌드·설치 스테이징한다. 재배치된 외부 소비자가 `.lvui`를
   생성하고 컴파일·링크할 수 있는지 확인한다.
3. 공개 헤더·생성 코드·CMake 메타데이터, 정적 심볼과 최종 바이너리의 연결을
   점검한다. 빌드 도구의 QML 파일 읽기와 전이 의존성도 확인하며, 단순 문자열
   검색이나 기본 경로 하나의 성공만으로 전체 독립을 선언하지 않는다.
4. 운영체제별 빌드·링크, 실제 창·입력·렌더링, 기기·접근성 결과를 각각
   기록한다. 실제 앱이나 기기 실행은 사용자가 실행 검증을 명시적으로 요청할
   때 수행하며, 실행하지 않은 항목을 통과로 표시하지 않는다.

**완료 조건:** 최신 소스와 설치 패키지의 자동 검사 및 독립 소비자 검증이
통과하고, 기능·플랫폼별 미검증 범위가 명확하다. 이전 LVRS 구현의 코드가
LVUI에 존재하는 것과 LVRS 모듈에 의존하는 것을 혼동하지 않는다.
