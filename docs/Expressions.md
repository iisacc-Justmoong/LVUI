# 값 표현식과 상수 AOT 계산

LVUI 컴포넌트 프런트엔드는 단항·이항·조건식, 묶음, 인덱스 및 후위 멤버·호출을
위치가 있는 AST로 보관한다. 이 문서는 현재의 실제 구현과 남은 네이티브 반응형 생성
범위를 구분한다. 언어·모듈 전체의 완료 기준은 [Completion.md](Completion.md)에 있다.

## 구문과 우선순위

높은 우선순위부터 다음과 같다. 이항 연산은 왼쪽, 조건 연산은 오른쪽으로 결합한다.

| 구문 | 의미 |
|---|---|
| `()`, `a[i]`, `a.member`, `a.method()` | 묶음과 후위 접근·호출 |
| `!`, 단항 `+`, 단항 `-` | 불리언 부정과 숫자 부호 |
| `*`, `/`, `%` | 수치 곱·나눗셈·나머지 |
| `+`, `-` | 수치 연산 또는 String끼리의 연결 |
| `<`, `<=`, `>`, `>=` | 수치 또는 String 순서 비교 |
| `==`, `!=` | 호환 타입의 값 비교 |
| `&&`, `||` | Bool 논리 연산 |
| `condition ? accepted : rejected` | Bool 조건과 호환 타입의 두 분기 |

`===`와 `!==`는 JavaScript 호환 연산자로 가져오지 않는다. LVUI의 비교는 값 타입의
계약을 따르며 숫자와 문자열을 암시적으로 같은 값으로 취급하지 않는다.

```lvui
@Static let gap: Metric = .space4 + 2
let title: String = true ? "Dense " + "tools" : "Other"
Window(width: 640 + 80) {
    VStack(spacing: gap) {
        Label(text: title)
        PushButton(text: "Run", enabled: 3 * 4 >= 12)
    }
}
```

줄바꿈은 연산자 뒤, 괄호·목록·호출 인자 안에서 사용할 수 있다. 연산자 앞의 줄바꿈을
임의로 다음 문장과 합치지 않는다. 문장 종결용 세미콜론은 계속 허용하지 않는다.

## 현재 상수 계산 계약

`LVUI/ConstantExpression.h`의 `fold_constant_expression`은 컴파일 단계의 API이다.
컴파일러가 이미 알고 있는 선언과 스타일 값을 resolver로 공급하며, 가져온 C++ 객체나
메서드를 실행하지 않는다. 생성된 네이티브 위젯 코드는 이 evaluator나 AST를 참조하지 않는다.

- 논리 연산과 조건식은 값 계산을 단락 평가한다. 비활성 숫자 분기의 0 나누기는 실행하지 않는다.
- 조건과 논리 피연산자는 Bool이어야 한다. 두 조건 분기는 호환 타입이어야 한다.
- 활성 계산의 0 나누기·나머지와 비유한 수치 결과는 원본 위치의 진단으로 반환한다.
- String 연결 결과는 1 MiB를 넘을 수 없다.
- 상수 목록 인덱스는 유한한 비음수 정수이며 목록 범위 안이어야 한다.
- Metric끼리의 나눗셈은 비율 Number이다. Metric 제곱·역수처럼 지원하지 않는 차원은 거부한다.
- 표현식 깊이는 64, 계산 대상 AST는 65,536 노드로 제한한다. 기존 입력·토큰·View 한계도 유지한다.

## 어노테이션과 구현 경계

`@Observable`과 `@Static`은 선언 앞에서 파싱한다. `@Observable`은 이미 기본인 반응성을
명시하며 추가 인스턴스를 생성하지 않는다. `@Static`은 고정 값이므로 불변 `let`에만
사용한다. 중복·충돌·미확인 어노테이션과 선언이 아닌 곳의 사용은 진단한다.

현재 AOT는 상수 계산 외에 C++ 속성의 산술·비교·논리·조건식과 동적 인덱스,
메서드 호출 결과를 네이티브 getter로 생성한다. `let`의 파생값은 읽기 전용이며
원본 변경을 따라간다. `@Static let initial = vm.value`는 활성화마다 한 번 소유 값을
복사하고 이후 변경을 따르지 않는다. 같은 활성화의 값 초기화는 중복 수행하지 않는다.

`vm.method`는 지연 메서드 참조이다. `vm.method()`는 getter의 실제 평가 때 호출하며,
반응형 getter에서 사용하는 메서드는 표시를 위한 읽기 작업이어야 한다. 임의의 C++ 메서드
본문을 분석하여 그 안의 모든 의존성을 추측하지 않는다. 객체의 변경 발행 계약을 사용한다.

일반 공개 멤버는 생성 스코프의 변경 버전을 구독한다. 바인딩된 메서드 실행 후 버전을
발행하며, 외부 작업에서 직접 바꿀 때에는 소유 UI 스레드에서 같은 변경을 발행해야 한다.
Core Observable 멤버는 자체 속성 변경만 구독한다. [NativeBindings.md](NativeBindings.md)를 참조한다.

`vm.document.title` 같은 C++ 멤버 경로는 공개 멤버를 직접 선택하는 타입 있는 C++로 생성한다.
객체·공유/고유 포인터·원시 포인터를 따라가며, 중간 객체의 변경 버전과 관찰 가능한 최종 값을
추적한다. 중간 객체가 바뀌면 이전 최종 값의 연결을 해제한다. null 경로는 마지막 성공 값을
보존하는 실패이며 다음 유효한 변경에서 복구한다. private·const 접근을 우회하지 않는다.
소유 스코프의 모델 별칭은 네이티브 데이터 입력에도 사용할 수 있다. 수명이 고정되어야 하는
서비스 입력은 계속 멤버/별칭 참조를 요구하며 임의 호출 결과를 서비스로 보관하지 않는다.

중첩 선언·동적 뷰 구성·후위 메서드 호출 전체와 모든 컴포넌트 입력의 갱신은 완료된
범위가 아니다. 구문 분석이나 일부 getter의 성공을 언어 전체 완료로 간주하지 않는다.

## 검사

`LVUI.Expressions.*`는 우선순위, 단락 평가와 타입 오류, 후위 AST, 어노테이션,
위치 진단·한계 및 상수 AOT 출력을 검사한다. 생성 문자열 검사와 생성 C++의 실제
컴파일·위젯 실행 증거는 구분한다. `LVUI.NativeGenerated`는 실제 생성한 C++를 컴파일·링크하고,
UI 호스트 없이 파생값·분기·인덱스 오류와 복구·고정 스냅샷·변경 발행을 실행한다.
LVRS 앱·위젯의 실행은 전체 작업의 최종 일괄 검증 단계에 유지한다.
