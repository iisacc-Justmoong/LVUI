# 객체 메서드의 네이티브 조회

일반 C++ 메서드를 표시식에서 호출할 수 있다. 가져온 백엔드, 중첩 객체, 값 별칭,
타입 지정 구성 입력, 괄호·인덱스로 선택한 객체를 수신자로 사용한다. 메서드 이름과
멤버 접근은 생성 C++에 직접 쓰며 런타임 문자열 검색·리플렉션·별도 VM은 사용하지 않는다.

```lvui
import class Domain.Item
import vm Model
let current = vm.selected
let Details(item: Item): View = Label(text: item.format(vm.amount))
Window { VStack {
    Label(text: vm.format(vm.amount))
    Label(text: current.format(vm.amount))
    Label(text: (vm.selected).format(vm.amount))
    Label(text: vm.items[0].format(vm.amount))
    Details(item: vm.selected)
} }
```

## 읽기 수집과 반응성

범위가 소유하거나 명시적으로 차용한 C++ 백엔드도 다른 메서드의 인자로 전달할 수 있다.
`vm.describe(peer)`는 `peer` 인스턴스의 좌측값을 넘기며 임시 복사본을 만들지 않는다.
인자 백엔드의 명시적 publication 의존성도 계산에 포함한다. 실제 C++ 함수의 값/참조
매개변수가 최종 복사·const·접근 계약을 결정한다. 타입 청사진을 인스턴스 값으로 넘기지는 않는다.

`NativeMethods.h`의 `Methods::query`와 `evaluate`는 동기 C++ 호출 범위를 연다.
Core의 `ObservableReadScope`가 메서드 내부 `Observable::get()`의 읽기를 기록하고
기존 `ReadContext`·Bindings가 해당 원본을 구독한다. private 필드를 공개하지 않아도
공개 getter 내부의 읽기는 추적한다. 조건에 따라 읽지 않은 원본은 다음 계산에서
의존 목록에서 제거한다. 별도 폴링·새 작업 스레드·병렬 런타임을 만들지 않는다.

명시적인 LVUI 값 읽기와 같은 Core 원본의 메서드 내부 읽기는 동일한 상태 식별자를
사용한다. 사용자 정의 값 원본의 observe 계약은 기존대로 유지하며, 그 get 내부의
Core 상태 소유권만 계산 중 보존한다. 다른 바인딩의 재진입 계산은 수집을 잠시 가려
독립적인 뷰의 getter·setter 읽기가 바깥 메서드의 의존성으로 섞이지 않도록 한다.

기존 타입 지정 함수 입력·선언의 호출도 실제 C++ 함수 내부 읽기를 수집한다. 호출
인자와 함수 버전의 기존 추적을 유지한다. 수집 자체는 메서드·함수 실행과 다르므로
지연 참조를 만든다는 이유만으로 명령을 실행하지 않는다.

가져온 백엔드의 합성 revision 읽기는 기존 일반 public 값의 publication을 위해
유지한다. 객체 내부의 임의 일반 대입이나 외부 라이브러리 상태를 자동으로 발견하는
계약은 아니다. 그런 상태는 Observable·명시적 revision 입력·새 값 발행으로 제공해야 한다.
조회 어댑터는 파일 revision을 발행하지 않는다. 조회 본문에서 파일 쓰기나 생성 명령을
실행하지 않도록 C++ 모델이 책임지며 명령은 별도 이벤트·작업 경로에 둔다.

## 타입·수명·실패

실제 C++ 선언이 접근성과 const, 오버로드, 인자·반환 타입을 검사한다. `const` 객체를
통해 비const 메서드를 호출하거나 private 조상을 통과하는 접근은 생성 C++에서 거부한다.
결과가 없는 `void` 호출을 Label의 표시값으로 사용하지 않는다.
수신자의 lvalue·rvalue 범주도 유지하므로 `&`·`&&` 메서드 한정자를 C++ 규칙대로
선택한다. 임시 반환값을 무조건 좌측값으로 바꾸지 않는다.

공유 수신자와 읽기 당시 Core 상태·공유 payload를 계산·의존성 검사·결과 적용까지
보존한다. 조회 중 선택 객체가 재진입으로 바뀌면 이전 수신자가 조기에 파괴되지 않으며
불안정한 이전 결과를 적용하지 않고 새 원본으로 재계산한다. 초기 조회가 차용 문자열을
반환하면 임시 읽기 범위를 닫기 전에 소유 문자열로 바꾼다. 일반 참조의 외부 수명과
무효화는 원래 C++ API 계약을 따른다.

초기 조회 실패는 후보 구성 실패로 반환한다. 이후 실패는 마지막 정상 표시와 의존성을
보존하여 다음 정상 publication으로 복구한다. 기존 편집 중인 입력·포커스·위젯을 조회
갱신에서 재생성하지 않는다. raw 포인터와 표준 참조는 기존 외부 소유자를 차용한다.

## 검증과 남은 경계

구성·설치 패키지는 Core의 범위 관측 기능을 C++ 컴파일로 확인한다. 같은 버전 문자열의
예전 Core 패키지가 발견되어도 기능이 없으면 구성 단계에서 거부하며, 타입 오류가 쌓인
뒤에야 알게 되는 경로를 피한다. `tests/native_install.py`는 해당 기능이 없는 Core와
정상 재배치 소비자를 각각 검사한다.

[Core 수집 검사](../../iiSDKCore/tests/observable_reads.cpp),
[컴파일러 검사](../tests/method_queries.cpp),
[네이티브 조회 검사](../tests/native_methods.cpp),
[실제 위젯 검사](../../iiGUI/tests/native_method_queries.cpp),
[C++ 타입 검사](../tests/native_method_validation.py)가 각 경계를 검사한다.
같은 두 구성을 LVRS 팩터리로 컴파일하며 실제 LVRS 실행은 저장소 지침의 최종 일괄
단계에 수행한다. 창 없는 검사와 플랫폼·GPU 실행의 증거는 구분한다.

즉시 조회와 [일반 객체의 지연 메서드 참조](ObjectMethodReferences.md)는 각각 조회와
콜백의 실행 경계를 따른다. 임의 callable 필드의 전체 버전·소유권 프로토콜은 남아 있다. 가변 View,
깊은 Static과 전체 LVRS·플랫폼 계약도 전체 완료 조건으로 유지한다.

숨김 공유모듈에서 범위 상태가 분리되던 문제를 위해 Core의 `Observation` 실행부를
명시적으로 연결한다. LVUI::Native는 이 작은 구현을 사용하며 큰 작업자 Runtime은
계속 선택 사항이다. 앱과 동적 모델 모듈은 같은 Core 관측 실행부를 연결해야 한다.
해당 의존성은 CMake 공개 타깃과 설치 패키지에 보존한다. 헤더 전용 Contracts만으로
관측 구현이 있다고 간주하지 않는다. 이전 실패와 당시 검증 수치는 아래 기록에 보존한다.

## 공유 관측 실행부의 검증

후속 구현은 Core의 독립 `Observation` 실행부로 같은 수집 범위를 사용한다. 기존 공유모듈
회귀의 수집 1건·변경 통지 1건이라는 수용 조건은 그대로 유지한다. 중첩 수집, 예외 복구,
스레드 분리, 공통 깊이 한도, 원본 제거 후 구독 수명도 독립 공유 라이브러리에서 검사한다.

LVUI의 `NativeSharedMethod.lvui`를 iiGUI 위젯과 LVRS 팩터리로 각각 생성한다. iiGUI는
창 없는 실제 위젯에서 표시 갱신·편집 보존·제거를 실행하고, LVRS는 이 단계에서 컴파일만
수행한다. 같은 Core 설치본을 사용하는 일반·ASan·UBSan 구성과 설치 후 재배치 소비자의
결과를 아래에 기록한다. 이 단계 검증도 전체 언어와 플랫폼 완료를 뜻하지 않는다.

|---|---|

현재 검증 자료는 `build/lvui-completion/shared-observation-verification-20261026.json`에
각 로그·소스 해시·생성 헤더·설치 결과와 함께 기록한다. 최초 제한 시간 초과와 위젯 ID
조회·설치 도구 연결 실패의 로그도 보존한다. 이 결과는 macOS arm64의 창 없는 실행이며
다른 플랫폼과 OS 창·GPU·LVRS 실제 실행을 대신하지 않는다. 동적 라이브러리의 언로드
수명도 별도 계약으로 남아 있다.

설치 소비자 검사는 임시 위치에서 여러 CMake 구성과 정상·부적합 C++ 소비자를 새로
빌드한다. 내부 소비자 실행이 통과해도 전체 60초 한도가 초과되던 관측을 보존하고,
이 빌드 검사의 한도는 180초로 조정한다. UI 반응시간의 수용 조건을 바꾸는 조정은 아니다.

AOT 호스트 도구는 네이티브 바인딩을 실행하지 않고 텍스트를 생성한다. 하위 호환 공개
타깃의 전이 연결 때문에 사용하지 않는 관측 DLL이 도구에 남으면 설치 후 재배치 시
라이브러리를 찾지 못할 수 있다. 지원 링커의 미사용 동적 의존성 제거를 도구에 적용한다.
설치 검사는 C++ 소비자뿐 아니라 재배치한 `lvui-check`와 `lvui-compile`도 직접 실행한다.
실제 관측을 실행하는 생성 앱의 Observation 의존성은 유지한다.
