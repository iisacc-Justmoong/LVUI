# 순서가 있는 View 구성 슬롯

`[View]`는 여러 뷰의 구성을 순서대로 전달하는 타입이다. 선언과 슬롯은 AOT에서 C++
구성으로 확장하며, 실행 중 소스 해석이나 중간 레이아웃 위젯을 추가하지 않는다.
아래는 현재 구현의 구성·타입·수명 계약이다.

```lvui
let Pair(title: String): [View] = [
    Label(text: title),
    PushButton(text: "Run")
]
let Panel(content: [View] = []): View = HStack {
    content()
}
Window {
    Panel(content: Pair(title: "Native"))
}
```

## 구성과 수명

목록은 순서가 있는 구성 정의이며 위젯 인스턴스를 공유하지 않는다. 빈 목록·중첩 목록·
목록 별칭을 지원하고, 사용 위치별 ID 영역과 지역 import의 독립 활성화를 유지한다.
값과 콜백은 원래 정의·호출 환경을 따르며 내부에서 같은 이름을 가려도 수신자가 바뀌지 않는다.
입력 변경은 각 자식의 기존 네이티브 바인딩을 갱신한다.

`View` 슬롯은 단일 뷰 구성을 받고 `[View]` 슬롯은 목록 구성을 받는다. 목록의 호출은
자식을 원래 부모에 직접 배치한다. 목록 자체에 루트 속성·자식 블록을 덮어쓰지 않는다.
매개변수가 있는 목록 생성은 선언된 이름·타입·기본값을 따른다.
별칭도 원래 타입을 유지하며 `[View]` 목록을 `View`로 재선언하여 타입을 우회하지 않는다.
`onContent: [View]`처럼 이름이 이벤트와 유사해도 빈 목록을 콜백으로 해석하지 않는다.

TabBar·Menu 등의 자식 타입 검사와 Window·Modal·조건부 분기·반복 행의 루트 수량은
목록을 펼친 실제 구성으로 검사한다. 목록을 경유하여 제약을 우회하지 않는다.
가변 View 교체와 깊은 Static 스냅샷은 기존 [전체 완료 범위](Completion.md)에 남긴다.
렌더링 시 필요한 목록에는 기존 [키 기반 반복](Repetition.md)을 사용한다.

구성 확장은 유한한 깊이·작업량 한도를 유지한다. 뷰를 하나도 만들지 않는 중첩 목록도
무한하거나 지수적으로 커지는 코드 생성을 계속하지 않는다.

## 코드 생성과 검증 경계

목록 선언은 실행 중 변경 가능한 위젯 배열이나 재해석하는 AST가 아니다. 사용 위치별
C++ 구성으로 확장하며, 조건부·반복 항목은 기존 네이티브 활성화 호스트를 유지한다.
구조 검사에서 팩터리를 평가하거나 콜백 저장소를 생성하지 않는다. 실제 확장에서 입력을
검사하므로 자식이 없는 목록에서도 잘못된 매개변수를 건너뛰지 않는다.
구성 깊이 64단계·생성 위젯 4,096개·구성 확장 및 개별 구조 검사 작업량 16,384개 한계를
적용한다.

`tests/view_sequences.cpp`는 구문·별칭·입력 타입·빈 목록·중첩·타입 제한과 진단을
검사한다. `iiGUI/tests/native_view_sequences.cpp`는 실제 생성 C++를 창 없는 위젯에
연결하여 순서·지역 상태·반응형 갱신·조건부 퇴역·실행 중 자기 제거·후보 실패 롤백·
키 기반 행 재사용과 호출 위치의 뷰 팩터리 포획을 실행한다. 파일 리비전도 함께 확인한다.
설치 후 경로를 옮긴 독립 소비자는 공개 AST·컴파일러에서 `[View]` 입력과 기본값을
컴파일·링크·실행한다. LVRS TabBar·Menu·Modal을 포함한 생성 팩터리는 중간 단계에서
컴파일만 하며, LVRS 앱·테스트 실행은 전체 작업의 최종 일괄 검증에 남긴다.

## 2026-10-26 검증 기록

macOS arm64의 현재 변경에서 다음 결과를 확인했다. 서로 겹치는 검사를 합산하여 독립
기능 수나 전체 플랫폼 지원 수로 표시하지 않는다.

| 범위 | 결과 |
|---|---|
| LVUI 전체 Release CTest | 183/183 통과 |
| 관련 언어·네이티브 구현 AddressSanitizer + UndefinedBehaviorSanitizer | 106/106 통과 |
| iiGUI 창 없는 기존 동작·생성 C++ 통합 | 95/95 통과 |
| iiGUI 구현·생성 C++·LVUI Runtime·Core AddressSanitizer + UndefinedBehaviorSanitizer | 95/95 통과, NativeBindings 구현은 별도 LVUI 검사 |
| 설치·재배치 독립 소비자 | Native·공개 파서/컴파일러·선택적 Runtime 3/3 통과 |
| 생성 C++ 함수 타입 회귀 | 유효 3개 컴파일, 잘못된 11개 거부 |
| LVRS 생성 C++ | 목록·이름 가림·TabBar·Menu·Modal을 포함한 총 22개 팩터리 컴파일, 실행하지 않음 |

단일 View로 잘못 재선언한 목록 별칭과 이벤트로 오인된 빈 슬롯을 재현한 후 거부·정상
처리 경로를 추가했다. AOT 도구가 동일한 헤더를 다시 써서 소비 C++를 재컴파일하던
경우도 일반 뷰·스타일 출력에서 재현하여 수정했다. 동일 출력은 수정 시각을 보존하며,
뒤이은 LVRS 팩터리 빌드는 `ninja: no work to do.`였다. 이 검사는 제품의 UI 지연 시간
개선율을 측정한 것이 아니다.

이 단계는 파서·컴파일러·생성 구성 변경이다. 작업·공유 콜백·함수·가변 함수의 이전
ThreadSanitizer 26/26 기록은 변경하지 않은 네이티브 소스·헤더 6개의 해시를 확인하여
재사용했다. 새 목록 코드의 동시성 검사를 별도로 통과했다고 주장하지 않는다. 해당
검사에서 빌린 Core Runtime 라이브러리는 ThreadSanitizer 비계측이다.
