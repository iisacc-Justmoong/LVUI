# 입력 필드와 LVUI 바인딩

## 텍스트 서비스 선택 입력

새 iiGUI의 `text_selection` 입력을 사용하면 포커스된 필드의 UTF-16 선택을
텍스트 서비스에서 변경할 수 있다. 조합 문자열 안팎으로 커서를 옮겨도 기존
조합을 보존하며, 확정과 Undo는 기존 입력 모델이 처리한다. 읽기 전용 필드에서도
선택할 수 있고 서로게이트 중간이나 범위 밖의 위치는 거절한다. 이 입력은 정규화된
범위와 방향을 함께 전달하므로 역방향 선택도 유지한다. 이전 iiGUI에서는 선택 방향
입력을 제공하지 않으며 기존 기능으로 빌드된다.
새 iiGUI는 이 입력을 Android `InputConnection`의 기본 선택·조합·확정에 연결한다.
입력기 동작 전체와 실제 기기 검증은 아직 완료되지 않았다.
`text_composition_region`은 기존 표시 문자를 조합 영역으로 지정하고 선택 방향을
보존한다. 기존 후보가 있으면 새 영역을 준비한 뒤 확정하며, 확정으로 바뀐 텍스트는
기존 편집 알림과 Undo 이력에 반영한다. 길이 제한으로 후보가 잘려 표시 문자가
달라지거나 범위가 잘못되면 요청 전체를 거절한다. 이 입력 경로는 같은 버전의 iiGUI
헤더와 라이브러리를 사용하며 구버전에서는 제외된다.
조합 입력의 커서 숨김과 선택 방향은 조합 표시 상태에 반영하며 후보 밑줄은
유지한다. 숨김만 변경된 경우도 다시 그린다. 이 입력 속성을 사용하는 빌드는 같은
iiGUI 빌드의 헤더와 라이브러리가 필요하며, 구버전 iiGUI에는 해당 입력 속성이 없다.
조합이 없을 때 선택 앞뒤의 코드는 하나의 편집으로 삭제하며 방향성 선택을 보존한다.
입력 필드에서는 Undo와 Redo가 삭제 전후의 텍스트와 선택을 각각 복원한다.
조합 중 주변 삭제는 선택을 보존하고 후보에서 겹친 부분을 줄인다. 후보 밖의
확정 텍스트가 바뀌면 편집 콜백에는 임시 표시 후보가 아니라 확정 원본을 전달한다.
콜백에서 이 확정값을 설정 옵션으로 다시 전달해도 진행 중인 후보는 유지된다.
조합을 확정한 뒤 Undo는 후보 확정과 주변 삭제를 각각 복원한다.
최신 iiGUI에는 필드의 단조 증가 상태 버전을 제공한다. 같은 길이의 후보 교체나
선택 변경도 입력기 요청에서 구별하며, 버전을 지원하지 않는 구버전 iiGUI에서는
기존 경로로 빌드한다.

새 iiGUI의 텍스트 기하 계약에는 필드의 실제 셰이핑·줄바꿈·스크롤과 일치하는
UTF-16 범위 양 끝의 커서 및 보이는 선택 영역을 제공한다. 잘못된 스칼라 경계는
거절하고 화면 밖의 영역은 노출하지 않는다. 기존 iiGUI에서는 이 조회를 생략한다.
헤드리스 필드 검사는 이모지·양방향 텍스트·여러 줄과 수평 스크롤, 커서 위치의
일치를 확인한다. iPhoneOS에서는 관련 소스만 객체 컴파일했으며 입력기를 실행하지 않았다.

## 입력 길이 제한

독립 필드는 이전 LVRS의 `InputField.maximumLength`와 iiGUI 입력 옵션의 길이 제한을
지원한다. 선언형 `maximumLength`는 0부터 2,147,483,647까지의 정수이며
생략 시 32,767 UTF-16 코드 단위이다. C++ 설정은 제한 없음 또는 명시적 제한을
선택하고 UTF-16 코드 단위와 Unicode 스칼라 단위 중 하나를 지정한다. iiGUI의
0은 제한 없음이고 양수는 스칼라 개수이므로 제품 어댑터에서 이 의미를 보존한다.
기존 64 KiB UTF-8 안전 한도는 별도로 적용된다.

초기값, 외부 값과 확정 입력은 제한 안에 들어가는 가장 긴 접두사로 자른다.
선택 범위를 교체할 때 기존 선택은 제한 계산에서 제외한다. UTF-16 제한이
서로게이트 쌍 가운데에서 끝나더라도 유효하지 않은 문자를 만들지 않는다.
IME 조합 중인 임시 문자열은 제한을 넘을 수 있으나 확정할 때 제한을 적용한다.
제한이 변경되면 진행 중인 조합은 취소하고 확정 문자열을 필요한 만큼 줄이며,
이전 제한에서 생성된 실행 취소·재실행 이력을 비운다. 제한 변경이 없는 일반
스타일 갱신은 조합과 이력을 보존한다. 잘못된 선언형 값과 손상된 UTF-8은
거절하고 기존 필드 상태를 유지한다. 제한 때문에 확정 문자열이 바뀌지 않은
입력에서는 편집 콜백을 호출하지 않는다.

## 현재 Figma 텍스트 필드와의 차이

개명된 원본 LVUI의 [TextField 텍스트 기본 상태](https://www.figma.com/design/0GkItQYSNIR0lZ3iJhfJzc/LVUI?node-id=114-176)는
206×22 논리 px, 좌우 7px과 상하 4.5px 여백, 8px 반경, 0.5px 선과 재질 효과를
사용한다. 아래의 현재 `NativeInputField` 기본값은 이 치수와 다르고 단색 배경을
그린다. 원본의 둥근 텍스트와 검색 기본 상태는 채우기·선·효과가 같으며, 검색
합성 필드의 그라디언트·선 그라디언트·효과 스냅샷도 원본 검색 상태와 직접 대조해
일치했다. 일반 입력은 아래의 둥근형·원통형·인라인형 재질과 지우기 동작을
선택할 수 있다. 이는 모든 상태의 실제 GPU 화면과 운영체제 입력이 검증되었다는
뜻은 아니다. Congregation은 개별 높이 스타일 대신 아래의 공통 크기 프리셋을
사용한다.

공통 크기 프리셋 `InputFieldSize::compact`는 원본 TextField의 22px 높이,
좌우 7px·상하 4.5px 여백, 8px 반경과 13px 글꼴·줄 높이를 사용한다. 기본
`regular`는 기존 206×30 동작을 유지한다. `.lvui`의 `size: .compact`와 반응형
크기 입력도 같은 프리셋을 선택한다. 명시적인 유효 치수는 프리셋 적용 후
우선한다. 크기를 바꾸어도 텍스트·선택·조합과 실행 취소 이력을 유지하며,
잘못된 크기 갱신은 기존 상태를 보존하고 진단한다. 이 프리셋은 재질이나 지우기
버튼을 자동으로 선택하지 않는다.

## 일반 입력의 지우기 동작 명세

원본 LVUI의 둥근 TextField에서 값이 있는 텍스트·암호 입력 상태는 오른쪽에
12px 지우기 버튼을 표시한다. 206px 입력에서는 오른쪽 여백이 7px이다. 빈 값,
비활성, 읽기 전용, 여러 줄 또는 버튼을 표시할 공간이 없는 상태에서는 이 동작을
표시하지 않는다. 버튼을 누르면 입력 전체를 사용자 편집으로 지우고 입력 포커스를
유지한다. 일반 텍스트의 지우기는 한 번의 Undo로 되돌릴 수 있고 입력기 조합을
지우면 조합 이전의 확정 값으로 되돌린다. 암호 입력은 기존 보안 이력 정책을 따른다.

독립 C++ 필드의 `clear_button_visible`과 선언형 `clearButtonVisible`로 선택하며
기본값은 `false`이다. 이는 기존 숫자·색상 등 다른 합성 위젯의 입력 영역을
임의로 바꾸지 않기 위한 호환 기본값이다. 사용자는 동작의 접근성 이름을
`clear_accessibility_name` 또는 `clearAccessibilityName`으로 지정할 수 있다.
표시 여부를 바꾸거나 상위 위젯을 비활성화해도 텍스트·선택·조합과 이력은
보존한다. 표시 공간은 항상 오른쪽에 예약하므로 첫 글자 입력이나 지우기로
입력 영역이 갑자기 이동하지 않는다. 원본의 화면은 Figma에서 확인했으나 실제
운영체제 창과 GPU 픽셀 동등성은 별도 검사 대상이다.

## 원본 TextField 표면과 공통 재질

저수준 C++ 입력과 기존 선언형 소비자는 숫자·색상 등 합성 위젯과 호환되도록
기존 단색 표면을 기본으로 유지한다. 원본 재질은 `InputFieldSurface::rounded`,
`cylinder`, `inline_` 또는 선언형 `surface: .rounded`, `.cylinder`, `.inline`으로
선택한다. 반응형 값은 각각 1·2·3이며 0은 기존 단색 표면이다. 잘못된 값은
거절하고 텍스트·선택·입력기 조합·이력을 보존한다.

둥근형과 원통형은 활성 시 `Panel/surfaceSolid`에 원본 컴포넌트의 0.64 불투명도를
적용하고 8px 배경 흐림·그라데이션·안쪽 그림자·0.5px 선을 사용한다. 둥근형의
반경은 공통 토큰이고, 원통형의 99px 반경은 입력의 실제 크기에 맞추어 제한한다.
인라인형은 반경과 일반 선 없이 별도 채우기·안쪽 그림자와 6px 흐림을 사용한다.
세 모양의 비활성 상태는 원본의 별도 채우기를 쓰고 흐림·그림자·일반 선을 제거한다.
상위 위젯이 비활성화된 경우도 같으며 다시 활성화하면 기존 상태와 재질을 복원한다.

일반 입력과 검색 입력은 원본 여섯 상태에서 같은 표면 재질을 공유한다. 배경을
먼저 그린 뒤 문자·선택·커서와 지우기 동작을 그린다. 일반 문자·플레이스홀더,
비활성 문자, 선택, 커서는 각각 공통 역할의 0.9·0.3·1.0·0.6 불투명도를 사용한다.
단색 표면은 기존 팔레트를 유지한다. 현재 포커스 테두리는 입력 방식과 관계없이
표시하므로 Figma의 키보드 포커스와 포인터 포커스는 구별하지 않는다. Apple 외
플랫폼의 지우기 심볼은 원본 SF Pro 심볼 대신 이식 가능한 대체 도형을 사용한다.

2026-11-03 후속 변경에서 입력·검색·버튼의 헤드리스 검사 13건과 패키지 경계
검사가 통과했다. 둥근형과 인라인형의 비활성 Figma 투명 PNG에서 각각 11개
위치의 RGBA를 오차 6 이내로 비교했다. 활성 표면은 현재 원본의 변수 연결과
재질 데이터를 검사한다. 이 표본은 실제 창·GPU·기기나 전체 화면의 픽셀 비교가
아니다. 이후의 제품 빌드 결과는 Congregation의 검증 문서를 따른다.

이 변경 전 macOS arm64의 기존 빌드에서 Qt·LVRS 주요 실제 경로를 차단한 상태로
LVUI 전체 대상이 빌드되었다. 입력·검색·텍스트와 이를 내장하는 목록·표·색상
컨트롤 관련 헤드리스 검사 108건 및 설치 패키지 경계 검사 1건이 통과했다.
별도 빌드 디렉터리를 생성하는 `LVUI.NativeInstalled`는 제외했으며, 기존 SDK
스테이징과 빌드 캐시를 재사용했다. 실제 창·GPU·기기와 Windows·Linux 실행
검증은 포함하지 않는다.

`InputFieldConfiguration`은 LVUI의 입력 필드 치수, 글꼴, 색상, 접근성 이름과
읽기 전용·여러 줄·비밀번호 속성을 정의한다. 기본 치수는 206×30 논리 px,
가로 안쪽 여백은 8, 글꼴 크기는 13이다. 설정과 텍스트의 유효성을 확인한 뒤에만
후보 상태를 게시한다. 텍스트·선택·조합의 상세 계약은 [텍스트 입력 상태](TextInput.md)에
설명한다.

iiGUI의 `BasicNativeInputField`는 텍스트 모델을 위젯 표면과 텍스트 서비스에
연결한다. iiGUI가 포인터 선택, 글자·단어 이동, 삭제, IME 조합, 제출, 선택
표시, 커서와 텍스트 그리기를 담당한다. LVUI는 `InputFieldHostPolicy`와
`InputFieldBinding`으로 디자인 값과 교체 가능한 계약을 제공하며 생성된 앱이
iiGUI 모델·재질·호스트를 조합한다. 단어와 자소 경계, 글자 배치는 교체 가능한
호스트 기능을 사용하며 Qt, QML, LVRS 위젯은 사용하지 않는다. Unicode 경계
어댑터 자체는 구체적인 그래픽 SDK에 의존하지 않고 앱이 인덱스 타입을 전달한다. 복사 출력을 별도
클립보드 포트로 주입할 수 있고 기본값은 호스트의 범용 클립보드이다. 비밀번호
필드는 복사와 잘라내기를 거절하고 암호 대신 마스킹된 글자를 그린다. 암호 원문은
소유자의 명시적 필드 snapshot과 편집 콜백에는 전달되므로 앱이 수명을 관리한다.

조합 텍스트는 표시와 OS 조회에 포함되지만 `edited` 콜백은 확정된 변경에서만
호출한다. 포커스를 잃으면 진행 중인 조합을 확정한다. 커서 오프셋이 없는 종전의
빈 조합 입력은 취소이며, 텍스트 서비스가 커서 오프셋을 함께 준 빈 조합은 빈
후보로 교체한 뒤 확정할 수 있다.
복합 컨트롤은 `displayed_changed`로 조합 중인 텍스트와 외부 값 변경을 포함한 실제
표시 문자열의 변경을 관찰할 수 있다. 표시 값이 같으면 호출하지 않으며 문서 편집으로
간주하지 않는다. 이 콜백이 다시 값을 바꾸면 이전 입력에 대한 오래된 `edited`는
전달하지 않는다. 조합 확정 여부는 기존 `edited` 계약을 따른다.
`set_accessibility_name()`은 접근성 이름만 변경한다. 유효하지 않은 UTF-8이나
크기 제한을 넘는 이름은 거절하며, 입력 중인 조합·선택·실행 취소 이력과 편집 콜백을
건드리지 않는다. `options()`에도 새 이름이 반영된다.
네이티브 C++ 콜백의 `focus_changed(bool)`는 화면 갱신을 기다리지 않고 포커스 변경을
전달한다. 포커스를 잃을 때 진행 중인 조합의 `edited`가 먼저 전달되므로 합성
컨트롤은 이 콜백에서 숫자와 같은 보류 입력을 확정할 수 있다. 조합 확정 중 필드가
폐기되면 폐기된 필드의 포커스 콜백은 전달하지 않는다.
텍스트 범위는 UTF-16 단위이며 다른 설정만 반응형으로 갱신될 때 외부 텍스트 값이
변하지 않았다면 사용자가 편집한 내용을 보존한다. 재진입한 새 갱신을 이전 갱신이
덮어쓰지 않도록 버전을 확인한다. 소유 스레드 이외의 접근과 폐기된 위젯 갱신은
거절한다.

`options()`가 돌려주는 표시 문자열을 그대로 둔 채 다른 옵션만 바꾸어 `set_options()`에
전달해도 진행 중인 조합을 확정하지 않는다. 나중의 확정 편집과 스타일 갱신 역시
이전 조합 문자열을 다시 덮어쓰지 않는다. 명시적인 `set_text()`는 별도의 외부 값
교체이므로 조합을 보존하는 옵션 갱신과 다르다.

C++ 호스트는 `set_palette()`로 텍스트를 다시 전달하지 않고 색상만 변경할 수 있다.
유효하지 않은 팔레트는 거절하고 기존 설정을 유지한다. 색상 변경은 입력 중인 조합,
선택, 초안과 이력을 보존한다.

검색 지우기처럼 사용자가 시작한 전체 삭제는 `clear_as_user()`를 사용한다. 이는
외부 상태를 교체하는 `set_text()`와 달리 삭제를 하나의 편집으로 기록하고 변경된
경우에만 `edited`를 한 번 전달한다. 조합 중이라면 조합 전 확정 텍스트를 실행 취소로
되돌린다. 비활성·읽기 전용 필드는 변경하지 않으며 암호 필드는 일반 입력과 같이
이력을 저장하지 않는다. 소유 스레드가 아니거나 폐기된 필드에 대한 호출은 거절한다.

별도 설계 파일의 [SearchField 상태 초안](https://www.figma.com/design/8nSrpI0BbsZlXQiotbClHD/LVUI?node-id=37-952)은
여섯 가지 상태와 로컬 아이콘·토큰을 보유한다. 이 컴포넌트는 해당 파일에서 게시된
상태이며, Congregation 화면이 사용하는 [공통 LVUI 라이브러리](LVUIIndependence.md)와는 다른 파일이다.
네이티브 합성 컴포넌트 및 선언형 요소의 구현과 한계는 [검색 입력](NativeSearchField.md)에
기록한다. 검색 컴포넌트는 배경 블러와 그라디언트를 사용하고 내부 그림자를
근사한다. 실제 GPU 화면에서의 원본 동등성과 플랫폼별 검증은 아직 완료되지 않았다.

2026-11-03 Qt·LVRS 패키지 탐색을 비활성화한 macOS arm64 빌드에서 전체
SDK 대상이 빌드되었다. 628개 회귀 검사 중 이전 토큰 수를 고정한 예제 소비자
한 건이 처음 실패했고, 기준과 새 검색 토큰 검사를 갱신한 뒤 해당 검사가 통과했다.
나머지 627건은 최초 실행에서 통과했다. 별도의 설치·재배치 소비자 검사도 통과했고
기존 설치 manifest의 SHA-256은 변경되지 않았다. 헤드리스 소비자 실행과 실제
운영체제 창·기기 실행은 구분하며, 후자는 이번에 수행하지 않았다.

단일 줄은 가로로 스크롤한다. 여러 줄 필드는 기본적으로 사용 가능한 너비에 맞춰
자동 줄바꿈하고 필요할 때 세로로 스크롤한다. 선언형 `wrapEnabled: false` 또는
C++ 설정의 `wrap_enabled = false`로 자동 줄바꿈을 끄면 명시적인 줄바꿈만 사용하고
가로·세로로 스크롤한다. 이 속성은 단일 줄 필드에는 영향을 주지 않는다. 줄바꿈은
호스트의 문단 배치로 계산하므로 방향이 다른 문자가 섞인 문단도 원래 문맥을 보존한다.
입력 필드 너비가 바뀌면 원문과 이력을 유지하며 다시 배치한다. 같은 텍스트 위치가
화면의 이전 줄 끝과 다음 줄 시작을 가리킬 수 있으므로 포인터와 방향키는 두 커서
위치를 구분한다. 비밀번호는 이모지와 결합 문자를 포함해 확장 자소마다 한 글자로
표시하되 원본과 OS의 선택 범위는 UTF-16 단위를 유지한다.

자동 배치는 최대 4,096개의 화면 줄을 허용한다. 이 한도를 넘거나 표시 너비가
0이면 원문을 지우지 않고 명시적 줄바꿈 방식으로 전환하며, C++ snapshot의
`wrapping_fallback`으로 이를 확인할 수 있다. 너비가 다시 커져 한도에 들어오면
자동 줄바꿈으로 복구한다. 명시적 줄바꿈만으로 문단이 4,096개를 넘는 입력은
별도의 문단 수 제한으로 거절한다. 자동 배치의 최대 너비는 8,192 논리 px이다.
실행 취소·재실행은 입력 필드의 로컬 이력을 사용한다. 명시적인 undo/redo 입력과
Command/Ctrl+Z, Command/Ctrl+Shift+Z, Ctrl+Y를 처리하며 읽기 전용 필드는
변경하지 않는다. 암호 필드는 이력 기록을 사용하지 않고 암호 모드로 전환할 때
기존 이력을 비운다. 플랫폼별 실제 단축키 전달은 별도 실행 검증이 필요하다.

시간 정보가 있는 두 번의 가까운 포인터 클릭은 단어를 선택하고, 두 번째 클릭에서
드래그하면 단어 경계로 선택을 확장한다. 선택은 텍스트 편집이나 실행 취소 이력을
발생시키지 않는다. 자소와 단어 범위는 주입된 Unicode 서비스가 제공하며 잘못된 범위는
거절한다. 기본적으로 iiGUI가 클릭 횟수를 전달하면 운영체제의 단일·더블 클릭
판정을 따른다. 동일 입력 필드와 기기의 직전 클릭이 있어야 하며, 세 번 클릭은
더블 클릭으로 처리하지 않는다. macOS·Windows 어댑터와 iPadOS 터치 어댑터는
네이티브 판정을 전달한다. 호스트가 횟수를 제공하지 않으면 기본 간격 0.5초와 거리 4 논리 px를
사용하며 C++의 `double_click_interval`과 `double_click_distance`로 조정할 수 있다.
`use_native_click_count=false`이면 네이티브 판정 대신 이 값을 사용하고, 간격 0은
어느 경로에서든 기능을 끈다. 클릭 중 드래그를 구분하는 데에도 거리 값을 사용한다.
비밀번호 필드는 더블 클릭으로 전체 값을 선택해 내부 단어 경계가 선택 상태로
드러나지 않게 한다. Linux 등 네이티브 횟수가 없는 입력의 운영체제 설정은
아직 자동 적용되지 않으며, 실제 포인터·터치 전달은 각 플랫폼에서 별도 검증이 필요하다.
iiGUI Android의 편집용 글자 배치와 하드웨어 키보드 입력은 연결되었다. Android
입력기는 기본 조합·주변 삭제를 제공하나 일부 확장 요청이 미구현이며 실제 기기
입력과 화면은 검증하지 않았다. 웹의 편집용 글자
배치는 미구현이다. macOS·iOS·Windows·Linux의 실제 창, 입력기, 접근성 기기 및
클립보드 실행 검증도 별개로 남아 있다. 기본 선언형 `InputField`는 이 어댑터를
생성하고 텍스트, 치수, 활성·읽기 전용·비밀번호 상태, 색상과 콜백을 연결한다.
반응형 옵션은 유효한 후보만 적용한다. LVRS 또는 Qt 위젯 생성 경로는 사용하지 않는다.
`fontFamily`를 생략하면 생성 시점의 창 글꼴을 사용한다. 이후 창 글꼴 변경에
자동으로 연동되지는 않으며 필요한 경우 반응형 `fontFamily`를 공급한다.

UIKit 텍스트 서비스는 이 필드의 UTF-16 문서·선택·조합과 커서 기하를 사용한다.

확인한다. iPhoneOS 생성 앱 링크는 입력기의 실제 기기 동작을 뜻하지 않는다.
플랫폼 범위 제한과 미지원 항목은 iiGUI의 iPadOS 입력 계약을 따른다.

강제하지 않는다.
