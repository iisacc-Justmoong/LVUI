# C++ 메서드가 반환한 콜백

선택된 객체·임시 수신자와 인자에서 반환 함수를 얻는 경우의 보존 규칙은
[반환 함수의 포획 수명](FactoryCaptures.md)을 따른다. 반환 함수 객체와 그 함수가
차용하는 원본 객체의 소유권을 각각 확인한다.

`PushButton(vm.makeHandler())`는 메서드 참조와 다른 표현식이다. `makeHandler()`를 C++
입력 바인딩을 처음 연결할 때 호출하고, 반환한 호출 가능 객체를 버튼 이벤트에 사용한다.
메서드 호출을 클릭 시점까지 연기하지 않는다. 반면 `PushButton(vm.increment)`는 기존
수신자에 대한 지연 메서드 참조이며, 생성 중 `increment()`를 실행하지 않는다.

```lvui
import vm DocumentModel
Window {
    VStack {
        PushButton(vm.makeHandler(vm.amount))
        InputField(onEdited: vm.makeTextHandler())
    }
}
```

일반 입력의 반응형 규칙을 따른다. 팩토리 호출의 인자와 C++ 원본을 네이티브 `ReadContext`로
읽고, 그 의존 원본이 바뀌면 새 함수를 만든다. 같은 위젯의 이벤트 연결은 유지한다. 표시·
프레임 갱신 자체로 매번 팩토리를 실행하지 않는다. 일반 C++ 멤버·메서드에는 기존 합성
백엔드 리비전 계약을 적용하므로 해당 리비전의 변경도 팩토리를 다시 평가할 수 있다.
팩토리는 재평가될 수 있는 읽기 경로에 속하며 제품의 생성·파일 쓰기 명령을 그 안에서
암묵적으로 발동하지 않도록 C++ 모델이 책임진다.

## 타입과 전달

반환 객체는 C++ 컴파일 시 실제 이벤트 인자로 호출할 수 있어야 한다. `void` 반환과
숫자 등 호출할 수 없는 결과는 생성 C++의 컴파일 오류이다. LVUI 문자열 검사만으로
알 수 없는 C++ 반환 타입을 임의로 추정하지 않는다. 오버로드·const 접근성·인자 변환은
해당 C++ 선언과 컴포넌트 이벤트 타입의 검사를 따른다.

iiGUI 버튼은 인자가 없는 호출, 입력 편집은 문자열 인자 등 각 이벤트 계약을 따른다.
LVRS 버튼의 반환 함수는 `const lvrs::ButtonEvent&`를 받을 수 있으면 그 인자를 사용하고,
그렇지 않으면 인자 없는 호출을 검사한다. 재사용 View의 입력 덮어쓰기와 중첩 스코프에
전달해도 팩토리가 참조한 원래 수신자와 인자를 보존한다.

반환 함수는 복사 가능할 필요가 없다. `unique_ptr`를 포획한 이동 전용 C++ 함수 객체도
지원한다. 명시적인 함수 타입 매개변수·읽기 전용 선언·반환값은 후속
[함수 값](FunctionValues.md)을 따른다. 가변 함수 교체·부분 적용·중첩 함수 타입 등
나머지 일반 계약은 별도의 완료 대상이다.

이동·복사 불가능한 값 반환도 C++ 복사 생략으로 소유할 수 있다. 좌측값 참조는 복사하지
않고 수신 스코프에 연결하여 차용하며 `const`를 보존한다. 함수 참조도 차용할 수 있다.
참조 대상의 유효성은 원래 C++ API의 계약을 따른다. 타입 지정 매개변수를 통한 다중
소비자와 공유 수명은 [단일 콜백 값](CallbackValues.md)을 사용한다.

## 오류와 수명

- 초기 팩토리 평가가 실패하면 해당 위젯 활성화도 실패한다.
- 이후 재평가가 실패하면 기존 유효한 함수를 유지하고 네이티브 바인딩 오류에 기록한다.
  의존 값이 복구되면 새 함수를 게시한다.
- 바인딩 그래프가 현재 함수를 소유하며, 저장된 이벤트는 함수 슬롯을 약하게 참조한다.
  뷰 퇴역 후 외부 이벤트 복사본이 백엔드나 반환 함수의 자원을 보관하지 않는다.
- 실행 중인 이벤트는 수신자와 현재 함수를 잠시 보유한다. 호출 중 함수가 교체되거나
  자신의 조건부 패널·창을 닫아도 반환 전에 객체가 파괴되지 않는다.
- 닫힌 스코프와 다른 UI 실행 영역에서 시작한 새 이벤트는 접수하지 않는다. UI 종료 후
  계속할 비동기 작업의 소유권은 별도 [수명 계약](InvocationLifecycle.md)을 따른다.

공개 C++ 도우미 `lvui::native::returned_callback`은 팩토리·호출 어댑터를 네이티브 바인딩과
접수 경계에 연결한다. 실행 중 LVUI 파싱·소스 식 해석·VM을 사용하지 않는다.
값이나 오류를 반환해야 하는 입력 경로는 `returned_function<Result>`를 사용한다.
이 도우미도 현재 유효한 팩터리 결과와 활성 범위·소유 스레드를 확인하며, 실패한
팩터리 갱신은 이전 유효 호출 대상을 유지한다. [이벤트 리스너](NativeEventListener.md)의
입력 결과가 이 경계를 사용한다.

## 검증

`LVUI.NativeCallbacks.*`는 최초 평가·의존 갱신·실패 롤백·이동 전용 함수·외부 콜백 복사·
접수 영역·실행 중 종료를 검사한다. `iiGUI.native_returned_callbacks.*`는 실제 생성 C++를
버튼·문자열 입력·재사용 View·중첩·조건부 교체·종료에 연결한다. 설치·경로 이동 소비자는
독립 프로젝트에서 이 헤더를 사용하고 `void`·숫자 반환이 C++ 컴파일에서 거부되는지
확인한다. 실제 LVRS 버튼 연결은 오브젝트 컴파일과 최종 실행 검증을 구분한다.
